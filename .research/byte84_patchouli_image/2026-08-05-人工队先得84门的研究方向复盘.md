# 人工队先得到 84/6 的研究方向复盘

日期：2026-08-05

## 结论

人工队先得到 `84 / 6 / 504`，不是因为其穷举规模更大，而是因为其选择了更正确的
架构边界。我们此前把大量算力用于固定 `85/6` DAG、固定 carry ABI、固定输出 owner
之后的局部搜索；这些搜索得到的负结果在各自边界内成立，却无法覆盖 Patchouli 真正使用
的五门 `S5` 改写。

Patchouli 的关键不是删除某个现有元件，而是放弃原有六门双 Switch owner，跨越原 cone
边界重新选择五个普通门：

```text
U45 = OR(B23,K34)                       @4
H5  = NOR(Q4,P5)                        @3
T5  = AND(U45,H5)                       @5
J5  = NOR(Q5,C6)                        @5
S5  = OR(T5,J5)                         @6
```

在可达的 `Q/P/G` 联合状态上：

```text
U45 = C4 OR G4
H5  = V4 AND NOT P5
T5  = C5 AND NOT P5
J5  = P5 AND NOT C5
S5  = C5 XOR P5
```

这是一项“先改变状态接口，再闭合输出”的架构改写，不是“在旧 owner 里少放一个门”的
局部优化。

## 为什么原研究没有先发现

### 1. 把条件下界误当成研究方向

此前大量 SAT、MaxSAT 和真值枚举都固定了 paid-source 池、到达时间、carry 相位或 BUS
owner 数。它们能够证明“在这个接口下不存在”，但我们随后仍继续扩大同一接口内的搜索，
没有及时把负结果解释为“应更换接口”。计算量增长了，架构覆盖率没有增长。

### 2. 固定了错误的 cone 所有权

旧 `S5` 被视为私有输出 cone，搜索重点是从其既有中间量中删除一门。Patchouli 却从
`B23/K34/Q4/P5/C6` 这些跨位、跨 carry、跨相位的现成 reason 重新取输入。只要边界仍
固定在旧 `D5/E5/Switch` owner 内，正确答案就不在搜索空间中。

### 3. 过度偏向 Switch，忽略普通门重关联

Switch 的 `Z` 能力非常重要，但每只 Switch 的真实成本是 `2 gate / 1 delay`。旧结构
因 BUS owner 直观而保留了两只 Switch；Patchouli 识别出这里无需保留三态所有权，五只
普通门就能在相同六延迟内输出完整 `0/1`。研究曾把“继续利用高阻态”当成默认方向，
没有同时维护“把 Switch 整体还原为相位逻辑”的对偶路线。

### 4. 没有优先利用可达状态不变量

`Q/P/G` 不是相互独立的任意布尔输入。Patchouli 的等式依赖其互斥、完备和 carry 语义。
如果宏搜索把这些 rails 当作自由变量，正确的局部恒等式会表现为不等价；如果只计算完整
真值向量却不提取人类可读的状态关系，也很难主动构造出 `U45/H5`。

### 5. 优化单位过细

此前代理常按单个 sum、单个 carry 或固定高尾 residual 分工，容易重复证明局部不可行。
人工图按共享 reason 和输出 owner 组织；其有效优化单位至少是 `S4/S5/C6` 或
`S5/S6/S7/C8`，而不是一个现成节点的扇入。

### 6. 物理工作曾抢占逻辑前沿时间

布局、导线和生成器质量是必要工程，但在 `85 -> 84` 的阶段继续改进布局不会改变排行榜
成绩。现在已经按用户要求停止布局研究，物化只作为完整候选通过逻辑证明后的最后一步。

## 纠偏后的研究规则

1. 每条路线先写明它允许改变哪些状态接口、输出 owner 和相位；只固定延迟与总成本，不
   默认固定旧 DAG。
2. 每个负结果必须带作用域。若同一 ABI 连续出现两个硬负证，停止扩大该空间，转而改变
   ABI，不再累计无目标样本。
3. 优先枚举架构宏而非门序列：carry/reason 暴露、正负相位选择、跨输出共享、Switch 与
   普通门互换、多个输出的联合 owner。
4. 结构发现阶段完全禁用 SAT、MaxSAT、SMT、ILP、函数池组合和门序列枚举。即使窗口很小，
   “提出门数边界后让求解器判 UNSAT”仍不是算法研究，也不得作为进展汇报。
5. 公式已经由布尔代数手工闭合后，只允许使用确定性真值重算检查人为推导错误；验证脚本
   不得反向承担发现网络的职责。
6. 所有候选必须一次给出完整 DAG、精确成本、逐节点到达时间、`131072` 组九输出真值、
   BUS 冲突证明和可物化网络；局部命中不再称为新前沿。
7. 代理按互斥架构窗口分工，不再重复搜索同一固定 source pool，并禁止代理再创建代理。

本次纠偏时已实际终止两个遗留匿名 Python 枚举进程，其中最大进程占用约 `6.2 GB`。远端
工作站没有继续运行本项目的求解负载。后续算力应服务于完整公式的真值重算、物化和审计，
不再用算力替代布尔代数与电路架构判断。

## 立即执行的前沿窗口

当前权威前沿为 `84 / 6 / 504`。严格改进只接受：

```text
83 / 6 / 498 或更低
100 / 5 / 500 或更低
```

并行路线改为：

```text
低位联合窗口       bits0..3 的 42 -> 41，允许重写 S3/S4/C4/C5
中位 owner 窗口    bits4:5 + C6 的 22 -> 21，联合 S4/S5/C6
跨 C6 高尾窗口     允许上游直接公开 nC6@3、Z7@4 或等价早到 reason
高输出 ABI          联合重写 S5/S6/S7/C8，不固定现有 C6@4 后缀
五延迟全局窗口      总门数 <=100，从输出相位和 state code 重新分配 30 门高位预算
```

其中 `S5` 私有 cone 已完成有界负证：单 Switch 加至多两只普通门不能把当前五门继续缩到
四门。因此下一门不能再靠私有 `S5` 小修，必须来自跨输出共享或上游状态重编码。
