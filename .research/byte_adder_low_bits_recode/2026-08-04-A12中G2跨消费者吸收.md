# 字节加法器：`A12` 中 `G2` 的跨消费者吸收

## 2026-08-04：低位手工重编码闭合 `92/6/552`

### 结论

在已部署 `93/6/558` 的真实 Factory DAG 中：

```text
A12 = OR(G1,G2)                                      1 gate @2
B12 = BUS(SW(C1,N12), SW(A12,N12))                  4 gate @3
```

`A12` 只有 `B12` 一个 fanout，而 `B12` 的四个消费者分别已经支付能吸收 `G2` 的旁路。故可改为：

```text
B12' = BUS(SW(C1,N12), SW(G1,N12))                  4 gate @3
```

并让 `A12` 的私有 OR 从 live cone 中死亡。

完整理论账本：

```text

delay    6 ->  6
energy 558 -> 552
```

这是一个保持 `B12@3` 的真实一门删除，不是此前已被否决的“先物化 `C3@4` 再拿它驱动 C5/C7”方案。

### 一、精确节点与 fanout

基线节点：

```text
G1    #21  AND(A1,B1)                         cost1 @1
G2    #24  AND(A2,B2)                         cost1 @1
C1    #44  BUS[(Cin,V0),(G0,V0)]              cost4 @2
A12   #47  OR(G1,G2)                          cost1 @2
N12   #48  NOR(Q1,Q2)                         cost1 @2
B12   #56  BUS[(C1,N12),(A12,N12)]            cost4 @3
```

精确唯一消费者：

```text
A12 -> B12

B12 -> C3#57
B12 -> C5#58 的 Switch enable
B12 -> C7#59 的 Switch enable
B12 -> S4.low_prefix#63
```

无第五个隐藏消费者；因此只需逐一证明这四处吸收。

### 二、完整 BUS owner

旧 owner：

```text
bus_56:
  Switch(enable=C1,  data=N12)
  Switch(enable=A12, data=N12)
  cost=4
  arrival=3
  complete_owner=true
```

新 owner：

```text
bus_B12_absorbed:
  Switch(enable=C1, data=N12)
  Switch(enable=G1, data=N12)
  cost=4
  arrival=max(C1@2,G1@1,N12@2)+1=3
  complete_owner=true
```

两只 Switch 始终传相同的 `N12`。重叠开启时只会传同值，不会出现 0/1 conflict。没有拆出或跨 owner 复用任何 partial Switch 输出。

### 三、value、driven、Z 必须分开记账

记：

```text
N  = N12
Eo = C1 | G1 | G2
En = C1 | G1
```

旧、新 `B12` 的数据面 value 为：

```text
Bo = N & Eo
Bn = N & En
Bo = Bn | (N & G2)
```

但 owner 的 driven 条件为 enable 并集，而不是 value：

```text
old driven = Eo
new driven = En
```

所以 **B12 owner 自身的 driven/Z 分类会变化**。当：

```text
G2=1, C1=0, G1=0
```

时，旧 owner 由 A12 driver 驱动 `N12`，新 owner 为 Z。不能错误声称 B12 自身逐行完全相同。

合法性的关键是：

- 普通门读取 BUS 的数据面，active 0 与 Z 都是逻辑 0；
- 作为 Switch enable 时，只有 active 1 才开启；active 0 与 Z 都关闭；
- 所有旧 `B12=1`、新 `B12=0` 的差异行都含 `G2=1`，且每个消费者已有同值吸收支路。

### 四、四个消费者的完整吸收证明

#### 1. `C3`

```text
old C3 = G2 | Bo
new C3 = G2 | Bn
```

代入 `Bo=Bn|(N&G2)`：

```text
G2 | Bo
= G2 | Bn | (N & G2)
= G2 | Bn
```

`C3` 是普通 OR，输出 fully driven；`B12` 的 active0/Z 差异不会传播。

#### 2. `C5` 完整 owner

当前：

```text
Apre = G4 | X23
X23  = G2 | G3
```

所以：

```text
G2 => Apre
```

`C5` owner：

```text
Switch(enable=Apre, data=V34)
Switch(enable=B12,  data=V34)
```

旧、新 B12 driver 的 active-1 差集只有 `N&G2`，已被 `Apre` driver 覆盖：

```text
Apre | Bo = Apre | Bn
```

因此：

- 两只 C5 Switch 的 active enable 并集完全相同；
- C5 的 driven 集和 Z 集完全相同；
- 两只 driver 的 data 都是 `V34`，重叠时同值，无新增 conflict；
- C5 value 完全相同；
- arrival 仍为 `max(Apre@3,B12'@3,V34@3)+1=4`。

#### 3. `C7` 完整 owner

`C7` owner：

```text
Switch(enable=A56,  data=V56)
Switch(enable=Apre, data=B55)
Switch(enable=B12,  data=B55)
```

后两只 driver 的 enable 并集仍满足：

```text
Apre | Bo = Apre | Bn
```

故：

- `B55` driver 组的 active/driven 集不变；
- 与 `A56/V56` driver 的交叠集合也完全不变；
- 原机器证书已经通过的跨 data conflict 分类保持不变；
- C7 value、driven、Z、conflict 逐行不变；
- arrival 仍为 4。

#### 4. S4 低前缀

```text
X23 = G2 | G3
old L = X23 | Bo
new L = X23 | Bn
```

因为 `G2 <= X23`：

```text
X23 | Bo
= X23 | Bn | (N&G2)
= X23 | Bn
```

`L` 的 arrival 仍为 `max(X23@2,B12'@3)+1=4`，后续 S4 仍在 arrival 6 收尾。

### 七、构建器集成

最小改法不是重写 carry witness，而是在构造其 source tuple 时，将 ABI 名 `A12` 的实际 Factory 节点替为 `G1`：

```python
from a12_g2_absorption_patch import absorbed_carry_sources

carry_sources = absorbed_carry_sources(
    factory,
    nets,
    REASSOCIATED_CARRY_SOURCES,
)
```

原 witness 的 source 1 随即从 `A12` 变为 `G1`，其 slot 3 自动变成：

```text
Switch(enable=G1, data=N12)
```

原 `A12=OR(G1,G2)` 即使仍在构建期暂时创建，也因没有 live consumer 而不会计入最终 reachable DAG。更干净的后续整理可直接不创建该节点，但不应把代码整理与首次验证混在一起。
