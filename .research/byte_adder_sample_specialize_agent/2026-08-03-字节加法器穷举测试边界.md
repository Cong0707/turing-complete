# 字节加法器穷举测试边界

## 结论

当前安装版 `2.1.281` 的 Byte Adder 不是有限随机抽样，而是把完整的
`U8 A x U8 B x U1 Carry in` 真值域恰好检查一遍：

```text
checked ticks            0..0x1ffff（含两端）
checked vectors          131072
distinct input triples   131072
missing input triples    0
duplicate input triples  0
```

因此不能通过“只对测试样本正确、对未测输入错误”来压缩 Byte Adder。任何纯组合候选
通过当前测试，等价于对全部 17 位输入正确。

固定测试顺序仍留下一个更窄的理论边界：状态元件可以尝试按照复位后的拍序重放答案，
而不直接实现加法。但它仍须连续正确重放全部 `131072` 步；目前没有证明这种状态机能
在公开能耗第一名 `103 gate / 5 delay / 515 energy` 之下。这个可能性不能被错误写成
“数学上不可能”，也不能被当作已经找到的优化路线。

对完全忽略三个输入端口的自主重放器，还能给出更强的有限序列下界。确定性自主状态机
从复位态出发的轨迹必然是“有限前缀 + 周期”。对 9 位正确答案序列做反向 Z 算法，末尾
能够复用此前轨迹的最长后缀只有 `2` 项，证书给出的最短 lasso 为：

```text
preperiod                     123800
period                          7270
minimum distinct path states  131070
minimum binary state bits          17
```

所以短周期计数器或 LFSR 不能自主重放本关答案。该下界只针对完全忽略输入的电路；同时
读取当前输入并使用少量历史状态的混合电路不受此下界约束。

## 拍序边界

仅看到 `if tick == 0x1ffff` 还不足以证明从零开始。当前 EXE 的内嵌运行器模板补齐了
这一点：

```text
var tick = -1
reset_sim(): .tick = -1

while .tick < burst_target_tick {
    .level_input = get_input(.tick + 1)
    ...执行电路...
    let result = check_output(.tick + 1, .level_input, .level_output)
    handle_test_result(result)
    .tick += 1
}
```

所以首次检查参数为 `0`，随后严格递增；脚本只在参数 `0x1ffff` 返回 `win`。任意更早
的错误都会返回 `fail` 并使运行器停止，完整成功路径正好包含 `2^17` 次检查。

## 置换证明

测试没有直接令 `x = tick`，而是对 tick 做三次 XOR-shift。只看最终用于输入端口的
低 17 位，这仍是 GF(2) 上的线性映射。对 17 个单位基向量计算得到列：

```text
08241 10482 00904 01208 02410 04a21 09442 12884 05108
0a210 14420 08a41 11482 02904 05208 0a410 14820
```

高斯消元秩为 `17`，所以映射可逆。独立的直接枚举也得到：

```text
unique low17 values = 131072
minimum             = 0
maximum             = 131071
vector SHA-256       = 2fd98014c77e2d2e05cc92dfa85f9a4a155c0644ae9554967f34dffae6328605
```

低 17 位再按 `[7:0]`、`[15:8]`、`[16]` 切分，正好就是所有
`(A, B, Carry in)` 三元组。因此这里的 XOR-shift 只是改变穷举顺序，并没有把测试域
缩成伪随机样本。

## 服务端边界

已有当前 EXE kind-3 请求逆向记录表明，提交内容包含：

- 当前 `level id`；
- 实际 schematic 的 `state_to_binary` 数据；
- 自定义依赖和 validation table。

本地 gate/delay/tick 尾字段不在权威网络序列中。相关证据位于：

```text
.research/rng_score_bypass/kind3_wire/wire_reader/sub_serializer/kind3_serializer_map.md
.research/rng_score_bypass/ida/score_network/add_validation_info.c
.research/rng_score_bypass/ida/score_network/add_schematic.c
```

这说明服务端拿到的是待重算电路，而不是只接收本地伪造成绩。另一方面，客户端不会把
`byte_adder/test.si` 本身随请求发送；服务端按 level id 使用自己的关卡定义。因此，
不掌握服务端源码或服务端测试资产时，不能声称已经证明远端 `test.si` 与本机文件逐字节
相同。严格结论是：

1. 当前官方客户端的游戏内验收确定为完整穷举；
2. 网络协议确定发送实际电路，且本地分数字段不是权威输入；
3. 服务端资产版本与本机资产的字节级一致性仍是不可观测边界；
4. 公开榜单存在大量当前结构可解释的合法成绩，但榜单页面本身不能证明测试向量数量。

2026-08-03 抓取公开页面时，能耗第一名为 `103/5/515`，与关卡完成后解锁的原生
`com_add` 解法一致；页面返回 `1000` 行并疑似有分页上限。

## 样本特化判定

| 路线 | 判定 | 原因 |
|---|---|---|
| 忽略一部分 `(A,B,Cin)` | 排除 | 没有未测输入 |
| 对常见输入设捷径 | 无收益 | 每个三元组出现次数都为 1 |
| 利用 XOR-shift 碰撞 | 排除 | 低 17 位映射满秩、无碰撞 |
| 忽略输入的短周期状态机 | 排除 | 自主重放至少经历 131070 个不同状态 |
| 输入与状态混合 | 理论可行，未证明有竞争力 | 必须重放完整 131072 步 |
| 伪造本地分数 | 不成立 | 权威请求发送实际 schematic |
| 假定远端测试更少 | 无证据 | 远端测试资产不可直接读取 |

对后续 Byte Adder 攻关的直接含义是：优先研究合法的 carry-lookahead、前缀加法器、
高阻开关共享和不同 gate/delay 前沿，而不是投入算力搜索输入样本漏洞。
