# 字节加法器协议与现有存档只读审计

## 修订结论

先前把 `unlocks_components = [com_add]` 直接解释为“`com_add` 在 Byte Adder 中
必然非法”，这个结论过强，现已撤回。该字段只直接证明：首次完成 Byte Adder 时会
解锁 `com_add`。它本身既不能证明已通关后的重玩仍禁用，也不能单独证明服务器一定
接受。

新版 `2.1.281` 客户端的静态运行链给出了更直接的证据：加载关卡时，客户端先读取
已完成关卡集合，再用它构造当前关卡的运行时预算/允许表。若某个 campaign 关卡名在
已完成集合中，或处于开发者模式，该关卡的 `unlocks_components` 会被加入该表。因此，
当前账号已经完成 `byte_adder` 后重玩时，客户端预算表会纳入 kind `30` `com_add`。

公开排行榜在 2026-08-03 同时保留四个独立的 `103 / 5 / 515` 成绩：
Patchouli、FermiEnergy、AidanMars、zagadka m。该元组恰好对应一个当前动态成本为
`103/5` 的 U8 `com_add` 加零成本接口；四个独立服务端成绩与上述运行链相互印证，
是“已解锁后重玩可用”的强运行旁证。

当前正式存档和仓库候选逐字节一致，SHA-256 均为
`6acfc377ce6fa1a07aa9d91732217ecc1ac4c7d329097be102c49eaa14bfdb6f`。
结构、端口、全域语义和几何审计均通过，文件头为 `103 / 5 / 515`。但本账号的
`levels.txt` 只有：

```text
"byte_adder",true,"Default",
```

它证明本账号已完成该关卡，却没有记录 Byte Adder 成绩前沿。因此报告的最终状态是：
**客户端静态链与公开服务端成绩均强烈支持该候选合法，但本账号候选仍待实机全测试
验收，不能提前写成已认证。**

## 运行时许可链

### 加载关卡

`load_level__modelZutilities_u7564`，地址 `0x1405a19fb`：

1. 在反编译行 924 调用
   `get_completed_levels__modelZutilities_u6010(&v88)`。
2. 在行 939--940 将 `v88/v89` 作为第二个参数传入
   `get_budget__modelZboardZschematics_u2168`。
3. 同一次调用还传入当前关卡名、campaign 表、是否为 dev mode、是否为 campaign
   关卡等状态。

这证明预算不是只从关卡 `meta.txt` 静态生成，而是依赖当前账号的完成状态。

### 构造预算/允许表

`get_budget__modelZboardZschematics_u2168`，地址 `0x140282a68`：

- 参数 `a2` 被复制为 `v53/v54`；它就是上一步传入的已完成关卡集合。
- 函数遍历 campaign 表中的关卡记录，并在反编译行 419--424 以关卡名查询
  `contains(completed_levels, level_name)`；未命中时只允许 dev mode 兜底。
- 命中后，行 426--459 遍历该关卡记录内偏移 `+280/+288` 的字节序列，并通过
  `X5BX5Deq___modelZboardZschematics_u2426` 写入预算表。
- `complete_level__modelZutilities_u8913` 对同一 campaign 记录的 `+280/+288`
  明确按 `unlocks_components` 遍历，从而确认上述字节序列的字段含义。

因此可以得出窄而明确的结论：**在客户端 `get_budget` 这一层，已完成关卡声明解锁的
元件会在后续加载中进入运行时预算表。** 这比仅看 `meta.txt` 更强，但仍不把尚未完整
恢复的编译器拒绝分支或服务器重算规则擅自等同于该预算表。

### 两条拒绝字符串的边界

运行版中确实存在：

```text
<Component> is not unlocked in this level.
<This custom component> uses a {name} component not unlocked in this level.
```

当前 IDA 数据库没有恢复到这些字符串的引用函数，所以只能证明客户端包含直接元件和
自定义元件依赖的合法性检查。它们不能证明“已完成后由 `get_budget` 纳入的 `com_add`
仍会被拒绝”，更不能推翻当前公开榜上的四个 `103/5` 服务端成绩。

## 动态成本链

静态原型表里的 U8 `com_add` 默认成本约为 `100/50`，不能解释当前候选的 `103/5`。
运行版还有两条动态更新路径：

1. `complete_level__modelZutilities_u8913`，地址 `0x1405a53ef`：从当前关卡记录
   `+280/+288` 读取 `unlocks_components`，并为每个元件调用
   `add_cost__modelZscores_u2110(kind, current_score)`。
2. `process_network_responses__presenterZutilities_u38439`，地址 `0x14065403f`：
   遍历网络响应中的每类元件成本前沿，并调用
   `import_costs__modelZscores_u2127` 覆盖运行时 `component_costs` 表。

`is_score_unlocked__modelZboardZschematics_u1782` 使用固定键 `"score"`，控制的是
全局评分系统解锁，不是 Byte Adder 对 kind `30` 的专用许可判断。

这解释了为什么同一个原生 U8 加法器会按玩家/服务端导入的前沿显示 `103/5`，而不是
按静态默认表显示 `100/50`。文件头仍不是权威来源；游戏和服务器的动态重算结果才是。

## I/O 与完整测试域

运行版固定接口如下：

| 名称 | 方向 | 位宽 | permanent ID |
| --- | --- | ---: | ---: |
| `A` | 输入 | 8 | 1 |
| `B` | 输入 | 8 | 4257300573296473173 |
| `Carry in` | 输入 | 1 | 2 |
| `Output` | 输出 | 8 | 3 |
| `Carry out` | 输出 | 1 | 2340322686578998678 |

`test.si` 对 `tick = 0..0x1ffff` 依次执行：

```text
x = tick
x ^= x << 6
x ^= x >> 11
x ^= x << 9
A        = x[7:0]
B        = x[15:8]
Carry in = x[16]
```

独立审计证书得到该 17 位 GF(2) 线性映射秩为 17。输入向量 SHA-256 为
`2fd98014c77e2d2e05cc92dfa85f9a4a155c0644ae9554967f34dffae6328605`，
131072 个 tick 产生 131072 个不同的低 17 位值，恰好覆盖
`256 * 256 * 2` 个 `U8 x U8 x U1` 三元组，无缺失、无重复。

期望输出严格是：

```text
sum       = A + B + Carry in
Output    = sum & 0xff
Carry out = sum >> 8
```

期望输出序列 SHA-256 为
`a39a167788e2c5acf49f9ff73b5296c77e50e28d239915e02a978ea0ece3ae87`。
因此不存在通过未覆盖输入子集删逻辑的空间；主 `Output` 还被明确要求不能为 Z。

## 当前 `103/5` 候选

候选由 5 个固定 I/O、1 个 U8 `com_add` 和 5 条导线组成。`com_add` 位于 `(0,0)`，
word size 为 8：

| 端口 | 坐标 | 位宽 |
| --- | --- | ---: |
| `in0` | `(-1,-1)` | 8 |
| `in1` | `(-1,+1)` | 8 |
| `carry_in` | `(0,-2)` | 1 |
| `out` | `(+2,0)` | 8 |
| `carry_out` | `(+1,+2)` | 1 |

10 个引脚全部连接；无多驱动、悬空网络、位宽冲突或组合环。导线穿元件、导线穿非端点
引脚、元件实体重叠和异常端点四类物理问题均为 0。候选当前唯一缺口是本账号实机全测试
与服务端提交证据，不是格式、连通性或已知测试域语义。

### A 级：实机/服务端行为

- 当前公开榜页面保留四个独立 `103/5/515`，是已被服务端接受的强旁证。

- 公开页面不公开电路内容、服务器测试资产或重算日志；四个成绩是否逐字节采用当前候选
  不能由页面单独证明。

### B 级：当前运行版反编译链

- `load_level -> get_completed_levels -> get_budget` 证明完成状态参与当前预算构造。
- `get_budget` 证明已完成关卡的 `unlocks_components` 被加入客户端预算表。
- `complete_level -> add_cost` 与网络响应 `-> import_costs` 证明元件成本动态更新。
- 尚未恢复拒绝字符串的引用函数，故不对独立编译器分支作超出证据的断言。

### C 级：当前持久状态与候选

- `levels.txt` 为 `byte_adder complete=true`，但成绩前沿为空。
- 正式文件与仓库候选哈希一致，结构、穷举语义和几何审计通过。

### D 级：关卡元数据

- `meta.txt` 的 `unlocks_components = [com_add]` 只证明首次完成后的解锁关系。
- 单独使用该字段推导“重玩必禁”或“重玩必允”都不成立。

1. 当前账号下一步应在游戏内对现有 `103/5` 候选执行完整测试；只有游戏重算通过并形成

4. 所有新生成器继续保证线路可互相交叉，但不得穿过元件实体或任何非端点引脚。
