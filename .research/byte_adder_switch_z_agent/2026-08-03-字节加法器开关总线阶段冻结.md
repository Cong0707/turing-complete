## 冻结原因

## 关卡边界

- Byte Adder 的输入空间是完整的 `U8 A * U8 B * U1 Cin`，共 `2^17 = 131072` 个向量。
- 当前客户端测试顺序虽然由 XOR-shift 状态生成，但映射在 GF(2) 上满秩，全部输入恰好覆盖一次。
- 输出必须确定驱动，不能依赖未覆盖样本，也不能以 Z 作为正确输出。
- 当前 `examples/byte_adder/candidate/circuit.data` 是单个原生 U8 `com_add`，头部成绩为 `103 / 5 / 515`。`com_add` 在完成 Byte Adder 后才解锁，因此该候选对本关自引用，不能作为合法排行榜方案。

## 排行榜门槛

冻结时记录到的公开前沿：

| Gate | Delay | Energy |
| ---: | ---: | ---: |
| 103 | 5 | 515 |
| 91 | 6 | 546 |
| 79 | 7 | 553 |
| 154 | 4 | 616 |

若要在能耗上严格超过 `515`，至少需要达到以下之一：

- `delay = 5` 时 `gate <= 102`；
- `delay = 4` 时 `gate <= 128`；
- 更低延迟时按乘积重新判断。

## 已确认的 Switch 语义

- Bit Switch：`2 gate / 1 delay`。
- `enable = 0` 时输出 Z；`enable = 1` 时主动输出 `data`。
- 多个 Switch 可以驱动同一 BUS，但所有同时活动的驱动必须输出相同值，否则短路。
- 全 Z 的普通逻辑数据面在当前引擎中读作 0。
- Splitter / Maker 不传播 Z，不能把高阻态当作普通位宽变换数据继续传递。

若一个 BUS 上的全部 Switch 使用同一个数据 `D`，则有严格等价式：

```text
BUS(Switch(e0, D), ..., Switch(en, D))
= D & (e0 | ... | en)
```

这种 BUS 的多个 enable 不必互斥，因为所有活动驱动的数据相同。

## 二位公开宏

公开二位加法器位于：

```text
.research/byte_adder_public/hub-155-add64/dependencies/00/2e64a/Add_2/circuit.data
```

SHA-256：

```text
36339F85309BDD4BD4B3A08615B26CE4EF5F16BBBB1D753E6CCB340FA79B757B
```

它的头部成绩为 `25 / 5`，核心状态编码为：

```text
G = a & b
Q = NOR(a, b)
P = NOR(Q, G)
```

由于 `G` 被后续共享，生成 `P/G` 合计只需 3 门。高位进位通过四个 Switch 共用同一个 data 实现：

```text
c2 = (a1 | b1) & (g1 | g0 | a0*cin | b0*cin)
```

重叠活动不会短路，因为四个 Switch 的 data 相同。这是“同 data 多驱动 BUS”可作为一层 `D & OR(enables)` 宏的实物证据。

## 前缀单元推导

对互斥的 generate / propagate 状态，可使用：

```text
Gnew = BUS(
    Switch(enable=Ghigh, data=1),
    Switch(enable=Phigh, data=Glow)
)
Pnew = Phigh & Plow
```

因为 `Ghigh` 与 `Phigh` 互斥，该 BUS 无冲突。成本对比：

```text
Switch prefix cell: 5 gate / 1 delay
ordinary prefix cell: 3 gate / 2 delay
```

也就是多付 2 门换取少 1 延迟。另一种以 `G=f(0), H=f(1), G<=H` 表示单调变换的方案，单个 `T_high(x)=Hhigh & (Ghigh | x)` 可由两只同 data Switch 一层实现；但同时输出新 `G/H` 需要四只 Switch，即 `8 / 1`，当前成本偏高。

## 已排除方向

- 不再把原生 `com_add` 候选当作合法解。
- 不做输入样本特化；测试是全空间穷举。
- 不依赖 Z 作为最终答案。
- 不把 Switch 当作廉价二选一 mux；真正可用优势是同 data 多驱动 BUS 和互斥 cover。
- 不仅优化传统 ripple / Kogge-Stone。现有传统 prefix 枚举共检查 1409 个结构，最好仅 `80 / 11 / 880`，无法达到 515。
- 不把局部 BUS 门数下界直接当作可构造网表；必须验证相位、共享、冲突和完整时序。

## 下一轮精确起点

1. 将公开 `154 / 4` 解码为布尔 DAG，并保留每个 BUS 的 driver、enable、data、receiver、到达时间与共享关系。
2. 对 18 个 BUS 分别建立精确等价模型；先处理 9 个同 data BUS，再处理两 data BUS 的相容 cover。

6. 只有得到完整可物化网表、全域仿真通过和几何可路由证明后，才允许覆盖候选或正式存档。

## 提交清单与排除项

### 第二阶段：BUS 替代与递归时序

在最初冻结记录之后，本分支继续完成了两层低内存筛选。

`synthesize_bus_alternatives.py` 对每个 BUS 的实际可达局部赋值做精确表达式枚举，
并使用原公开网表的输入到达时间进行第一轮筛选。独立相加的结果是：

```text
depth 4: 56 original ordinary gates + 75 BUS gates = 131
depth 5: 56 original ordinary gates + 64 BUS gates = 120
depth 6: 56 original ordinary gates + 56 BUS gates = 112
depth 7: 56 original ordinary gates + 56 BUS gates = 112
```

D4 初筛会替换以下 10 个 BUS：

```text
N91 N120 N122 N156 N158 N231 N238 N246 N284 N308
```

其中 `N120/N284` 在实际可达域上各有一个三门表达式；`N238` 的两层 OR 表达式
完全不读取原 Switch data。这个 `131/4` 数字看似只差 3 门即可超过 515，但它只是
冻结原到达时间的局部相加，不能当作联合网表成绩。

`search_joint_choices.py` 随后从 Sum/Cout 做真实 backward slice，并在每一种替换
组合下递归重算所有输入到达时间。它先用全 Switch 选择严格复现：

```text
154 gate / 4 delay
56 live ordinary gates
98 live Switch gates
```

对上述 10 个具有 D4 表达式的 BUS 穷举全部 `2^10 = 1024` 个组合后，结果是：

```text
delay <= 4 feasible masks: 1
唯一可行 mask: 0（保留全部原 Switch）
```

10 个局部表达式同时启用时，门数确实为 131，但真实递归深度是 8，而不是 4：

```text
131 gate / 8 delay
56 live ordinary gates
50 live Switch gates
25 new Boolean gates
```

原因是若上游 BUS 也由两到三层普通门替换，下游局部表达式的输入不再保持公开
网表中的原到达时间；这些额外层会沿 carry/phase 网络连续叠加。当前表达式选择下，
`N120/N284` 忽略另一 driver、`N238` 忽略全部 data 仍未让任何一个原始普通门整体
失活，因为对应生成锥同时被其他 BUS 使用。因此“D4 独立 131，再全局死删 3 门”
不能成立。

这不是任意 Switch-Z 改写在 D4 下不可行的下界。它只严格排除了当前十个局部最小
表达式的全部组合。若继续 D4，必须做跨 BUS 联合表达式，直接共享 enable 极性与
中间项；若转向 D5/D6，则需要在真实递归时序模型中重新选择表达式，不能继续使用
冻结到达时间的独立总数。

## 第三阶段：Fermi 前沿校准与命名区间 DAG

公开个人页给出的完整 Pareto 链为：

```text
56/18, 57/17, 59/16, 61/15, 62/14, 63/13,
65/12, 67/11, 68/10, 71/9, 74/8, 79/7,
88/6, 103/5, 154/4
```

`search_fermi_carry_dag.py` 使用七门共享全加器作为严格基线，并允许每个 carry 从任意
较早 carry 经连续区间跳转。局部宏的真实成本是：

```text
slow black = 3/2
fast black = 5/1
slow gray  = 2/2；一位局部路径与 Sum 共享 P&C 时净增 1 门
fast gray  = 4/1
```

该模型严格复现 `56/18`，carry 到达时间为 `0,4,6,8,10,12,14,16,18`。固定
“每位六门 Sum 锥 + 局部 Pareto 区间计划”的受限搜索没有命中公开 `74/8`；放宽到
`82/8` 后得到完整结构见证：

```text
gate/delay = 82/8
carry arrivals = 0,3,5,4,6,5,6,6,8
sum arrivals   = 4,5,7,6,8,7,8,8
structural sha256 = 1893c0ed47cfcc7997e6b46151edad542c1c42022cceedcd4784df4125810987
```

因此可以严格断定：固定六门 Sum 锥本身并未被排除，但“各区间只保留局部 Pareto
计划再逐位 beam 选择”的搜索空间太窄；公开 Fermi 链必须依赖跨多个 carry 输出共享的
非局部 Pareto 区间，或者进一步联合改写 Sum/carry 相位。`82/8` 只用于校准，不优于
公开前沿，也没有物化为游戏电路。

随后在 `interval_dp.py` 中加入 `solve_named_interval_dag`：每个非叶连续区间最多选择
一个命名实现，所有 `C_i` 可以复用同一 DAG 节点，并以 backward slice 的节点并集精确
计门。为避免一次求解 `d=4..18` 时结果只留在终端，新增聚焦入口：

```powershell
.\.venv\Scripts\python.exe `
  .\.research\byte_adder_interval_dp_agent\run_named_interval_focus.py `
  --delay 6 `
  --output .\.research\byte_adder_interval_dp_agent\named_interval_d6.json
```

聚焦入口会立即写出：所选区间 recipe、carry edge、精确 gate/delay、完整 131072 行
真值验证、所有 BUS 冲突掩码和最终输出 Z 掩码。冻结通知到达时，旧的 `d=4..18`
宽泛求解已运行约两分半但尚未返回，且不会落盘；该进程已终止。因此 `d=6` 的当前状态
严格为 `UNKNOWN`，不能宣称已经复现 `88/6`，更不能宣称找到 `<=85/6`。
