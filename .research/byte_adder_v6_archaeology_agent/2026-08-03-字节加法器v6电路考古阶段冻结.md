# 字节加法器 v6 电路考古阶段冻结

## 结论

对以下公开归档中的 24 个 `byte_adder/circuit*.data` 已完成只读解析：

```text
examples/rng/research/archive/rng_public_search/magnitood_tc/
examples/rng/research/archive/rng_public_search/zoickx_tc/
```

没有命中可直接迁移的 `103/5`、`91/6`、`88/6` 或 `79/7`：

- 24 个文件全是版本 6；
- 所有文件的 `dependencies=[]`，`Custom` 实例数均为 0；
- 所有文件的 legacy `Add8`（kind 44）和转换后 `com_add`（kind 30）均为 0；
- 真正完整的三类结构只有 `8 x FullAdder`、六开关串行进位、`4+4`
  carry-select；
- 按当前已实机确认的成本 `XOR=3/2`、`Bit Switch=2/1`，以及当前账号
  `levels.txt` 中可导入的 `FullAdder=16/8` 重算，三类完整主文件分别是
  `128/64`、`144/18`、`209/10`，均不构成当前排行榜前沿。

因此，这批 v6 文件能够证明早期玩家如何利用 Z 总线，但不能解释当前榜单的
`103/5`、`88/6`、`79/7` 等成绩，也不应覆盖正式存档。

## 关键格式差异

直接把 v6 enum 映射为 v15 enum 会得到可解析容器，却不会得到等价物理电路。
本批样本实测至少有四处针脚差异：

| 元件 | v6 针脚 | 当前针脚 | 影响 |
|---|---:|---:|---|
| `LevelInput8` | output `(+1,0)` | word input output `(+3,0)` | 接口错开 2 格 |
| `LevelOutput8` | input `(-1,0)` | word output input `(-3,0)` | 接口错开 2 格 |
| `Switch1` | enable `(0,-1)`，out `(+1,0)` | enable `(0,+1)`，out `(+2,0)` | 旧开关全部断线 |
| `Not` | out `(+1,0)` | out `(+2,0)` | parallel 的 `~C4` 断线 |

脚本对临时 v15 的关卡字接口做了中心平移；对 Switch/Not 则在离线审计时使用
v6 针脚表，不伪装成当前可运行布局。所有临时 v15 都明确标记
`current_game_ready=false`，其旧头部分数也没有被篡改。

## Low-Delay：六开关多数进位链

主文件：

```text
zoickx_tc/schematics/byte_adder/Low-Delay/circuit.data
legacy header: 96/36
16 XOR + 48 Switch + 2 Splitter8 + 1 Maker8 + campaign I/O
当前重算: 144/18/2592
```

每一位使用两个 XOR 生成和：

```text
S[i] = (C[i] XOR B[i]) XOR A[i]
```

进位先用三只 Switch 生成三个乘积项：

```text
t0 = Switch(data=C[i], enable=B[i])  = B[i] C[i] 或 Z
t1 = Switch(data=A[i], enable=C[i])  = A[i] C[i] 或 Z
t2 = Switch(data=B[i], enable=A[i])  = A[i] B[i] 或 Z
```

再让每个 `t` 自己控制第二只 Switch，并把三个输出接到同一 BUS：

```text
C[i+1] = resolve(
    Switch(data=t0, enable=t0),
    Switch(data=t1, enable=t1),
    Switch(data=t2, enable=t2)
)
```

活跃 driver 永远只驱动 `1`，所以没有冲突；无 driver 的情况以 Z 表示逻辑 0。
8 条进位 BUS 全部通过 131072 组真值，冲突为 0。最终 `C8` 有 65536 组 Z，
`Wire.value` 按 0 读取时语义正确。

旧成本中 Switch 只有 1 gate，因此每位为 `2*3 + 6*1 = 12`，总门数正好
`96`。当前 Switch 为 2 gate，每位变成 18，总门数 144。当前关键路径为每位
两层 Switch，最终再经两层 XOR，总延迟 18。

## Low-Delay-parallel：4+4 carry-select

主文件：

```text
zoickx_tc/schematics/byte_adder/Low-Delay-parallel/circuit.data
legacy header: 139/20
21 XOR + 70 Switch + Not/And/Or/Xnor 各 1
当前重算: 209/10/2090
```

拓扑可严格分解为：

1. bit 0..3 使用前述六开关宏，得到 `S0..S3` 和 `C4`；
2. bit 4 同时生成 `P4=A4 XOR B4`、`~P4`、`G4=A4 AND B4`、
   `H4=A4 OR B4` 和 `~C4`；
3. bit 5..7 建立两条互相独立的六开关进位链，一条从 `G4` 出发，代表
   `C4=0`；另一条从 `H4` 出发，代表 `C4=1`；
4. `S4..S7` 与 `C8` 各使用两只 Switch，由 `C4/~C4` 在两组预计算结果中
   选择，五条输出 BUS 都连续驱动且冲突为 0。

当前成本账本：

```text
lower 4-bit ripple       4 * 18 = 72
two speculative chains  2 * 3 * 18 = 108
P4/G4/H4/~P4/~C4                  = 9
five 2-Switch selectors      5 * 4 = 20
total                              = 209
```

完整主文件通过 131072 组真值，Sum/Cout 均无 Z、无冲突，关键延迟为 10。
`circuit_backup_2.data` 少了 `Not ~C4`，因此只有 102 个元件且真值失败；其余
parallel 备份虽布线路径不同，但逻辑均通过且仍是 `209/10`。

不能把文件头直接当作 2.1.x 排行榜分数。

## 可复现方法

运行：

```powershell
$env:PYTHONDONTWRITEBYTECODE = '1'
.\.venv\Scripts\python.exe `
  .\.research\byte_adder_v6_archaeology_agent\audit_legacy_byte_adders.py
```

脚本执行以下验证：

- 逐文件 v6 解压和结构解析；
- 迁移器 `write_v15 -> parse_v15` 往返；
- 本项目 `decode_v15` 第二次解析；
- 17 输入、131072 组位并行真值；
- 每条多 driver BUS 的 driven/value/conflict 三平面；
- 当前基础门成本和加权关键路径重算。

详细逐文件清单位于 `legacy_byte_adder_inventory.json`；两套主电路的元件、网络、
driver、sink、语义标签和真值摘要位于 `legacy_low_delay_topologies.json`。
