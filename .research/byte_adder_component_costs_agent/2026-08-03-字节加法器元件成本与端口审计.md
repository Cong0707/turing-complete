# 字节加法器元件成本与端口审计

## 结论

当前正式 `byte_adder/Default/circuit.data` 的文件头虽然是 `103/5/515`，并且内部只有一只
`kind 30 / com_add`，但这不能证明 Byte Adder 关卡内已经能以 `103/5` 使用原生加法器：

- `campaign/byte_adder/meta.txt` 明确写着完成本关后才解锁 `com_add`；
- 当前 `levels.txt` 的 `byte_adder` 成本前沿为空；
- 游戏会从已保存的关卡前沿导入可覆盖成本，文件头本身不是成本表；
- 可执行文件中的 `com_add(U8)` 初始默认仍是 `100/50`。

因此后续优化必须从基础门、字门、Switch 和零成本 Splitter/Maker 构造，不能把现有
`103/5` 文件当作合法的原生加法器成本证明。

## 原生端口

IDA 从当前 2.1.281 原型表导出了 35 种相关 kind，缺失数为 0。Byte Adder 最相关端口为：

| kind | 名称 | 输入 | 输出 |
| ---: | --- | --- | --- |
| 3 | Bit NOT | `Input (-1,0) U1` | `Output (+2,0) U1` |
| 4/7/10 | Bit AND/OR/XOR | `Input0 (-1,-1)`, `Input1 (-1,+1)` | `Output (+2,0)` |
| 12 | Bit Switch | `Enable (0,+1) U1`, `Input (-1,0) U1` | `Result (+2,0) U1 tristate` |
| 15 | Full Adder | `Carry in (0,-2)`, `Input0 (-1,-1)`, `Input1 (-1,+1)` | `Result (+2,0)`, `Carry out (+1,+2)` |
| 16 | U8 Bit Maker | 八个 U1，纵向 `y=-3..+4` | `Result (+1,0) U8` |
| 17 | U8 Bit Splitter | `Input (-1,0) U8` | 八个 U1，纵向 `y=-3..+4` |
| 18/19/20/23 | Word NOT/OR/AND/XOR | 与同类 Bit 门相同 | 可变 word_size 输出 |
| 25 | Word Switch | `Enable (0,+1) U1`, `Value (-1,0) word` | `Output (+2,0) word tristate` |
| 30 | Add | `Input0 (-1,-1) word`, `Input1 (-1,+1) word`, `Carry in (0,-2) U1` | `Result (+2,0) word`, `Carry out (+1,+2) U1` |

Word 原型中的 `9223372036854775807` 是 AUTO_SIZE token，不是实际 64 位数据宽度；组件
实例的 `word_size` 决定真实宽度。

## Switch 的 Z 语义

Switch 输出的原型方向码不是普通 output，而是 `output_tristate`：

```text
enable=0 -> output._is_z=true
enable=1 -> output._is_z=false, output.value=input.value
```

多驱动网会忽略 Z；所有主动驱动值相同才合法，0/1 冲突会短路并停止模拟。全 Z 网的普通
数据面读作 0，但 Architecture Output 仍能单独检查 `_is_z`。Splitter/Maker 不会传播 Z，
而会把数据面 0 重新变成主动 0。因此 Byte Adder 可以用互斥 Switch 消掉最终 OR 树，
但不能把冲突驱动当作 wired-OR，也不能通过 Splitter 免费复制独立三态源。

## 排行榜预算

公开第一参考为 `103/5 = 515`。严格击败 515 时，各延迟的最大门数为：

| delay | gate 上限 |
| ---: | ---: |
| 4 | 128 |
| 5 | 102 |
| 6 | 85 |
| 7 | 73 |
| 8 | 64 |
| 9 | 57 |

最值得优先验证的 delay-5 账本是：

```text
P = A XOR B          24 gate / 2 delay
S = P XOR CarryVec   24 gate / 2 delay
Carry 网络预算       <=54 gate，且 CarryVec 到达 <=3
总计                 <=102 gate / 5 delay
```

这只是明确的综合目标，不是已经找到的网表。若 Carry 网络无法在 `54/depth3` 内完成，
应同时搜索以下前沿，而不是只优化 ripple adder：

```text
<=85/6
<=73/7
<=64/8
```

Switch 路线适合把互斥积项直接汇入同一三态总线，以 `2n` gate 替代积项后的 OR 树；只有
同时减少门数或关键深度时才值得采用。普通 AND/OR 表达式机械换 Switch 通常不会省门。
