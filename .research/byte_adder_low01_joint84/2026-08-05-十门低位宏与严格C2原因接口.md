# Byte Adder 十门低位宏与严格 C2 原因接口

日期：2026-08-05

## 结论

成熟的 `10 gate / D4` bit0 全加器宏没有隐藏的 `C2@2` 收益。它省下的一门，正是把
bit0 carry 的两个早期原因先 resolve 成 `C1@2`；而严格前缀需要在同一时刻输出：

```text
C2@2 = V1 * (G1 OR G0 OR T0)
T0@1 = Cin * (A0 OR B0)
```

`C1@2` 已经来不及再经过 C2 Switch。若重新公开 `T0@1`，只能采用以下两种同价接口：

```text
两原因：T0 两-Switch owner 4 gate + G0 1 gate
三原因：A0B0、A0Cin、B0Cin 三只 AND，共 3 gate
```

前者在 C2 中需要两只 bit0 Switch，后者需要三只，二者的“原因生产 + C2 消费”成本
严格相同：

```text
4 + 1 + 2*2 = 9 gate
3     + 3*2 = 9 gate
```

所以不能把 `joint10` 的局部 `11 -> 10` 直接带入当前 `C2@2 -> B23@3 -> C6@4`
关键路径。阻塞它的不可删除项是：

```text
V1 * Cin * P0
```

其中 `P0=A0 XOR B0`。本报告关闭的是固定 `C2@2` 原因接口，不是全部游戏电路的全局
下界。

## 一、为什么三因子项不可缺少

标准进位为：

```text
C1 = G0 OR P0*Cin
C2 = G1 OR P1*C1
```

利用 `G1<=V1` 与 `P1=V1*NOT G1`：

```text
C2 = V1*(G1 OR C1)
   = V1*(G1 OR G0 OR Cin*(A0 OR B0))
```

若保留 `G0` 单独原因，`T0` 中真正不可被它吸收的剩余 one-set 是：

```text
V1 * Cin * P0
```

固定真值重放中恰有 `4` 行命中：

```text
bit0=P, Cin=1, bit1=P
```

两个 P 状态各有两种原始输入排列，所以是 `2*2=4` 行。删除 `T0` 后这些行全部把
正确的 `C2=1` 算成零。

## 二、为什么一只普通 D1 gate 不够

为了让最终 C2 owner 在 `D2` 完成，bit0 原因必须不晚于 `D1`。一只普通二输入门只
能读取三个 bit0 原始输入中的两个。若其 one-set 要严格包含于三输入多数函数 `C1`，
它不能在“只有一个输入为一”的行输出一。因此可用的非零两变量正相原因只能是三个
pair product：

```text
A0*B0
A0*Cin
B0*Cin
```

任意两个都会漏掉第三种“恰有两个一”的多数行，所以普通门方案必须支付三只 AND。

这不是门序列枚举，而是多数函数的 cylinder 约束：忽略第三个变量的原因若在某个 pair
赋值上为一，则该 pair 的两个 third-variable cofactor 都必须属于 majority one-set；只有
`11` 满足该条件。

## 三、两种最小原因编码严格打平

### 3.1 两条原因 rail

任选一个变量作公共数据，三种旋转完全对称。当前结构选择：

```text
T0 = BUS(
  SW(A0,Cin),
  SW(B0,Cin)
)                                           4 gate @1

G0 = A0 AND B0                              1 gate @1
```

于是：

```text
C1 = G0 OR T0
C2 = BUS(
  SW(T0,V1),
  SW(G0,V1),
  SW(G1,V1)
)                                           @2
```

所有 C2 driver 共用 `V1` data，重叠行同值，不产生 active-zero/active-one conflict。

只计 bit0 原因及其 C2 Switch：

```text
T0 owner                  4
G0                        1
T0/G0 两只 C2 Switch      4
---------------------------
subtotal                  9
```

### 3.2 三条 pair rail

展开为：

```text
R01 = A0*B0
R0c = A0*Cin
R1c = B0*Cin                              3 gate @1
```

三者的 OR 正好是 `C1` one-set。为了保持 `C2@2`，它们必须各自进入一只最终 Switch：

```text
三只原因 AND             3
三只 C2 Switch           6
---------------------------
subtotal                  9
```

它没有比 `T0+G0` 少门，只是把四门 early owner 换成三只普通 AND，再在 C2 多付一只
Switch。

## 四、两个看似便宜的替换都会产生假阳性

不能把三因子项偷换成：

```text
Cin*V1
```

因为 bit0=K 时 `V0=0`，即使 `Cin=1,bit1=P`，真实 `C1/C2` 仍为零。

也不能偷换成：

```text
V0*V1
```

因为 `Cin=0,bit0=P,bit1=P` 时真实 carry 仍为零。

固定审计分别记录了这两类可达反例。主动零不能与另一条 one driver 并线“覆盖”；那会
成为真实 BUS conflict，而不是 Boolean OR。

## 五、十门宏为何必然慢一层

十门人口计数宏使用：

```text
V0 = A0 OR B0
G0 = A0 AND B0

C1 = BUS(
  SW(Cin,V0),
  SW(G0,G0)
)                                           4 gate @2
```

随后四门闭合 `S0`。这里两条 Switch 已经把 carry 原因 resolve 到同一个 C1 owner；
它们的独立输出不是可免费再次接线的 rail。于是最便宜的后续 owner 是：

```text
C2 = BUS(
  SW(C1,V1),
  SW(G1,V1)
)                                           4 gate @3
```

布尔值完全正确，但 arrival 从 `C2@2` 变为 `C2@3`，继而使 `B23@3` 接口丢失。

若在十门宏外另加原来的 `T0@1`，会增加四门；若把十门宏改回 `T0+G0` 并用普通 OR
形成标量 `C1`，正好恢复权威十一门结构。局部省下的一门不能同时保留两种接口。

## 六、与 C1/S1 五门单元的关系

另一条可能是保留 `T0/G0`，删除标量：

```text
C1 = OR(T0,G0)
```

再让 `S1` 直接读取两个原因。但 `S1` 同时需要：

```text
bit1=K/G 时读取 C1；
bit1=P 时读取 NOT C1。
```

正负两个 care-domain 都复用 `T0 OR G0`。现有独立审计已经证明，固定 C2 owner 与当前
paid basis 下，没有得到把 `{C1,S1}` 从五门压成四门的手工因式分解：

```text
.research/byte_adder_low01_joint84/
2026-08-05-C1S1五门因式分解与四门阻塞.md
```

因此“删除 C1 gate”只是把同一个 OR 共因子复制到 S1 两个相反相位，不是净省门。
