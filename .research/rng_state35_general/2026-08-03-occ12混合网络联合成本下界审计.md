# RNG occ12 混合网络联合成本下界审计

## 结论

对 `occ12-warm.json` 的 35-state 线性重编码候选完成了 cancellation-aware 两层混合
网络联合审计。在刻意把所有 Switch-XOR3 的 NOR/AND 控制门都按 **0 门**计算的严格
放松模型中，114 条可独立复核的输出覆盖割已经使弱主问题的精确最优值达到：

```text
relaxed core >= 224
fixed shell = 213
physical total >= 437
```

因此该候选不可能达到 `<=430 gate`，也不能产生预期的无 RAM `431/9/66` 解。
这不是因为控制门估价偏高：控制门已经全部免费，真实成本只会更高。

这个结论只适用于本候选和本文定义的完整两层库，不是对所有状态编码、任意深度 XOR
DAG 或任意跨拍拓扑的全局不可能性证明。

## 成本口径

```text
scalar XOR2 / U1 Word XOR = 3 gate / 2 delay
U2/U3/U4/U8 Word XOR      = 6/9/12/24 gate / 2 delay
scalar Switch-XOR3 base   = 8 gate
Switch-XOR3 NOR/AND       = 0 gate（仅在下界放松中）
fixed shell               = 213 gate
RAM                       = 禁止
```

Word 打包没有折扣。真实 scalar Switch-XOR3 由 4 个 Bit Switch 的 8 门基础成本、3 个
NOR 控制和 1 个可选 AND 控制组成；不同节点可共享相同控制函数。本文为取得严格下界，
进一步把全部控制函数免费，因此无需依赖某一种共享选择。

## 候选枚举

一级源完整包含 35 个 unit 以及全部 support-2、support-3 线性形式。每个输出完整枚举：

- direct 一级形式；
- 末级 scalar XOR2；
- 末级 scalar Switch-XOR3；
- 目标坐标三次出现及目标外坐标两次出现所产生的全部取消项；
- 一级 pair/triple 和同输出末级类型的全局共享成本。

最终得到：

```text
候选实现             340,549
紧凑实现变量引用   1,350,474
有成本变量               7,205
一级形式变量             7,140
末级类型变量                65
```

weight-2 目标强制 direct pair 是无损规范化：任何替代实现至少支付 3 门末级 XOR2，换成
3 门 direct pair 不会增加成本，并可能为其他输出提供更多共享。

支配消元由原先逐候选扫描全部替代，改成“已存在需求触发集”查询。小维度穷举验证在
8-state 下覆盖 92 个一级源、125,580 个三源组合、238 个目标；新旧物理/放松消元结果
逐项完全相同。

## 下界证明方法

每个输出的合法实现是有成本变量上的单调 DNF。脚本不为 340,549 个实现各建 selector，
而是重复执行：

1. 用 RC2 精确最小化当前弱主问题的成本；
2. 若某输出尚未覆盖，从其每个 DNF 项的当前 false 变量中构造 hitting set；
3. 加入该 hitting set 的正子句。

任一合法实现会满足其中某个 DNF 项；hitting set 与每个项相交，所以该正子句必然成立。
因此每条割都是原完整覆盖条件的逻辑后果。只使用这些后果得到的主问题比原问题更弱；
弱主问题最优值达到 224，便严格推出原问题最优值也至少为 224。

本次前沿：

```text
iteration 1: weak optimum   0, 0/46 covered, +46 cuts
iteration 2: weak optimum 138, 10/46 covered, +36 cuts
iteration 3: weak optimum 212, 14/46 covered, +32 cuts
iteration 4: weak optimum 224 > bound 217, stop
```

## 工程记录

最初尝试过“每个实现一个 selector”的 MiniCard 编码，C 端二元蕴含使工作集升至
661 MiB，已在越过 680 MiB 上限前主动终止。随后低内存 lazy 编码在 MiniCard 1.2 的
“重复 literal 原生 at-most + 宽正子句”路径稳定触发 Windows `0xC0000005`；该失败运行
没有被当成 SAT/UNSAT 证据。最终改用 RC2 加权软子句，14.5 秒内完成严格结果。

本轮没有启动游戏、没有读取或修改正式存档、没有使用 RAM、没有创建子代理。

## 下一步

`occ12-warm` 两层路线已经比 430 门目标至少高 7 门，不应继续优化其控制共享。下一步应
改动候选本身或拓扑类别：

1. 搜索新的 `occ11/occ10` 可满足状态编码；
2. 允许跨输出共享的三层或更深 XOR DAG；
3. 联合优化状态编码和真实 Switch 控制，而不是先固定 heavy-occurrence；
4. 探索合法跨拍重定时，但继续排除 RAM 和服务端不可重算技巧。
