## 已复核基线

公开 Hub 79 加法器：

```text

154 gate / 4 delay / 616 energy
49 Bit Switch + 56 ordinary gates
```

已有穷举审计证明它在全部 `2^17 = 131072` 个
`A[7:0], B[7:0], Cin` 输入上正确，且 18 条多驱动 BUS 没有 0/1 冲突。

本轮重新检查了 `.research/byte_adder_switch_z_agent` 的独立 BUS 替换与联合时序结果。
独立冻结输入到达时间得到的 `131/4` 不是有效全局网表：十个局部替换同时采用后，
真实递归深度为 `8`；在这些既有替代表达式的全部 `2^10` 组合中，
满足全局深度不超过 4 的唯一组合是保留原电路，即 `154/4`。
因此不能再沿“局部门数相加，再假设删三门”的路线汇报 `129/4` 或 `128/4`。

## 关键代数

对每一位定义：

```text
G = A & B
K = ~(A | B)
L = ~K = A | B
P = A xor B
```

进位递推可写成：

```text
Cout = L & (G | Cin)
```

这个形式比显式 `P` 更适合高阻 BUS。两只使用相同 data=`L` 的 Switch：

```text
Switch(enable=G,   data=L)
Switch(enable=Cin, data=L)
```

可以在一层中实现 `L & (G | Cin)`，重叠时两只驱动器数据相同，不会短路，
成本为 `4 gate / 1 delay`。

对区间转移，以 `(G,L)=(f(0),f(1))` 编码 `K/P/G` 三态。低区间 `lo` 与
高区间 `hi` 合成满足：

```text
Gnew = Lhi & (Ghi | Glo)
Lnew = Lhi & (Ghi | Llo)
```

每个输出都可用两只同 data=`Lhi` 的 Switch 在一层产生；完整双轨合成成本
`8 gate / 1 delay`。这是后续构建真正四延迟前缀 DAG 的基础，而不是局部布尔替换。

公开 `154/4` 还使用了更省的三区间恒等式。对区间内各位的单点生成集合
`Ablock = OR(Gi)`，有：

```text
CarryOut = Lblock & (CarryIn | Ablock)
```

因为 `Lblock=1` 时，区间中任意 generate 都没有被更高位 kill 覆盖；两只
同 data=`Lblock` 的 Switch 可在一层完成该式。公开网表中的：

```text
N158 = L[4:2]
N238 = G2 | G3 | G4
N246 = C5 = N158 & (C2 | N238)
```

正是这个结构。它说明下一轮应联合综合“区间 survival `L` + generate-any `A` +
最终相位选择”，避免同时物化完整 `G/K/P` 三轨。

## 公开电路分层事实

反向检查公开网表得到：

```text
depth 1: 21 ordinary + 7 Switch
depth 2: 20 ordinary + 9 Switch
depth 3: 11 ordinary + 18 Switch
depth 4:  4 ordinary + 15 Switch
```

普通门总数 56、Switch 总数 49，按 Switch 每只 2 gate 合计 154。
所有序列化普通门都在输出 backward slice 内，没有可直接删除的死门；
所有标量网络也没有可直接合并的相同 `(value, driven)` 信号。
因此要达到 `<=128/4` 必须重写至少一个完整区间层或输出相位层。

## 下一步精确搜索入口

1. 用 `(G,L)` 双轨构建区间 DAG，并允许区间只保留 `L` 与 `OR(Gi)`，联合枚举
   三位分组，而不是独立替换 18 条 BUS。
2. 优先精确综合公开三位块 `[4:2]`：联合输出 `L[4:2]` 与
   `G2|G3|G4`，保留深度 2，并计入共享的一层原始门和冲突约束。
3. 枚举最终输出 BUS 时，每个 driver 必须满足
   `enable & (data xor target) == 0`；所有 target=1 样本必须被覆盖。
   这样可同时证明正确性和无主动 0/1 冲突。
4. 任意命中必须重新从九个输出做全局 backward slice，递归复算真实深度和
   唯一元件成本，然后对全部 131072 个输入验证 `Sum/Cout`。
5. 在生成可物化 v15 网表、通过几何障碍审计前，不覆盖共享候选或正式存档。

## 当前结论

当前没有可落盘的 `<=128/4` 完整网表，也没有把局部下界误报成候选。
最有价值的新起点是上述 `(G,L)` 一层区间合成与
`Lblock / OR(Gi)` 联合状态编码；下一轮应直接对完整分组 DAG 做搜索。

## 2026-08-03：三态输出的物理网络纠错

后续交叉审计发现，早期 SAT 抽象允许同一个 Switch 输出同时出现在两个成员集合不同的
resolved BUS 中。例如抽象 `2-bit 10/2` 证书的两个输出 BUS 分别是：

```text
U = {7, 11}
V = {7, 11, 12}
```

在布尔/Z 求值器中这看起来像同一 driver 的免费扇出；但在 Turing Complete 中，同一个
输出针脚接入两组导线会把两组导线合并为同一物理网络，不能作为两个隔离的 BUS 使用。
因此必须执行以下规则：

```text
任意两个 resolved BUS 若共享至少一个 source，则二者完整 source set 必须相同。
```

审计脚本与机器结果：

```text
audit_cross_bus_driver_reuse.py
cross_bus_driver_reuse_audit.json
```

它们确认以下旧证书不可物化，只能保留为 SAT 编码漏洞的回归反例：

```text
transfer2-b10-d2-c7-s3.json
transfer3-b18-d3-c12-s6.json
```

这也撤回了“完整双轨 combine 只需三只 Switch，即 `6/1`”的结论。两个独立输出必须
各自拥有驱动器，通用双轨 combine 仍应按四只 Switch，即 `8/1` 计费。

## 物理隔离后的有效 transfer 证书

`repair_transfer_bus_isolation.py` 对旧证书只做必要的 Switch 复制/被支配 driver 删除，
随后调用更新后的独立 verifier，检查所有组件输入 BUS 与最终输出 BUS 的完整物理网络
partition，而不只检查两个最终输出。

复跑结果：

```text
transfer2-physical-b12-d2.json
  12 gate / 2 delay
  16 assignments / 32 output checks
  mismatch=0 / conflict=0 / illegal-Z=0
  physical_net_partition_violation=0

transfer3-physical-b20-d3.json
  20 gate / 3 delay
  64 assignments / 128 output checks
  mismatch=0 / conflict=0 / illegal-Z=0
  physical_net_partition_violation=0
```

其中三位 `20/3` 是当前已经机器重放确认的真实物理上界，比四只 Switch 逐层组合得到的
朴素 `22/3` 更小。它仍然只是区间 `(U,V)=(f(0),f(1))` 宏，不是完整 Byte Adder。

## 三位局部搜索与相位搜索

`search_three_bit_block.py` 在六个原始输入、两层普通门/Switch BUS 的受限语法中联合枚举：

```text
Vblock=f(1) 独立最小：18 gate

联合共享后：             26 gate / depth 2
```

该结果与公开结构的局部代数相符，但只封闭脚本明确定义的两层语法，不是无条件下界。

`search_shared_phase.py` 又在 Hub79 当前信号基底上枚举最多两只新增普通门，尝试在
depth 3 直接产生 `~C5`，以便把 S5/S6/S7 的三 driver 选择压缩为两 driver。命中数为零。
因此“在现有基底上加不超过两门，再净删三只 Switch”的捷径已排除；若要共享 `~C5`，
必须联合改写中间三位块，而不是局部补门。

## 冻结前发现但尚未验证的新方向

当前存档的 `byte_mux` 已保存成本为 `34/3`。运行时的窄字宽缩放公式会令同一原生 MUX
在 U1/U2/U3 宽度下分别计为 `1/3`、`2/3`、`3/3`。更重要的是，若先在 Byte MUX 关卡
合法取得“两只 Word Switch + 一只 NOT”的 `33/2` 前沿，则窄宽 MUX 可能相应成为：

```text
U1 MUX = 1 gate / 2 delay
U2 MUX = 2 gate / 2 delay
U3 MUX = 3 gate / 2 delay
```

这是运行时成本缩放的推导线索，不是已经验收的 Byte Adder 候选。恢复研究时应先由主任务
独立确认 `33/2` Byte MUX 能否在游戏与服务端合法导入，再考虑用窄宽 MUX 做两层
Shannon/区间状态综合。未验证前不得把它写入候选或正式存档。
