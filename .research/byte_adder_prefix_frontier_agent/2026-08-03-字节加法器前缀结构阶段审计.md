# 字节加法器前缀结构阶段审计

## 2026-08-03 / 冻结点

本目录只研究 `A[7:0] + B[7:0] + Cin -> Sum[7:0], Cout` 的常规门级结构，
不启动游戏、不写候选、不修改正式存档。目标参考点是当前原生 `com_add` 的
`103 gate / 5 delay / 515 energy`。

### 固定成本模型

| 元件 | gate | delay |
|---|---:|---:|
| NOT / AND / NAND / OR / NOR | 1 | 1 |
| XOR / XNOR | 3 | 2 |
| Bit Switch | 2 | 1 |
| 两只互斥 Bit Switch 构成的一路选择 | 4 | 1 |
| 导线、常量、Splitter、Maker、关卡端口 | 0 | 0 |

这里没有把 XOR 错算成一门。每位预处理同时需要 `P=A XOR B` 和
`G=A AND B` 时，使用以下共享半加器恒等式：

```text
G = A AND B
Q = A NOR B
P = Q NOR G
```

所以同时得到 `P/G` 是 `3 gate / 2 delay`；这是共享中间项带来的真实三门实现，
并不改变独立 XOR 的 `3/2` 成本。

### 枚举范围

`enumerate_frontier.py` 共生成并审计 2177 个结构：

- 1 个共享全加器 ripple；
- Serial、Brent-Kung、Kogge-Stone、Sklansky、Han-Carlson 各自的全部
  256 种“前缀进位或局部 ripple 进位”混合掩码；
- 将动态 `Cin` 作为前缀树第 0 叶的 Brent-Kung、Kogge-Stone、Sklansky，
  各自全部 256 种混合掩码；
- 8 位的全部 128 种有序 carry-select 分块。

动态 `Cin` 叶使用 `(G=Cin, P=0)`。任何已覆盖 `Cin` 的前缀单元会自动退化成
不再生成组传播信号的 gray cell。这一点是公开 Kogge-Stone 实物与模型对齐的
关键，不能在树尾机械增加八个 Cin 修复单元。

每个前缀组合都检查区间连续性；每个最终结构另外执行 32 个低位边界向量和
32 个固定种子随机向量。结构摘要、逐输出到达时间和 Pareto 集均写入
`frontier.json`。

### 结果

| 结构 | gate | delay | energy |
|---|---:|---:|---:|
| Ripple，共享全加器 | 56 | 18 | 1008 |
| Carry-select 最优分块 `1+3+4` | 110 | 9 | 990 |
| Brent-Kung，动态 Cin，纯前缀 | 76 | 12 | 912 |
| Kogge-Stone，动态 Cin，纯前缀 | 103 | 10 | 1030 |
| Sklansky，动态 Cin，纯前缀 | 79 | 10 | 790 |
| **Sklansky，动态 Cin，混合掩码 `0x8b`** | **75** | **10** | **750** |

本轮常规结构最优是 `75/10/750`。`0x8b` 表示第 0、1、3、7 位使用局部
ripple 进位/求和共享，其余进位取 Sklansky 前缀结果。其逐输出到达时间为：

```text
sum0..sum7 = 4, 6, 8, 8, 10, 10, 10, 10
cout       = 10
```

2177 个结构中，`energy < 515` 的数量是 **0**。这不是任意布尔电路的下界，
而是本报告明确枚举范围内的负结果。

### 公开实物校准

通过只读 Schematic Hub 请求取得公开条目 `186`：

```text
名称                Kogge-Stone 8bit
主电路 SHA-256      d661a61467e0c24f52e0b2f025684c7f6e428da73b95d961cf68c5af65f52f5c
游戏声明成绩         111 / 10 / 1110
PG 子元件             4 / 2
Black combine 子元件  3 / 2
Gray combine 子元件   2 / 2
```

公开实物的 8 个 PG、13 个 black、8 个 gray 与动态 Cin Kogge-Stone 的单元数
完全一致：

```text
8*4 + 13*3 + 8*2 + 8*XOR(3) = 111 gate
```

把 8 个独立 `XOR+AND` PG 改成上述三门共享 PG，恰好得到模型的
`103/10`，延迟不变。这构成了对枚举器计分和动态 Cin 单元分类的独立实物校准。

仓库中另一份当前 v15 公开实物“4d 8bit adder”为 `154/4/616`，由 49 个
Bit Switch 和 56 个普通门构成。它已经优于本轮所有教科书前缀/CS 结构的能量，
也说明下一阶段必须研究一般化的多驱动一热 Switch-Z 网络，而不是继续穷举
Brent-Kung 与 Kogge-Stone 的微小变体。

### 对 `energy < 515` 的含义

严格改进 515 至少要进入下列一个格点：

```text
delay 4: gate <= 128
delay 5: gate <= 102
delay 6: gate <= 85
delay 7: gate <= 73
delay 8: gate <= 64
```

常规结构没有命中。下一阶段的有效方向是：

1. 从公开 `154/4` 的一热 Switch-Z 网络出发，允许一层额外控制逻辑，目标
   `<=102/5`；
2. 对 9 个输出联合做控制项共享，而不是逐位独立实现 carry/sum；
3. 研究 group generate/kill/propagate 的三态总线编码，利用关闭开关的高阻态
   消除显式 OR；
4. 对任何候选执行服务端可重算语义所需的“每个总线每个输入恰有一个驱动”证明。

### 冻结结论

- 本轮没有可写入存档的 `<515` 候选。
- `75/10/750` 是当前常规结构枚举的最优点，不应覆盖已存在的 `103/5/515`。
- 下一步应转向通用 Switch-Z 联合综合；继续单独优化传统 prefix 拓扑收益不足。
- 本目录没有运行中的 Python、SAT、Yosys 或游戏进程。
