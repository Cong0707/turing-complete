# Delay Bit 不保存高阻态审计

## 结论

在当前审计的 Turing Complete `2.1.281` 中：

```text
com_delay_line_bit 只跨拍保存 U1 value。
输入的高阻态不会被保存；下一拍输出始终主动驱动。
```

因此搜索器必须把 `Delay Bit` 建模为一个普通二值寄存器，不能把它当作可保存 `0 / 1 / Z` 的三值状态单元。

## 审计对象

```text
文件：D:\Game\Steam\steamapps\common\Turing Complete\Turing Complete.exe
SHA-256：c93f5e8e826050c3f92e2b3891d26fcdfc933658614185cb9b2eb6a34c5b8d1c
镜像基址：0x0000000140000000
```

IDA 数据库来自同一可执行文件。导出的反编译和交叉引用保存在 `delay-native-audit/`，所有文件哈希记录在 `delay-z-storage-certificate.json`。

## 原生路径

组件编号映射和分派表均指向：

```text
case 13 = com_delay_line_bit
dispatcher = add_circuit_code__modelZsimulationZcode95gen_u4264
```

早期/加载分支：

```text
0x000000014044a74c  引用 load_and_output
0x000000014044a797  读取 Nim 字符串常量 "1"
0x000000014044a7c5  调用 load_and_output(..., "1")
```

晚期/存储分支：

```text
0x000000014044a862  引用 store_bit
```

`store_bit` 生成的模拟代码只有一个状态写入：

```text
store(#SIMULATION_STATE + state_index, U1 value)
```

它恰好调用一次 `get_state_index`，且完全没有：

```text
get_z_state_index
z_state_index
_is_z
```

## 为什么常量 1 表示主动驱动

`load_and_output` 从普通状态槽加载保存值，然后把第五个字符串参数继续传给 `store_output`。case 13 在该参数位置传入固定字符串 `"1"`。

`store_output` 生成的关键结构是：

```text
if predicate != 0 {
    // drive value
}
```

动态 Z 输出帮助函数生成 `!z...` 作为同一谓词。这同时确定了谓词极性：

```text
predicate = 1  => 非 Z，主动驱动
predicate = 0  => Z，不驱动
```

所以 Delay 的下一拍不是“恢复此前的 value 与 Z”，而是“恢复 value，并固定以非 Z 方式输出”。

## 机器复核

先用 IDA 批处理导出轻量交叉引用，不需要反编译巨大的总分派函数：

```powershell
& 'D:\Develop\Tools\IDA_Pro_7.7\idat64.exe' -A `
  '-SD:\Develop\Other\turing-complete\.research\rng_sample_dfa\dump_delay_xrefs_ida.py' `
  'D:\Game\Steam\steamapps\common\Turing Complete\Turing Complete.exe.i64'
```

然后执行断言：

```powershell
.\.venv\Scripts\python.exe `
  .research\rng_sample_dfa\audit_delay_z_storage.py
```

脚本会核对 EXE 哈希、反编译结构、case 13 的固定谓词调用、普通状态槽与 Z 状态槽访问，并生成 `delay-z-storage-certificate.json`。

版本升级后若 EXE 哈希变化，必须重新导出并审计，不能直接沿用本结论。
