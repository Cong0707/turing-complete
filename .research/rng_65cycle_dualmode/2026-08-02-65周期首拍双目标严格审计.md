# RNG 65 周期首拍双目标严格审计

## 结论

对 `radius14-x56-neighbors.jsonl` 中全部 128 个 x56 状态编码、386 个完整最小 pair
cover 的严格检查结果为：

```text
候选编码              128
完整最小 pair cover   386
SAT                     0
cover 枚举截断           0
求解器未决或分歧          0
状态             unsat_complete
```

因此，这一批深度二 XOR2 编码不能在 `393 / 10 / 65` 预算内实现正确的首拍输出方案。

## 正确周期模型

关卡必须依次提交 `F(seed)` 到 `F^65(seed)`。若 Architecture Input 只在 tick 0 开启，
编码状态为 `q=T*x`，那么首拍必须同时满足：

```text
tick 0 output = A * seed
tick 0 state  = T * A * seed
```

旧的 `state=T*seed` 只适用于“tick 0 装载、tick 1 才输出”的 66 周期协议。把它直接用于
65 周期会在 tick 0 输出 `A*seed` 后，于 tick 1 再次输出同一个值。

## 成本和拓扑

本轮固定壳为：

```text
32 * Delay Bit       160 gate
ready Delay + NOT      6 gate
固定壳                166 gate
```

公开参考为 `431 * 9 * 66 = 256014`。在 10 delay、65 cycle 下必须满足
`gate <= 393`，所以组合逻辑预算为：

```text
3 * XOR2 + OR <= 227
```

XOR2 严格按 `3 gate / 2 delay` 计算。模型覆盖深度二 XOR2 DAG、完整最小 pair cover、
首拍输入 Z/OR mediation、逐引脚 seed 标签，以及反馈 `T*A*seed` 和输出 `A*seed` 两个
同时成立的目标。

## 边界

本结论不覆盖非最小 cover、三层或更深 XOR DAG、Switch-XOR3、不同状态维数以及持续读取
seed 的仿射协议。它是对指定 radius14/x56/最小-cover 拓扑族的完整反证，不是所有 65
周期电路的全局反证。

本轮没有启动游戏、没有读取或修改正式存档、没有使用 RAM。
