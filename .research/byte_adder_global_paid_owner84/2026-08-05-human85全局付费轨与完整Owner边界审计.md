# human85 全局付费轨与完整 Owner 边界审计

日期：2026-08-05

## 结论

本轮以已经实机验收的：

```text
85 gate / 6 delay / 510 energy
```

为唯一基线，对全部 `63` 个付费实例、`85` 门、六个完整 BUS owner、每条付费轨的
arrival、fanout、直接消费者与九个公开输出可达域作了统一审计。结论是：

```text
完整、可物化、通过完整 owner 账本的 84/6 候选：没有
当前完整前沿：                                 85/6/510
最高优先级缺口：             U6 部分进位 + S6/S7/C8 高尾
```

没有启动游戏，没有读取或修改正式存档，没有修改候选电路，没有运行 SAT、MaxSAT、
BDD、ABC、随机搜索或任意 DAG 大枚举。脚本只执行：

1. 权威 Factory DAG 的独立位并行物理状态重放；
2. 全图 fanout、输出可达域和 D6 反向 deadline 计算；
3. 六个 BUS 的每只 Switch driver、Z、active-zero、active-one、重叠和冲突统计；
4. 汇总已经记录的小型、有明确边界的 owner/cut 证书。

本报告不是全局 `84/6` 不可能性证明。它关闭的是下文明确列出的当前 paid endpoint、
owner normal form 和 bounded topology；下一次突破仍必须来自新的状态接口或完整 owner
重画，而不是现有节点的单门同义替换。

## 四、优先级一：`U6` 部分进位与完整高尾

当前固定切面为：

```text
K34/G345/V45/D45                         4
C6 two-Switch owner                      4
D5                                       1
nP6/K67                                  2
A6/B6/Z7                                 3
S6 final                                 1
------------------------------------------
current                                  15 gate / D6
```

使用吸收律：

```text
C6 = G5 OR U6

U6 = BUS(
  SW(enable=B23, data=V45),
  SW(enable=K34, data=V45)
)
```

可真实删除 `D45/G345` 两门。`C6` 与 `U6` 只在 `G5=1` 域不同，而
`G5=1 => P5=0`，所以：

```text
NAND(P5,C6) = NAND(P5,U6)
```

`D5/S5` 的 value、arrival、Z 和 conflict 均保持。为了让高尾直接消费 `{U6,G5}`，
最紧的公共原因树为：

```text
M  = G5 OR G6                              1 gate @2
N  = M OR Q6       = G5 OR nP6            1 gate @3
K' = M OR G7       = G5 OR K67            1 gate @3

A6 = U6 OR N                               1 gate @5
Z7 = NOR(U6,K')                            1 gate @5
```

完整新账本：

```text
K34 + V45 + U6 owner                       6
D5                                         1
M + N + K'                                 3
A6 + Z7                                    2
S6 direct D6 closure                      >=3
---------------------------------------------
best closed                              >=15 gate / D6
```

既有放宽证书甚至免费提供了原 DAG 与 U6 方案中的大量 paid rail，仍没有
`<=2 gate / D6` 的 S6 closure。小状态审计同时给出：

```text
C6 conflict rows             0
U6 conflict rows             0
C6 Z rows / 1458           324
U6 Z rows / 1458           486
```

所以 `U6` 是合法的部分进位接口，但当前完整 owner 边界只能 `15 -> 15`。下一步不应
再次显式物化 `C6=G5|U6`，而应改变 bit6/7 state leaves 或最终 S7/C8 owner，使一个
新相位同时替代：

```text
M/N/K' 中的一门，或
A6/Z7 中的一门，或
S6 三门 closure 中的一门。
```

这是全图优先级最高的结构缺口，因为它已经先取得两门真实上游收益，只差让下游少
补一门。

## 五、优先级二：拆出 C2 的 G1 driver

当前：

```text
C2 = BUS(SW(B0partial,V1),SW(G1,V1),SW(G0,V1))
cost = 6 gate / D2
```

先构造：

```text
B = BUS(SW(B0partial,V1),SW(G0,V1))       4 gate @2
B = V1*C1
```

owner 表面省两门。为了保持 `B23@3`，用：

```text
H12 = G1 OR G2                            1 gate @2

B23 = BUS(
  SW(B,   N23),
  SW(H12, N23)
)                                        4 gate @3
```

但 S1/S2/T2 仍需要完整 carry：

```text
C2full = G1 OR B                          1 gate @3
```

完整净账：

```text
current C2 owner                          6

B owner                                   4
H12                                       1
C2full                                    1
-------------------------------------------
replacement                               6
```

`B` 与新 `B23` 都是 common-data owner，重叠数据同值，conflict 为零；上述 arrival
仍可守住 S1/S2/S3 的 D6。真正的减一要求取消 `C2full` 这条 scalar ABI，同时重画
S1/S2/T2/S3。现有 bounded 证据为：

```text
fixed-C2 S1 private tail, 4 ordinary gates    UNSAT
fixed-C2 S1 private tail, 5 ordinary gates      SAT
partial {B,G1,H12} -> S2, <=3-gate/Z cover    no hit
encoded-C2 bits0:3 complete macro              29 -> 29
```

因此这个方向仍有架构价值，但不能以“删一只 G1 Switch”单独落盘。

## 六、优先级三：B23/C4 与 S2/S3

当前原子删除集合成本：

```text
BUS31                                      4
其余 14 个普通门                         14
--------------------------------------------
B23/C4/S2/S3 cut                          18
84/6 replacement ceiling                 17
```

严格输出 ABI：

```text
B23 <= D3
C4  <= D4
S2   <= D6
S3   <= D6
```

正确但无收益的 C4 owner 为：

```text
E23 = C2 OR G2                            @3
V23 = G3 OR N23                           @3

C4 = BUS(SW(E23,V23),SW(G3,V23))         @4
```

问题在于 `B23` 还有边界外消费者 `C6`。若删除 `B23` 并只保留 `C4@4`，C6 会到
D5，随后四个高位输出全部到 D7。故 `B23/N23` 仍须保留；新 C4 owner 只会增加成本。

已记录的 `133` 个 equal-cost near cut 两两合并共 `8778` 对，合法合并中没有严格
负 gate delta。这不是任意新 recipe 的全局下界，但证明继续拼接旧同分 cut 不会得到
84 门。下一步必须创造一个新的 D3 lower-carry descriptor，同时服务 C6 与至少一个
S2/S3 phase。

## 七、优先级四：最终 S5/S7 owner

现有 paid endpoint 的完整正覆盖审计结果：

```text
S5 best complete final cover     85/6，复现当前 owner
S7 best complete final cover     85/6，复现当前 owner或交换首路enable/data
strict improvement hits          0
```

当前两个跨输出共享点已经兑现：

```text
T4 -> S4 + S5 enable
A6 -> S6 + S7 data
Z7 -> C8 + S7 enable
```

把多个 lane 放入 Word Switch 不会减少门数：`Uw Switch = 2w gate / 1 delay`。相同
enable 只减少布线，不减少计分；普通 wire fanout 原本就免费。因此，除非上游重编码
先产生新的共享 data phase，否则只交换现有 S5/S7 的 enable/data 无法净省一门。

## 九、后续研究顺序

后续只保留以下顺序：

1. **U6 高尾状态重编码**：目标不是再证明 `B6` 不能由一门生成，而是改变
   `{nP6,K67,E7,H7}` 的付费编码，使 `G5` 吸收与 S6/S7/C8 的某条 reason 合并。
2. **取消 scalar C2 ABI**：将 `B/G1/H12` descriptor 直接延伸到 S1/S2/S3/B23，
   完整目标为当前 29 门 cut 到 28 门，而不是只压 C2 owner。
3. **D3 lower-carry descriptor**：一条新轨必须同时满足 B23 的 C6 消费者和 S2/S3
   的至少一个相位，才有真实死亡节点。
4. **冻结现有最终 owner endpoint 交换**：在新 state rail 出现前，不再重新扫描
   当前 S5/S7 enable/data 的排列。

任何新草图在进入全域验证前必须先列：

```text
完整删除节点和 gate
完整新增节点和 gate
每个节点 arrival
全部 BUS owner/driver partition
expected-one driven completeness
expected-zero Z/active-zero 行为
0/1 conflict
全局净账 <=84/6
```
