## 一、低位所有权重编码：删除 A12

旧结构：

```text
A12 = OR(G1,G2)                                      1 gate @2
B12 = BUS(
    SW(enable=C1,  data=N12),
    SW(enable=A12, data=N12)
)                                                     4 gate @3
```

新结构：

```text
B12' = BUS(
    SW(enable=C1, data=N12),
    SW(enable=G1, data=N12)
)                                                     4 gate @3
```

`A12` 的唯一 fanout 是 `B12`，因此替换后这只 OR 从 live cone 死亡，净省 1 门。

定义 driven enable：

```text
old enable = C1 OR G1 OR G2
new enable = C1 OR G1
```

两者只在 `G2=1,C1=0,G1=0` 的行不同。这些差异被所有四类消费者已有的独立路径吸收：

```text
C3     = OR(G2,B12)
C5/C7  另有 Apre，且 G2 => Apre
S4     低前缀另有 X23，且 G2 => X23
```

因此 `B12` 自身的 Z 分布允许改变，但最终 `C3/C5/C7/S4` 的 value/driven/conflict 保持正确。物化审计中：

```text

```

## 六、方法修正

本候选来自架构边界变化，而不是枚举：

1. 找出私有节点 `A12` 的完整消费者集合，并证明每个消费者已有吸收路径。
2. 删除整个 `V/C7` 高位表示，不再局部修补 carry spine。
3. 直接使用已付费的 `C5/A56/G/Q/P` 副产物生成 S5/S6/S7/C8。
4. 在跨输出边界复用 S7 已付的 `J7`，删除 C8 私有的 `X7`。
5. 只在需要 active scalar 的 C8 边界使用 Maker/Splitter，明确保持 `0 gate / 0 delay`。
6. 对所有 Switch owner 同时证明 value、driven、Z 与 conflict，而不是只证明布尔值。

这应作为后续研究的默认方式：先改变状态表示和输出边界，再做成本账本；不再回到旧的大样本电路空间遍历。
