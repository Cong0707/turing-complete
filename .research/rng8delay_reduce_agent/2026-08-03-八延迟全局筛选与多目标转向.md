# RNG 八延迟全局筛选与多目标转向

日期：2026-08-03

## 结论

本轮完成一次 `12,000,000` 步、单线程、低内存的全局状态基退火。搜索目标是正常
one-shot 66 周期协议，不使用 RAM、非零 Delay 初态、伪造计分或游戏引擎漏洞。

独立筛选结果为：

```text
records                 512
unique T                512
algebra failures          0
accepted                  0
structural rejects      512
timing-zero exact jobs    0
```

因此本轮**没有**可进入 `exact_all_terminal_split.py` 的候选，也没有生成、部署或提交
八延迟电路。空的 `calibrated-global-12m-timing0.jsonl` 是预期结果，不是求解器遗漏。

搜索仍提供了有用的边界：旧低门状态的最佳严格必要条件端点为
`bad_rows=0 / timing_violations=13`；单标量退火把时序冲突降至 4，但代价是产生 3 条
权重 5 行：

```text
bad_rows=3
squared_excess=3
maximum_weight=5
timing_violations=4
timing_excess=4
```

这证明原回归标量会用结构破坏交换时序改善，不能把 `strict_logic=281` 等松弛下界当成
可综合门数。

## 正确协议与必要条件

本轮沿用已复核的 66 周期 one-shot 代数：

```text
C*T = A
T*C = B
```

`A` 为 xorshift32 线性矩阵。Delay 初态为零，Architecture Input 由
`NOT(ready)` 开启，所以 seed value 到达时间为 5。在当前 depth-2
XOR2/dual-rail/Switch + terminal split 模型内，必须满足：

```text
popcount(B[i]) >= 3  =>  popcount(T[i]) <= 2
```

此外 `T/B/C` 每一行都必须非零且权重不超过 4。筛选脚本没有信任搜索器自报字段，而是
独立重算 GF(2) 矩阵乘法、行权重和上述时序条件。

## 独立筛选

```powershell
.\.venv\Scripts\python.exe `
  .research\rng8delay_reduce_agent\screen_calibrated_candidates.py `
  --source .research\rng8delay_reduce_agent\calibrated-global-12m.jsonl `
  --output .research\rng8delay_reduce_agent\calibrated-global-12m-timing0.jsonl `
  --summary .research\rng8delay_reduce_agent\calibrated-global-12m-screen.json
```

筛选顺序是 `parse -> algebra -> structure -> timing`。512 项全部先在 structure 阶段被
拒绝，所以摘要中的 `timing: 0` 表示没有记录进入该阶段，不表示它们满足时序；原始前沿
的最少时序冲突仍为 3 至 4。

由于接受数为零，严格 RC2/CNF 综合没有被调用。这样避免对已知不满足必要条件的状态浪费
内存与时间。

## 多目标转向

单标量拟合已经停止。新的 `search_feasibility_beam.cpp` 对每个前沿状态完整枚举
`32*31=992` 个初等基变换，并分别保留结构优先、时序优先和平衡前沿；每个
`(bad_rows,timing_violations)` 单元设容量上限，避免位重命名等价项占满束宽。

从退火的 `(3,4)` 前沿继续后，目前得到：

```text
结构合法端：  (0,13) -> (0,11)
平衡端：      (3,4)  -> (3,3)
桥接格点：    (2,5), (5,3), (4,2)
严格可行端：  (0,0) 尚未命中
```

这是一条新的多目标结构搜索路线，不再重复同一个回归标量。只有命中 `(0,0)` 后才会运行
严格综合；严格综合仍需证明 `logic<=291` 才可能形成 `<=457/8/66` 的正常榜一候选。
