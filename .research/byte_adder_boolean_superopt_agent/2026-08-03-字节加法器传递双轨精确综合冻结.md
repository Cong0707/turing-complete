# 字节加法器传递双轨精确综合冻结

> **2026-08-03 物理审计纠正：** 本文初版的 `10/2`、`18/3` 与 `6/1` combine
> 将同一 Switch 输出部分复用于两条独立 BUS。真实 TC 导线会把两组 BUS 合并成一个网，
> Splitter/Maker 又不能隔离 Z，因此这些结构不可物化，现已全部撤回。下文保留其发现过程
> 作为 SAT 抽象漏洞记录；当前可信前沿以新增物理 net-partition 约束后的 `12/2` 为准。

## 2026-08-03 / 研究目标

本阶段在 `U=f(0), V=f(1)` carry-transfer 双轨上研究 2--4 位连续块，并继续遵守：

```text
普通门                      1 gate / 1 delay
XOR/XNOR                    3 gate / 2 delay
Bit Switch                  2 gate / 1 delay
Switch(enable=0)            输出 Z
多驱动 BUS                  活动 0/1 冲突非法
内部 transfer 的逻辑 0      可由 Z 表示
transfer 的逻辑 1           必须主动驱动
Byte Adder 九个最终输出      不允许 Z
```

本阶段没有启动游戏，没有修改正式存档、共享候选或 Git。

## 精确模型修改

`exact_adder_block_sat.py` 新增默认关闭的 `--allow-z-false`。默认值保持旧证书的
“所有主输出均主动驱动”语义；只有 transfer 包装器开启该选项。开启后：

1. 目标为 1 的每一行仍强制至少一个活动 driver；
2. 目标为 0 的行允许 driven-0 或全 Z；
3. 任意 BUS 仍禁止同时出现活动 0 和活动 1；
4. 独立 Python 重放器分别统计非法未驱动与允许的 Z-zero。

`exact_transfer_sat.py` 将目标函数替换为 n 位区间的：

```text
U = carry_out(A + B + 0)
V = carry_out(A + B + 1)
```

`verify_transfer_certificate.py` 不调用 SAT，只读取 JSON 中的网络，以第二套 value/Z
解释器重放所有输入，并要求结果与证书内嵌验证逐字段一致。

## 已撤回结构：跨 BUS 共享高位 Generate Driver

对高、低两个 transfer 双轨 `(Uh,Vh)`、`(Ul,Vl)`，组合满足：

```text
Uout = Uh OR (Vh AND Ul)
Vout = Uh OR (Vh AND Vl)
```

初版曾按三个抽象 Switch 输出写成：

```text
shared = Switch(enable=Uh, data=1)   # 错误：同时接入两条独立 BUS
u_low  = Switch(enable=Ul, data=Vh)  # 只接 Uout
v_low  = Switch(enable=Vl, data=Vh)  # 只接 Vout
```

布尔值/Z 重放虽然不会出现 0/1 冲突，但 `shared` 的单个输出针脚接到 U、V 两条
多驱动线时，两条线在电气上已经是同一个物理网；随后只接到 U 或 V 的 driver 也会被
并入同一网。故所谓跨输出扇出不是隔离复制，下面的初版结论无效：

```text
3 Bit Switch = 6 gate / 1 delay   # 已撤回，不可物化
```

真实实现必须为 `Uh` 在 U、V 两条 BUS 各放一只独立 Switch，因此 combine 恢复为
`4 Bit Switch = 8 gate / 1 delay`。

```text
= 7 physical components
= 10 weighted gate
= 2 delay
```

## 3 位抽象反例：`18 / 3`（不可物化）

文件：`transfer3-b18-d3-c12-s6.json`

```text
6 ordinary + 6 Bit Switch
= 12 physical components
= 18 weighted gate
= 3 delay
```

SAT 用时约 `17.68 s`。独立重放结果：

```text
64 assignments
128 output checks
mismatch                  0
bus conflict              0
illegal undriven output   0
allowed Z-zero           48
replayed max depth        3
```

证书 SHA-256：

```text
cc2030895982df17532b5a80a3ac1736f7436168546cee1a4826014390993853
```

该网络同样在 U、V output bus 之间部分共享 Switch 输出，现仅保留为回归反例。
本线按两次朴素 `8/1` combine 得到 `22/3` 代数上界；对应 SAT 搜索被协调停止，尚未
形成结果文件，严格状态为 `UNKNOWN`。随后 `byte_adder_depth4_global_agent` 对旧证书中
跨输出 BUS 共享的 source 19 做了一次物理复制，以仅增加一只 Bit Switch（2 gate）的
方式得到合法 `20/3` 正向证书：

```text
.research/byte_adder_depth4_global_agent/transfer3-physical-b20-d3.json
SHA256 437e030f798026e23950a87f8a9405c0a20857a388f8fb24a7650a710be86366
64 assignments / 128 checks
mismatch=0 / conflict=0 / illegal-Z=0 / net-partition violation=0 / depth=3
```

因此 `22/3` 只是本线的朴素构造，不再是当前全局 3 位上界。

## 4 位可构造上界与未完成项

以平衡树组合四个 `2/1` 的 U/V 叶，并使用三次真实 `8/1` combine，可直接得到：

```text
8 leaf gates + 3 * 8 combine gates = 32 gate
arrival = 1 + 2 combine layers = 3 delay
```

这是代数可构造上界，但冻结前尚未导出 JSON DAG，也未执行 256 行双轨重放，因此当前
不得把 `32/3` 标成机器证书。恢复时应先生成确定性 DAG 证书，再尝试更小边界。

## 联合 `Sum + U/V` 两位宏

单独优化 transfer 会重复计算每位传播条件，因此本阶段新增
`exact_sum_transfer_sat.py` 和确定性构造器 `build_sum_transfer_macros.py`，联合接口为：

```text
inputs  = A[0..n-1], B[0..n-1], Cin
outputs = Sum[0..n-1], U=f(0), V=f(1)
```

驱动策略按输出区分：所有 `Sum` 行必须主动驱动；`U/V` 为 0 时允许全 Z，为 1 时必须
主动驱动。全部 resolved BUS 同时满足物理 net-partition，禁止部分共享 source。

已固化三份两位合法 DAG：

| 证书 | 加权门数 | 延迟 | 完整检查 | SHA-256 |
|---|---:|---:|---:|---|
| `sum-transfer-2bit-ordinary-g17-d6.json` | 17 | 6 | 32 输入 / 128 输出 | `e6f0d1b690eaa93e6ecc0d341128ef9fc24b17e25f8c2373556e83695e1b053f` |
| `sum-transfer-2bit-fast-low-g19-d5.json` | 19 | 5 | 32 输入 / 128 输出 | `23903c9005ec1ee5e8916d75b023fd1e1191be19bbd1b2a1c43ecc9d68ea07f9` |
| `sum-transfer-2bit-switch-prefix-g28-d4.json` | 28 | 4 | 32 输入 / 128 输出 | `b05f216b32687a67d29edf96ded70bf3e75d5b17c0c1d78529099b2b49ffde38` |

三份证书均由独立重放器确认：

```text
mismatch                                  0
BUS active-0/active-1 conflict            0
illegal final Z                           0
physical net-partition violation          0
deterministic builder reproduction        true
```

`28/4` 中 U、V 两条 BUS 所需的 generate driver 被物理复制，未复用同一输出针脚；这也是
它高于已撤回抽象结构的主要成本来源。

直接精确搜索两位联合 `18/5`（16 个槽、1 XOR、0 Switch）在 60 秒后返回 `UNKNOWN`：

```text
sumtransfer2-physical-b18-d5-c16-s0-x1.json
```

该文件不是 UNSAT 证书，更不是正向候选。ABC 对同一联合函数得到普通门 `18/6`，没有优于
确定性的 `17/6`。

## 一位非对称到达边界

对 `Sum deadline=4`、`Cout deadline=3` 的一位全加器，当前精确结果包括：

```text
8 gate / 6 components / 1 XOR      SAT
8 gate / 8 ordinary components     SAT
8 gate / 6 components / 2 Switch   UNSAT（固定模板）
8 gate / 7 components / 1 Switch   UNSAT（固定模板）
```

8 门 SAT 结构利用了全加器输入对称性，没有保留 A/B 的独立 G/P 轨，因此不能直接据此把
两位联合 `19/5` 算术减为 `18/5`。

## 安全 SWOR 技术映射试验

`tc_switch.genlib` 增加了只表示同 data 多驱动 BUS 的 `SWOR2/3/4`：

```text
SWORk(D,E...) = D AND OR(E...)
cost          = 2*k
delay         = 1
```

同一宏内全部 Switch 的 data 都是 `D`，所以 enable 重叠不会冲突。ABC 在该库下得到的
最好低延迟试验映射为 `89/8`，没有达到本阶段目标；这些 `abc-switch*.v` 只保留为结构
探索材料，未做完整 Z 传播证书，不能作为候选。

## 冻结结论

- 已撤回不可物化的 `6/1` combine、2 位 `10/2` 和 3 位 `18/3`。
- SAT 与独立物理网审计确认 2 位合法正向点为 `12/2`；固定 `10/2` 为 UNSAT。
- 已固化并完整重放三份合法两位联合宏：`17/6`、`19/5`、`28/4`。
- 两位联合 `18/5` 仍为 `UNKNOWN`，不得当作下界或候选。
- 3 位当前已有独立物理合法 `20/3` 正向证书；本线的 `22/3` 搜索本身仍为 `UNKNOWN`。
- 4 位 `32/3` 当前仅为代数上界，尚无本线机器证书。
- 尚未生成完整 8 位 `<=102/5` 或 `<=85/6` DAG，未触碰共享候选或正式存档。
- 下一步应把三份联合宏接入共享节点感知的全局 Sum/carry DP，并搜索 3 位联合宏；所有
  combine 只能使用真实物理网络，同时计算最终 Sum/Cout 主动驱动与全局最长路径。
