# 字节加法器布尔超优化阶段冻结

## 2026-08-03 / 阶段目标

本线只研究 Byte Adder 的布尔网表、真实元件成本和小位宽精确综合。没有启动游戏，
没有读取认证信息，没有修改 `examples/byte_adder/candidate` 或正式存档，也没有自行提交、
推送或派生子代理。

优化目标以公开前沿 `103 / 5 / 515` 为基准。若要严格降低能耗，至少要命中下列格点之一：

```text
delay 4: gate <= 128
delay 5: gate <= 102
delay 6: gate <= 85
delay 7: gate <= 73
```

本线始终使用用户确认的实际原语成本：

```text
NOT / AND / OR / NAND / NOR = 1 gate / 1 delay
XOR / XNOR                  = 3 gate / 2 delay
Bit Switch                  = 2 gate / 1 delay
```

## 整体 ABC 映射

`adder.v` 是完整的 `U8 + U8 + Cin -> U8 + Cout` 参考描述，`tc.genlib` 把普通门、
XOR/XNOR 的成本和延迟写成上述实测模型。Yosys/ABC 面积映射得到的四份网表完全相同：

```text
12 AND + 26 NAND + 14 OR + 2 XNOR
54 physical cells
58 weighted gate
18 delay
1044 energy
```

`analyze_netlist.py` 对每份网表独立执行拓扑计时，并以 Python 大整数位并行重放完整
`2^17 = 131072` 个输入。四份结果均为 `mismatch_count = 0`。

ABC 命令中的 `-D 4/5/6` 只是映射目标，不是已经满足该延迟的证书。本地计时器确认
`mapped-d4.v`、`mapped-d5.v`、`mapped-d6.v` 仍全部是 `58 / 18`，因此不能把综合器日志
中的目标值误报成可写入游戏的低延迟候选。

这个结果不优于已知普通门串行前沿 `56 / 18`。已知每位 `7 / 4` 全加器为：

```text
ab0   = NOR(a,b)
ab1   = AND(a,b)
p     = NOR(ab0,ab1)
pc0   = NOR(p,c)
pc1   = AND(p,c)
sum   = NOR(pc0,pc1)
carry = OR(ab1,pc1)
```

八级串联正好得到 `56 / 18`，与公开低门前沿相符。这说明成本和拓扑计时模型可用，
但通用 ABC 映射没有利用足够的多输出共享。


## 小位宽 Switch/Z 精确模型

`exact_adder_block_sat.py` 新增了独立的有界 CNF 综合器。它复用仓库中已经审计的普通门
和 Switch 位级编码，但针对 Byte Adder 修正了三个边界：

1. 输入源只有原始输入和免费常量 0/1，输入反相信号不免费；
2. 多驱动 BUS 在每个赋值下禁止同时出现有效 0 和有效 1；
3. 每个主输出在每个赋值下必须至少有一个有效驱动，不能把全 Z 当成输出 0。

普通门读取全 Z 数据面的数值 0；Bit Switch 在 `enable=0` 时输出 Z，在 `enable=1` 时
输出 data。SAT 见证写出后由第二套 Python 重放器重新检查完整真值表、BUS 冲突、输出 Z
和实际拓扑深度。

### 一位校准

已完成三个固定槽位边界：

| 证书 | 槽位 | 门上限 | 延迟上限 | 结果 |
|---|---:|---:|---:|---|
| `fa-b7-d4-c7.json` | 7 | 7 | 4 | SAT，完整 8 输入通过 |
| `fa-b6-d4-c6.json` | 6 | 6 | 4 | UNSAT |
| `fa-b7-d3-c7.json` | 7 | 7 | 3 | UNSAT |

这里的两个 UNSAT 只对表中固定槽位数量和模型成立；本轮没有逐一封闭更少槽位，不能把它们
单独扩张成无条件全局下界。`7 / 4` 正向见证与已知全加器一致，校准通过。

### 二位正向见证

已得到两份完整重放通过的二位多输出见证：

| 证书 | 元件槽位 | 加权门数 | 延迟 | Switch | 验证 |
|---|---:|---:|---:|---:|---|
| `add2-b14-d6-c14.json` | 14 | 14 | 6 | 0 | `32 * 3` 输出检查全通过 |
| `add2-b25-d5-c16.json` | 16 | 25 | 5 | 1 | `32 * 3` 输出检查全通过 |

第一份是普通门二位链的独立重综合；第二份与公开二位 `25 / 5` 宏的计分点一致，但 SAT
找到的是另一份含一只 Switch 的合法布尔网络。两者都没有生成 v15 电路，不能直接验收。

本线随后启动了更紧的 `15 gate / 5 delay / 15 slots` 与
`16 gate / 5 delay / 16 slots` 搜索。主任务要求立即归档时，两项仍未返回 SAT/UNSAT，
求解进程已全部终止，也没有写出结果文件。它们的严格状态是 `UNKNOWN`，不得依据运行时长
推断不可满足。

### 二位 `16 / 5` 手工构型

通用 SAT 尚未在限时内给出 `16 / 5` 见证，但已得到一个可直接代数复验的 14 元件、
16 加权门、5 延迟构型。低位先生成快速进位：

```text
o0  = OR(a0,b0)          # d1
ng0 = NAND(a0,b0)        # d1
p0  = AND(o0,ng0)        # d2，a0 XOR b0
g0  = NOT(ng0)           # d2，a0 AND b0
h0  = AND(o0,cin)        # d2
c1  = OR(g0,h0)          # d3
s0  = XOR(p0,cin)        # d4，成本 3
```

高位接已验证的普通门 `7 / 4` 全加器；其局部传播项在 d2 到达，`c1` 在 d3 到达，
所以 `s1` 与 `cout` 均在 d5 到达。低位加权成本 `9`，高位成本 `7`，合计 `16 / 5`。
它是明确的正向上界，但本轮尚未导出为 v15 电路或 SAT JSON，因此不能把它写成已实机验收结果。

### Carry transfer 继续入口

下一阶段不应恢复高内存的任意真值表枚举，而应只枚举合法连续区间的三态传递函数。
对一位定义 one-hot 状态 `K/P/G`，其中：

```text
G = AND(a,b)             # generate
K = NOR(a,b)             # kill
P = NOR(G,K)             # propagate
```

等价双轨端点为 `(g,h)=(f(0),f(1))` 且恒有 `g <= h`。高块 H 与低块 L 的普通组合为：

```text
P = P_H AND P_L
G = G_H OR (P_H AND G_L)
K = K_H OR (P_H AND K_L)
```

应为每个 2/3/4 位连续区间保存 `G/P/K`（或 `(g,h)`）各轨到达时间、加权门数、
结构哈希和来源，并做共享节点感知的全局 8 位 DP。若 sum 仍用 XOR `3 / 2`，各 carry
必须在 d4 前到达；若用双轨加 Switch 选择 sum，则必须把 Switch、相位修复和最终非 Z
约束完整计入，不能把关闭态或免费反相当作输出。

## 原生成本公式逆向

只读 IDA 导出了下列成本函数及初始化路径：

```text
get_gate_cost__modelZscores_u2232
get_delay_cost__modelZscores_u2270
get_gate_cost__modelZscores_u2304
get_delay_cost__modelZscores_u2316
```

对 kind 30 `Add`，若当前动态 U8 基准为 `(G,D)`，位宽 `w <= 8` 的分档为：

```text
gate(w)  = ceil(G*w/8)
delay(w) = max(D, 4, ceil(D*w/8))
```

例如条件性地代入当前候选头部 `103/5`，U1..U8 的门数会是：

```text
13, 26, 39, 52, 65, 78, 91, 103
```

延迟均为 5。这个公式说明窄位原生元件可以成为混合构型的研究对象，但 `103/5` 是否是
运行时动态表中 kind 30 的权威基准，仍须沿 `import_costs/get_cost` 继续追踪；不能只凭候选
头部反推。

安装包默认回退表还包含 `XOR 4/3`、`Switch 2/1`、`FullAdder 8/4`、`Add U8 100/50`。
这些是未导入动态成绩时的回退值，不是用户当前实测成本。本线所有综合仍以 XOR/XNOR
`3/2` 为准。

## 冻结结论与继续点

- 已建立能复现普通门/XOR/Switch-Z 的小块精确综合器，并强制最终输出非 Z。
- 已完整验真 `1-bit 7/4`、`2-bit 14/6`、`2-bit 25/5` 正向见证。
- 已得到可代数复验的 `2-bit 16/5` 手工结构上界；尚未生成游戏电路或 SAT JSON。
- 尚未得到严格优于 `103/5/515` 的八位候选，没有修改共享候选或正式存档。
- `2-bit <=16/5` 的紧边界仍为 `UNKNOWN`，3/4 位块尚未启动，不能声称已完成块前沿。
- 下一次应固化 `16/5` 结构证书，并直接做连续区间 carry-transfer DP；对 Switch BUS 必须
  继续保留全赋值冲突约束与主输出有效驱动约束。

冻结前再次用 `exact_adder_block_sat.py` 的独立重放器读取三份 SAT JSON，结果为：

```text

```

三份均为 `mismatch=0`、`bus_conflict=0`、`undriven_output=0`。两份 UNSAT JSON 状态仍为
`unsat`。冻结时没有本线求解进程在后台运行。
