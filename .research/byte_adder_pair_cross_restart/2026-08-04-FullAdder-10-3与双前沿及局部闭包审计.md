# FullAdder 10/3、双前沿与 bit0 局部 connected-cut 审计

日期：2026-08-04

## 结论

本检查点得到四类彼此边界清晰的结果：

| 目标 | 结果 | 证明强度 |
|---|---:|---|
| FullAdder `delay<=1` | 不可达 | 完整结构枚举证书 |
| FullAdder `delay<=2` | `17/2` 可行 | 严格物理 SAT witness + 独立 replay；**尚未证明 gate 最小** |
| FullAdder `delay<=3` | `10/3` | 严格物理 witness，且 `gate<=9` 的 90 个完整分片全 UNSAT |
| FullAdder 已有低门点 | `7/4` | 既有独立物理验收 |
| 权威 `80/7` bit0 的 `(S0,C1)` 非对称切口 | `gate<=9` 不可替换 | `S0<=4/C1<=2` 的 45 个严格物理分片全 UNSAT；**仅为局部 cut 下界** |

因此 FullAdder 当前已严格确认的 client Pareto 行至少保留：

```text
(7,4)
(10,3)
```

`17/2` 是新的低延迟可行上界；在 `gate<=16,delay<=2` 尚未做完整 composition
闭包前，不把它标成最小点或正式 Pareto 最小行。

## `10/3` 逻辑与物理结构

令 `A=Input 0`、`B=Input 1`、`C=Input 2`：

```text
V     = OR(A,C)
N     = NAND(A,C)
Q     = NAND(V,N)          # XNOR(A,C)
P     = AND(V,N)           # XOR(A,C)
SQ    = SWITCH(enable=Q,data=B)
R     = NAND(B,V)
SP    = SWITCH(enable=P,data=R)
CARRY = NAND(N,R)
SUM   = BUS(SQ,SP)
```

账本为 6 个 ordinary gate 加 2 个 Switch：

```text
weighted gate = 6 + 2*2 = 10
delay         = 3
energy        = 30
normalizer    = 0
```

关键 masks：

```text
A=aa B=cc C=f0
V=fa N=5f Q=a5 P=5a R=37
SQ: driven=a5 one=84 Z=5a
SP: driven=5a one=12 Z=a5
SUM: value=96 driven=ff conflict=00
CARRY: value=e8 driven=ff conflict=00
```

`Q/P` 互斥且完备，两个 Switch 输出属于同一个 resolved physical net；因此 Sum
的 driver overlap 为 `00`、complete mask 为 `ff`，无需 Maker/Splitter normalizer。

Factory DAG 的付费节点为：

```text
id  op    args       arrival  role
3   OR    0,2        1        V
4   NAND  0,2        1        N
5   NAND  3,4        2        Q
6   AND   3,4        2        P
7   NAND  1,3        2        R
8   BUS   5,1,6,7    3        SUM, owner=sum_bus
9   NAND  4,7        3        CARRY
```

物化候选包含 13 个实体组件、19 条线和 10 个逻辑网络；其中一个真实网络有 2 个
tri-state driver。独立证书从真实 pin endpoint 重建网络，得到 `10/3/30`，8 行 16 个
输出检查全对，mismatch/conflict/undriven、死门、几何、连通性问题均为零，v15
roundtrip byte-identical，且没有 native FullAdder 或 native Add。

## `D3` gate 最小闭包

冻结求解器在以下完整模型中枚举了 `gate<=9,delay<=3`：

- strict fully-driven 与 target-zero-may-be-Z 两种 primary-output policy；
- paid component count `1..9`；
- exact normalizer count `0..4`；
- ordinary gate、XOR、Switch、BUS value/driven/conflict；
- Maker/Splitter `Z -> numeric 0 -> driven`；
- physical driver sets 必须形成 wire-net partition；
- multi-driver `0/1` conflict 禁止。

总计 `2*9*5=90` 个分片，最终为：

```text
UNSAT  = 90
SAT    = 0
unknown= 0
failure= 0
```

normalizer 上界 `4` 是完备上界：每个有用 normalizer 至少消费一个独立 raw
Switch-output net，而每个 Switch 成本为 2；`gate<=9` 最多允许
`floor(9/2)=4` 个这种独立网络。独立清单审计重新计算 90 案笛卡尔积、每案参数与 SHA、
物理语义和状态。因此 `10/3` 是当前 reviewed physical library 中严格确认的 D3 gate
最小点。

## 双前沿与实例选择

`7/4` 与 `10/3` 互不支配：

```text
7 < 10
4 > 3
```

无论先验收哪一行，client component frontier 都保持：

```text
[(7,4), (10,3)]
```

saved-level 第三指标同为 1 时同样保持：

```text
[(7,4,1), (10,3,1)]
```

实例选择必须原子地选择同一 frontier row：

```text
cost_gate=-1, cost_delay=0   -> minimum gate  -> 7/4
cost_gate=0,  cost_delay=-1  -> minimum delay -> 10/3
cost_gate=7,  cost_delay=4   -> exact 7/4
cost_gate=10, cost_delay=3   -> exact 10/3
```

`get_cost` 从同一行同时取 gate 与 delay；单个实例不能把两行拼成不存在的 `7/3`。
不同实例可以分别选不同的完整行。Builder 若要使用低延迟 kind15，必须显式选择
`(10,3)` 或 minimum-delay sentinel `(0,-1)`；默认 `(-1,0)` 仍选择 `7/4`。

## 任意 truth tuple wrapper 正回归

新增的 hash-separated wrapper 不修改冻结 FullAdder 闭包求解器，而是在独立模块中提供：

- 任意 `input_count`；
- 任意数量 truth masks 与 output names；
- 每个输出独立 arrival bound；
- Switch/BUS value、driven、conflict；
- Maker/Splitter normalization；
- exact normalizer/Switch/XOR counts；
- physical net partition 与解码后的 owner manifest。

用 `(SUM=0x96,MAJ=0xe8)`、arrival `[3,3]`、gate 10、8 个 paid component、0 个
normalizer 回归时，wrapper 在 4.754 秒重新找到 `10/3` 网络。独立 replay 字段为：

```text
mismatch/conflict/undriven/partition = 0/0/0/0
replayed output arrivals             = [3,3]
actual gate                           = 10
Sum owner                             = physical_net_owner_007
Sum driver sources                    = [9,11]
Carry owner                           = physical_net_owner_009
```

## bit0 非对称 connected-cut

权威 `80/7` DAG 中 bit0 connected cut 的成本为 10，但输出时序不对称：

```text
S0 node49 arrival 4
C1 node45 arrival 2
```

所以统一 `10/3` FullAdder 不能直接替换该 cut。新的任意双输出 exact 闭包固定：

```text
inputs                 = 3
truth tuple            = (0x96,0xe8)
S0 max arrival         = 4
C1 max arrival         = 2
gate bound             = 9
primary-output policy  = strict fully driven
paid components        = 1..9
exact normalizers      = 0..4
physical nets          = enabled
```

45 个分片最终全部 UNSAT：

```text
UNSAT  = 45
SAT    = 0
unknown= 0
failure= 0
min/median/max solve seconds = 0.0047 / 0.5433 / 96.7941
```

独立审计重新枚举 45 案笛卡尔积、检查每个 artifact SHA、truth tuple、逐输出 arrival、
strict policy、normalizer normal form、Switch/BUS 冲突和 physical driver-set partition。

该结果只封闭这个具名的二输出 connected cut。它不排除通过其它 tuple、cofactor、正反相、
partial-driver network、跨位共享或内部 byproduct 达到 `79/7`，也不是完整 Byte Adder 的
全局一门下界。

## `D1` 完整结构不可达

`delay<=1` 时：

- ordinary gate 只能读取 raw inputs/constants；
- Switch enable/data 也只能读取 raw inputs/constants；
- XOR 原语 delay 为 2，不能成为 live D1 输出；
- zero-delay Maker/Splitter 可以 normalize 一个 D1 Switch BUS，因此 direct BUS 和
  normalized BUS 两种输出形态都必须检查。

独立枚举得到：

```text
raw sources                         = 5
ordinary gate instances            = 65
distinct ordinary truth masks      = 20
raw Switch enable/data pairs       = 25
Sum mask                            = 96
raw/ordinary Sum hits              = 0/0
Sum-compatible Switch pairs        = 5
compatible pairs covered Sum-1 rows= 00
uncovered Sum-1 rows               = 96
```

5 个 compatible pair 都是 `enable=constant 0`，不能覆盖任何 Sum=1 行。任何在 enable
行给出错误值的 driver 都不能靠另一 driver 修复：否则产生 output mismatch 或禁止的
0/1 conflict。因此 direct strict BUS 与 Maker/Splitter-normalized BUS 都无法产生三输入
parity，FullAdder 在 D1 不可达；无需再分析 Carry。

## `17/2` 严格物理上界

令 `A/B/C` 为三个输入，构造：

```text
nAB = NOR(A,B)
nAC = NOR(A,C)
nBC = NOR(B,C)

X   = SWITCH(enable=A,data=C)
Y   = SWITCH(enable=B,data=C)
M   = BUS(X,Y)                       # partial physical net
U   = NORMALIZE(M)                   # C AND (A OR B), fully driven
G   = AND(A,B)

D0  = SWITCH(enable=nBC,data=A)
D1  = SWITCH(enable=nAB,data=C)
D2  = SWITCH(enable=nAC,data=B)
D3  = SWITCH(enable=M,data=G)

SUM   = NORMALIZE(BUS(D0,D1,D2,D3))
CARRY = OR(U,G)
```

成本与时序：

```text
ordinary   = 5
Switch     = 6 * 2
normalizer = 2 * 0
gate       = 17
SUM/Carry arrival = 2/2
```

独立审计不导入 SAT/CNF helper，从解码网络重建 8 行 masks、BUS value/driven/conflict、
Maker/Splitter、成本、arrival、liveness 和 owner partition，得到：

```text
mismatch/conflict/undriven           = 0/0/0
physical partition violation         = 0
dead component                       = 0
normalizer normal-form violation     = 0
Sum partial BUS owner                = physical_net_owner_006
Sum output owner                     = physical_net_owner_011
Carry output owner                   = physical_net_owner_010
Maker/Splitter owners                = maker_splitter_slot_6, maker_splitter_slot_12
```

对 `gate=16` 已做六个最接近该 witness 的 exact composition 诊断，均为 UNSAT：

```text
o8+s4+n2
o6+s5+n1  o6+s5+n2
o4+s6+n1  o4+s6+n2
o2+s7+n2
```

这六案不是 `gate<=16` 的完整 composition 覆盖，所以不能据此宣称 `17/2` 最小。另需
注意 `o4+s6+n2` 的 payload 写有 300 秒内部 timeout，但 CaDiCaL 的 PySAT interrupt
在 timer thread 中不受支持；该案最终在 344.347 秒自然返回 UNSAT。其 UNSAT 状态仍是
完成求解结果，但“300 秒硬超时”字段不能作为证据使用。bit0 45 案和 D3 90 案均在各自
外层 subprocess 上限内自然完成，不受这项诊断限制影响。
