# Switch 154/4 人工前沿样本反解

日期：2026-08-05

## 结论

用户提供的 `Switch 154 4/circuit.data` 是一份完整、可重算的 8 位加法器：

```text
gate                 154
delay                4
energy               616
truth rows           131072
sum mismatch         0 / 8 bits
carry mismatch       0
BUS conflict rows    0
```

它的核心不是普通 CLA，而是四层 conditional-sum / carry-state 电路：

1. 用 `G/K/H/P` 位状态并行计算多个“假设低位 carry 为 0/1”的 cofactor。
2. 用 Bit Switch 的 Z 输出构造正相 carry descriptor 和 phase cover。
3. 最后一层 Switch 只负责按较低位 carry phase 选择已经算好的结果。
4. `S3`、`S4`、`C8` 在逻辑 0 的部分行保持 Z，再由免费 Maker/Splitter 边界按 0 读取。

该样本提供了有价值的架构证据，但**没有直接给当前 84/6 带来一门替换**。最关键的固定检查结果是：

```text
154/4 的 S0..S3 活锥             41 gate / D4
目标接口                         nC4 @ D3
现有 <=D3 descriptor 等价项      0
现有 <=D2 信号加一只普通门        0
全样本任意 <=D2 信号加一只普通门  0
```

因此不能把它直接拼成已知的：

```text
42 gate low front + 21 gate middle + 20 gate high = 83 / 6
```

## 输入输出识别

v15 端口由组件 ABI、标签、位宽和连接共同确认：

| 组件 | 标签 | 位宽 | 位置 | 方向 |
|---:|---|---:|---|---|
| 113 | `A` | 8 | `(-52,-53)` | input |
| 114 | `B` | 8 | `(-43,-53)` | input |
| 112 | `Carry in` | 1 | `(-30,-52)` | input |
| 111 | `Output` | 8 | `(21,-53)` | output |
| 115 | `Carry out` | 1 | `(29,53)` | output |

`A` 和 `B` 分别进入组件 19、18 的免费 8 位 Splitter。八个 sum 位进入组件 20 的免费 Maker。

`Carry out` 使用一个额外的免费边界：

```text
C8 descriptor -> maker_2.in1
maker_2.in0    -> unconnected
splitter_2.out1 -> Carry out
splitter_2.out0 -> unconnected
```

这不是门或延迟来源；它把 C8 descriptor 的 Z/0 边界稳定地投影成 1 位逻辑输出。

## 记号

对第 `i` 位定义：

```text
Gi  = Ai * Bi                    generate
Ki  = NOT(Ai OR Bi)              kill
Hi  = Ai OR Bi                   non-kill
Pi  = Ai XOR Bi                  propagate
nPi = Gi OR Ki                   equal / non-propagate

C0  = Cin
C{i+1} = Gi OR Pi*Ci
Si  = Pi XOR Ci
```

`BUS(SW(e0,d0),...)` 表示多个 Bit Switch 共用一个三态网络。

对普通门、Maker 和 Splitter，Z 被读成逻辑 0；active-0 与 active-1 同时出现仍是非法冲突。

## 低四位逻辑 DAG

### bit 0

```text
X0 = BUS(
  SW(B0,C0),
  SW(A0,C0)
)                                      @1, 4 gate

H0 = A0 OR B0                          @1, 1 gate
G0 = A0 AND B0                         @1, 1 gate
C1 = G0 OR X0                          @2, 1 gate
N0 = NOR(H0,C0)                        @2, 1 gate
J0 = G0 AND C0                         @2, 1 gate
Y0 = NOR(C1,N0)                        @3, 1 gate
S0 = Y0 OR J0                          @4, 1 gate
```

`X0` 的 one-mask 是 `H0*C0`，driven-mask 是 `H0`；`K0` 行保持 Z。

`S0` 完整活锥为 `11 gate / D4`。

### bit 1 和 C2

```text
K1  = NOR(A1,B1)                       @1
G1  = A1 AND B1                        @1
P1  = NOR(K1,G1)                       @2

A1s = P1 AND C1                        @3
B1s = NOR(P1,C1)                       @3
S1  = NOR(A1s,B1s)                     @4

H1 = A1 OR B1                          @1
C2 = BUS(
  SW(G1,H1),
  SW(G0,H1),
  SW(X0,H1)
)                                      @2, 6 gate
```

`C2` 的 active-one 真值严格等于 carry `C2`，但 false 行并不全部 active-0：

```text
one rows          65536
active-zero rows  16384
Z rows            49152
```

### bit 2

```text
K2 = NOR(A2,B2)                        @1
G2 = A2 AND B2                         @1
P2 = NOR(K2,G2)                        @2

E2 = C2 OR P2                          @3
F2 = NAND(C2,P2)                       @3
S2 = E2 AND F2                         @4
```

这是 `OR + NAND + AND` 的三门 XOR 后处理，`F2` 还被下一位复用。

### bit 3 的直接 one-cover

```text
K3  = NOR(A3,B3)                       @1
G3  = A3 AND B3                        @1
nP3 = K3 OR G3                         @2

L3  = NOR(nP3,G2)
    = P3*nG2                           @3

T2  = P2*C2                            @3
F2  = NAND(P2,C2)                      @3, 已由 S2 支付

S3 = BUS(
  SW(L3,F2),
  SW(G2,nP3),
  SW(T2,nP3)
)                                      @4, 6 gate
```

解释：

- `C3=1` 的 `G2` 或 `P2*C2` 行选择 `nP3`。
- `C3=0` 且 `P3=1` 的行由 `L3*F2` 驱动 1。
- `C3=0` 且 `P3=0` 的零结果可以保持 Z。

`S3` 的统计是：

```text
one rows          65536
active-zero rows  32768
Z rows            32768
conflict rows     0
```

`S0..S3` 的联合活锥为：

```text
41 gate / D4
```

## 中间 carry-state DAG

样本不直接形成 C4，而是从 bit2/3 原始输入形成一个宽松的区间状态：

```text
RA = BUS(
  SW(A2,A3),
  SW(B2,A3),
  SW(B3,A3)
)                                      @1, 6 gate

RB = BUS(
  SW(A2,B3),
  SW(B2,B3)
)                                      @1, 4 gate

U23  = G3 OR H3*H2
nU23 = NOR(RA,RB)                      @2, 1 gate
```

`RA` 和 `RB` 的 one-mask 之 OR 严格等于 `U23`。它不是 C4，也不是 nC4；它故意把 bit2 的 `G/P` 状态合并成 `H2`，后面再由 C2/G2/G3 phase 修正。

bit4 的预计算：

```text
G4 = A4 AND B4                         @1
K4 = NOR(A4,B4)                        @1
H4 = A4 OR B4                          @1
P4 = NOR(G4,K4)                        @2

R234 = BUS(
  SW(G2,1),
  SW(G3,1),
  SW(G4,1)
)                                      @2, 6 gate

R234.one    = G2 OR G3 OR G4
R234.driven = G2 OR G3 OR G4

W4 = BUS(
  SW(RA,H4),
  SW(RB,H4),
  SW(G4,H4)
)                                      @2, 6 gate

W4.one    = H4*(G4 OR U23)
W4.driven = G4 OR U23
```

由此形成 C5 的正相 descriptor：

```text
C5d = BUS(
  SW(C2,W4),
  SW(R234,W4)
)                                      @3, 4 gate

C5d.one    = C5
C5d.driven = C2 OR G2 OR G3 OR G4
```

同时不物化单独的 nC5，而是保留两个 reason：

```text
N50 = NOR(C2,R234)
    = NOT(C2 OR G2 OR G3 OR G4)        @3, 1 gate

N51 = NOT(W4)
    = NOT(H4*(G4 OR U23))              @3, 1 gate

N50 OR N51 = nC5                       完整真值成立
```

这里的 `OR` 只是语义 cover，不需要真的放 OR 门；下游可用两只同 data Switch 分别消费 `N50`、`N51`。

这是样本最重要、也最可迁移的 ABI：

```text
positive carry descriptor + multiple negative phase reasons
```

## S4 与 S5

S4 使用 `nU23`、`R234` 和低位 phase 直接形成 one-cover：

```text
E4 = NOR(P4,nU23)                      @3
L4 = C2 OR G2 OR G3                    @3, 2 gate

S4 = BUS(
  SW(nU23,P4),
  SW(E4,L4),
  SW(N50,P4)
)                                      @4, 6 gate
```

S4 同样允许逻辑 0 行为 Z：

```text
one rows          65536
active-zero rows  32768
Z rows            32768
```

bit5 的基础状态：

```text
G5  = A5 AND B5
K5  = NOR(A5,B5)
H5  = A5 OR B5
nG5 = NAND(A5,B5)
P5  = NOR(G5,K5)
nP5 = G5 OR K5
```

S5 直接消费 C5 的正负 phase：

```text
S5 = BUS(
  SW(N50,P5),
  SW(N51,P5),
  SW(C5d,nP5)
)                                      @4, 6 gate
```

注意：该 selector 本身需要 3 只 Switch，即 6 gate。当前 84/6 的 Patchouli S5 是 5 gate，因此该局部结构按门数直接迁移会**增加 1 门**。

## Conditional-sum 高位架构

### S6 的两个 cofactor

在 `C5=0` 时：

```text
C6 = G5
F60 = P6 XOR G5

F60 = BUS(
  SW(nG5,P6),
  SW(G5,nP6)
)                                      @3, 4 switch-gate
```

在 `C5=1` 时：

```text
C6 = H5
F61 = P6 XOR H5

F61 = BUS(
  SW(K5,P6),
  SW(H5,nP6)
)                                      @3, 4 switch-gate
```

最终选择：

```text
S6 = BUS(
  SW(N50,F60),
  SW(N51,F60),
  SW(C5d,F61)
)                                      @4, 6 gate
```

如果位状态都已支付，两个 cofactor 加最终 selector 仍需：

```text
4 + 4 + 6 = 14 gate
```

它换取的是 D4，而不是低门数。当前 84/6 已知 S6 只需要 3 个普通门到 D6，所以不能直接替换。

### S7 的两个 cofactor

先定义 C5 两个 phase 下的 C7：

```text
C70 = G6 OR P6*G5
C71 = G6 OR P6*H5

F70 = P7 XOR C70
F71 = P7 XOR C71
```

样本用四个 helper 形成 bit5/6 联合状态：

```text
E0 = G5*H6   = NOR(nG5,K6)             @2
F0 = H5*H6   = NOR(K5,K6)              @2
E1 = nG5*nG6 = NOR(G5,G6)              @2
F1 = K5*nG6  = NOR(H5,G6)              @2
```

然后：

```text
F70 = BUS(
  SW(G6,nP7),
  SW(K6,P7),
  SW(E1,P7),
  SW(E0,nP7)
)                                      @3, 8 gate

F71 = BUS(
  SW(F0,nP7),
  SW(K6,P7),
  SW(G6,nP7),
  SW(F1,P7)
)                                      @3, 8 gate

S7 = BUS(
  SW(N50,F70),
  SW(N51,F70),
  SW(C5d,F71)
)                                      @4, 6 gate
```

这是一棵标准 conditional-sum tree 的游戏化版本。它高度并行，但门数显著高于当前 84/6 高尾。

### C8 的正相 owner

定义：

```text
R0 = G6 OR G7 OR G5*H6                 @3
W8 = H7*(G6 OR G7 OR H5*H6)            @3 descriptor
```

样本实际实现：

```text
R67 = G6 OR G7                         @2
R0  = E0 OR R67                        @3

W8 = BUS(
  SW(R67,H7),
  SW(F0,H7)
)                                      @3, 4 gate

C8 = BUS(
  SW(R0,W8),
  SW(C5d,W8)
)                                      @4, 4 gate
```

完整真值验证：

```text
C8.one    = arithmetic carry-out
C8.driven = R0 OR C5
C8 Z rows = 30720
conflict  = 0
```

这说明输出不要求生成完整的 active-zero cover。只要 positive descriptor 的 one-mask 等于 C8，false 行可以是 active-0 或 Z，再由免费输出边界读取为 0。

## Switch 与 Z 审计

49 只 Switch 组成 18 个多驱动 BUS。所有 BUS 的 active-0/active-1 冲突均为 0。

|---:|---|---:|---:|---:|---:|
| 24 | `H0*Cin` descriptor | 1 | 49152 | 49152 | 32768 |
| 57 | `C2` descriptor | 2 | 65536 | 16384 | 49152 |
| 121 | `S3` | 4 | 65536 | 32768 | 32768 |
| 125 | `S4` | 4 | 65536 | 32768 | 32768 |
| 154 | `G2|G3|G4` positive reasons | 2 | 75776 | 0 | 55296 |
| 156 | `W4` | 2 | 73728 | 20480 | 36864 |
| 196 | `C5` descriptor | 3 | 65536 | 37888 | 27648 |
| 200 | `F60` | 3 | 65536 | 65536 | 0 |
| 197 | `F61` | 3 | 65536 | 65536 | 0 |
| 346 | `F70` | 3 | 65536 | 65536 | 0 |

| 349 | `W8` | 3 | 73728 | 20480 | 36864 |

可复用的安全模式是：

```text
1. 同一个 BUS 的多个 Switch 尽量使用同 data；
2. controls 可以重叠，因为重叠时驱动值相同；
3. 正相 reason 用 data=1，可只产生 active-1/Z；
4. 下游普通门把 Z 读成 0；
5. 任意 active-0 与 active-1 重叠仍必须判冲突。
```

## 跨输出共享

样本的共享不是“一个完整 carry 同时喂所有输出”，而是共享 phase 和 cofactor：

| 共享信号 | 消费者 |
|---|---|
| `X0` | `C1`、`C2` |
| `C2` | `S2`、`S3`、`S4`、`C5` phase |
| `F2=NAND(P2,C2)` | `S2`、`S3` |
| `RA/RB` | `nU23`、`W4` |
| `R234` | `N50`、`C5d` |
| `W4` | `N51`、`C5d` |
| `N50/N51/C5d` | `S5`、`S6`、`S7`、`C8` |
| `E0=G5H6` | `F70`、`R0` |
| `F0=H5H6` | `F71`、`W8` |
| `W8` | C8 最终两只 Switch 的公共 data |

最重要的结构性认识是：**phase reason 的扇出比完整 carry 的扇出更有价值**。负相可以是多个 cover，不必先 OR 成一根完整 nC 线。

## 41 门低闭包与 nC4 合同

现有 83/6 路线要求：

```text
low front   42 gate，发布 nC4@3
middle      21 gate
high        20 gate
```

该人工样本的低四位具有诱人的 `41 gate / D4`，因此进行了三层固定审计。

### 1. 现有 descriptor

对 41 门闭包所有标量输出网络，枚举 `arrival<=3` 的：

```text
active-one truth
active-zero truth
driven mask
Z mask
```

共得到 41 个 descriptor，没有一个在“Z 读 0”语义下等于 nC4。

距离最近的是：

```text
root 86 = K3 @1
全 17 输入 truth distance = 32768 / 131072
投影到 9 个低位输入      = 128 / 512
```

这不是一个小修补距离；它缺少整个 `P3*nC3` 区域。

### 2. 闭包内新增一门

对 41 门闭包全部 `arrival<=2` 标量网络，固定检查：

```text
NOT(x)
AND(x,y)
OR(x,y)
NAND(x,y)
NOR(x,y)
```

命中数为 0。

### 3. 全 154/4 样本复用

把候选输入扩展到该样本所有 `arrival<=2` 标量网络，仍然没有任何一门组合得到 nC4。

这封闭了“41 门 sum 闭包只补一门 nC4”的直接移植路线。

## 为什么 care-domain 不能放宽

21 门负相中段的 nC4 被三个位置观察：

```text
S4  = XNOR(P4,nC4)
U   = NAND(nC4,P4)
nC6 = BUS(SW(K45,1),SW(P45,nC4))
```

对低位输入投影后，care-domain 仍是全部 `2^9=512` 行：

1. XNOR 对 nC4 是双射；P4 取 0 或 1 都能观察 nC4 的翻转。
2. `P4=1` 对每一个低位输入都存在，因为 bit4 与低四位独立。
3. `P45=1` 对每一个低位输入都存在，因为 bits4:5 与低四位独立。

因此允许的唯一放宽是：

```text
nC4=0 的行可以 active-0 或 Z
nC4=1 的行必须 active-1
不得有 conflict
```

现有 41 个 descriptor 连这个 Z-aware 条件也没有满足。

## 对 84/6 的迁移判断

### 可以迁移的机制

1. **正相 descriptor + 多负相 reason cover**

   不物化 nC，可以让多个同 data Switch 分别消费负相 reasons。21 门负相中段已经体现了这一原则，样本给出了更大规模的实证。

2. **conditional cofactor 预计算**

   如果 carry phase 到得晚，而下一位的局部 `G/K/H/P` 到得早，可以同时计算 `F0/F1`，最后只做一层 Switch 选择。

3. **输出 Z/0 合同**

   carry-out 只需发布正确的 positive one-cover；false 行不必恢复成完整 active-zero。未来若出现现成的正相 carry reason，应该直接接免费 Maker/Splitter，而不是额外 NOT/OR 恢复。

4. **跨输出共享 phase，不共享完整 carry**

   `N50/N51/C5d` 同时控制 S5、S6、S7、C8，比先合成 C5/nC5 再分别 XOR 更适合 Switch 成本模型。

### 不能直接迁移的子结构

| 子结构 | 样本局部成本 | 当前 84/6 对应 | 判断 |
|---|---:|---:|---|
| S5 phase selector | 6 gate | Patchouli S5 5 gate | 增加 1 门 |
| S6 两 cofactor + selector | 14 gate，不含位状态 | 现有 S6 3 gate | 只降深度，大幅增门 |
| S7 两 cofactor + selector | 至少 22 gate，不含全部叶子 | 现有高尾共享结构 | 大幅增门 |
| C8 两级正相 owner | 8 switch-gate，加 helper | 现有 C8 与 S7 共享零理由 | 无直接门数收益 |
| 41 门 S0..S3 + 一门 nC4 | 不存在 | 83/6 所需 | 已严格封闭 |

## 后续研究建议

该样本最值得保留的不是 154/4 整体，而是以下研究接口：

```text
carry phase = {
  positive descriptor,
  negative reason 0,
  negative reason 1,
  ...
}
```

下一步针对 84/6 应做架构推导，而不是把 154/4 的 conditional-sum 树整体搬入：

1. 在当前 84 DAG 中寻找已经存在的、可作为 `negative reason` 的零理由，避免合成完整 nC。
2. 对 S4/S5/C6 或 S6/S7/C8 做联合布尔分解，要求一个新 reason 至少被两个输出消费。
3. 若新的 carry-out one-cover 已存在，直接采用 Z 输出，不支付 false-cover 恢复门。
4. 继续以完整真值表验证固定候选，但不要把该样本扩展成门序列穷举起点。
