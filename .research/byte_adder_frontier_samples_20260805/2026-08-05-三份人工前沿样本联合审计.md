# 三份人工前沿样本联合审计

日期：2026-08-05

## 结论

用户提供的压缩包包含三份完整 Byte Adder 电路：

```text
Switch 154 4    154 gate / 4 delay / 616 energy
Switch 103 5 A  103 gate / 5 delay / 515 energy
Switch 103 5 B  103 gate / 5 delay / 515 energy
```

三份电路均已按游戏 v15 物理拓扑重新计算门数、延迟、三态 BUS 和全部
`131072` 组输入。九个算术输出全部正确，所有 Switch BUS 均无
active-0/active-1 冲突。

这些样本确实补充了此前缺少的人工前沿架构证据：

1. `154/4` 是 carry phase / conditional-sum 电路，不是普通 CLA。
2. 两份 `103/5` 是同一低前端上的两种不同 bit4:5 状态编码，不是布局重排。
3. 人工结构大量保留 `positive descriptor + negative reason covers`，避免先恢复完整
   正负 carry。
4. 最终逻辑零可以保留为 Z，再由免费 Maker/Splitter 归一化。
5. 多个 Switch 合流时，人类方案优先共享同一 data，让 enable 重叠仍然安全。

但是，本轮没有从三份样本中得到可诚实物化的 `83/6`：

```text
154/4 的 41 门 S0..S3 活锥无法在一门内补出 nC4@3
103/5 的 C4@3 比当前 C4@4 多付 3 门
103/5 B 的 C6 核局部省 1 门，但 C4+C6 合并后净增 2 门
103/5 A/B 的两处一门差异依赖不同 ABI，不能直接拼成 102/5
当前 84/6 中没有一门或一只 Switch 可公开 E6@3 / nC6@4
```

因此候选和正式存档继续保持已实机验收的：

```text
84 gate / 6 delay / 504 energy
SHA-256 953A83A229DF9C1D104498F0DCEFD9DA216B63599445E7D9DF85E543D175B14A
```

没有把条件接口、局部账本或未经完整拼接的结构写入存档。

## 验证方法

通用审计器：

```text
analyze_frontier_samples.py
```

它执行：

1. 解码 v15 Snappy 存档。
2. 从实际导线端点恢复物理网络。
3. 分别保存每条网络的 truth、driven、Z 和 conflict 掩码。
4. 按普通门、Switch、Maker/Splitter 的实际 Z 读取语义执行位并行仿真。
5. 对 `A[7:0]、B[7:0]、Cin` 的 `2^17` 个输入组合验证 `S[7:0]、Cout`。
6. 从原生元件重新计算门数和逻辑 arrival。

三份样本的共同验证结果：

```text
truth rows                 131072
sum/carry mismatch         0
BUS conflict rows          0
declared gate == derived   true
declared delay == derived  true
```

该模型严格区分：

```text
active 0
active 1
Z
active-0/active-1 conflict
```

尤其没有再次采用错误假设：

```text
SW(enable=1, data=Z) -> Z
```

实物化 Switch 在该条件下会读取数据零并主动驱动 0；只有关闭的 Switch 自身才输出 Z。

## `154/4`：phase-split conditional-sum

该样本使用 49 只 Bit Switch 和 18 个 resolved BUS。核心接口不是完整 carry 的正负双轨，
而是：

```text
carry phase = {
  positive descriptor,
  negative reason 0,
  negative reason 1,
  ...
}
```

以 C5 为例：

```text
C5d.one = C5
N50 OR N51 = NOT C5
```

但电路不物化 `N50 OR N51`。`N50/N51/C5d` 直接同时控制 S5、S6、S7、C8，
把相位选择留到最后一层 Switch。

这解释了其四延迟：高位同时计算 carry phase 为 0/1 时的 sum cofactor，最后只选择一次。
代价是显著增加门数；例如 S5 phase selector 本身就是三只 Switch，即 6 门，而当前
Patchouli S5 只需 5 门。

### 41 门低闭包

固定 `S0..S3` 的完整活锥为：

```text
41 gate / D4
```

它看似只需再加一门就能满足 `42 gate low front`，但缺失的合同是完整 `nC4@3`，不是
任意相关 descriptor。三层固定审计结果：

```text
41 门闭包内现有 <=D3 nC4 descriptor             0
闭包内任意 <=D2 根 + 一只普通门                  0
全 154/4 样本任意 <=D2 根 + 一只普通门            0
```

已知 21 门负相中段的 S4、S5、nC6 对低位 nC4 的观察域覆盖全部 `2^9` 个低位输入，
不能借 bits4:5 条件隐藏错误。允许的唯一放宽是 nC4 为零时使用 Z，现有 descriptor
仍然没有命中。

所以以下拼接不存在：

```text
41 gate S0..S3 + 1 gate nC4 bridge + 21 middle + 20 high
```

## `103/5 A`：二位 group owner 与 reason split

样本 A 的低前端在 D3 产生 C4：

```text
D23 = BUS(SW(G3,V3), SW(V2,V3))                 @2
R23 = NAND(nG2,nG3) = G2 OR G3                  @2
C4  = BUS(SW(R23,D23), SW(C2,D23))              @3
```

该结构先计算共享 data，再合并 generate enable；所有 driver 重叠时 data 相同，
因此无 BUS 冲突。

样本还证实了合法的 ordered-cofactor `nC4@3` 对偶：

```text
M23     = BUS(SW(Q3,nG3), SW(nG2,nG3))          @2
Kreason = Q2 OR Q3                              @2
nC4     = BUS(SW(Kreason,M23), SW(nC2,M23))     @3
```

不过该公式与仓库已经验证的
`.research/byte_adder_segmented_switch84/segmented-negative-spine-audit.json`
完全相同，只是人工样本对这一架构的独立印证：

```text
delta vs repository ordered-cofactor baseline = 0
```

不能把它相对一个未采用的三 Switch 写法的局部 `-1`，重复计成当前前沿的新收益。
目前也没有一张完整 43 门或 42 门负相低前端；低两位和 S2/S3 仍缺完整联合闭合。

## `103/5 B`：负 reason 不合流与 S7/C8 共享

样本 B 的 bit4:5 主干：

```text
V45 = NOR(Q4,Q5)
D45 = G5 OR V45
E45 = G4 OR G5

C6 = BUS(
  SW(E45,D45),
  SW(C4,D45)
)

K45 = NOT D45                         @3
R1  = NOT(C4 OR G4 OR G5)             @4
K45 OR R1 = NOT C6
```

它不支付最后的 `K45 OR R1`，而是让 S5、S6、S7 分别消费两条 negative reason。

高尾还把 S7 的内部 cofactor 直接提供给 C8：

```text
P7*V6          同时属于 S7 cofactor 与 C8 data
G6 OR nP7      同时属于 S7 cofactor 与 C8 enable
```

raw C8 的目标零行可以保持 Z：

```text
Maker2(0, raw_C8) -> Splitter2.out1 -> Carry out
```

该边界是 `0 gate / 0 delay`，但不能修复内部 BUS 冲突。

### 对当前 84/6 的替换账本

```text
当前 C4 producer       6 gate / C4@4
B C4 producer          9 gate / C4@3
差额                   +3

当前 C6 core           8 gate / C6@4
B C6 core              7 gate / C6@4，要求 C4@3
差额                   -1

联合差额               +2
```

B 的三 Switch S5 即使把其他 helper 全部视为已付，仍需 `H5 + 3 Switch = 7` 门，
而 Patchouli S5 是 5 门。因此这些是 D5 的时序换门结构，不是 D6 的直接减门结构。

把 B 的 `K45/R1` 分裂 reason 完整迁移到 D6 后再次做固定状态账本，结论更严格：

```text
K45/R1 producer                     +2
S5                         5 -> 8   +3
S6                         3 -> 7   +4
尚未替换 S7/C8 前                    +9

完整 B 高尾                        30 gate
Patchouli 高尾                     20 gate
相关完整切口                 33 -> 48，+15
```

即使不可能地把旧 C6 四门 owner 全部免费删除，仍然净增 5 门。因此分裂 reason 是
理解 D5 架构的有效证据，但不能代替当前 `E6@3/nC6@4` 缺失 producer。

## `103/5 A/B` 结构差分

两份样本按 permanent ID 有 69 个物理元件共有，但其中 6 个元件被重新接线；A-only
和 B-only 的付费区域均为 25 门。

表面的互补一门来自：

```text
A helper          2 gate
B helper          3 gate                 A 省 1

A S5 completion   7 gate
B S5 completion   6 gate                 B 省 1
```

不能把 `A helper + B completion` 机械拼成 24 门。B 的 completion 消费：

```text
HB = NOT(Q4 OR P5)
Q4
B 专用 S4 phase rail
```

其中 `HB` 正是 B 多付的一门 helper，A 的接口不提供；A/B 的 C6 虽然归一化布尔真值
相同，driven/Z 域也不同。因此本轮只否决“零适配直接拼成 102/5”，不把它冒充成对
所有重新协同设计的 102/5 下界。

## 当前 84/6 缺失接口审计

已知补相联合尾在条件接口：

```text
D45@3
E6@3
C6 = D45*E6
```

成立时可以只产生 `nC6=NAND(D45,E6)@4`，理论上把完整 84 门结构降到
`81 + E6 producer compensation`。真正问题是当前 DAG 没有独立 E6 rail。

`audit_missing_interfaces.py` 对当前权威 84/6 的固定早到节点检查：

```text
E6@3 under D45 care:
  existing <=D3 node                 0
  one ordinary gate over <=D2 roots 0
  one Bit Switch over <=D2 roots     0

nC6@4:
  existing <=D4 node                 0
  one ordinary gate over <=D3 roots 0
  one Bit Switch over <=D3 roots     0
```

这里已经允许 E6 只在 `D45=1` 的有效数据域正确，而不是要求全域相等。因此现有节点
不能用一只门或一只 Switch 把条件联合尾变成 `83/6`。要继续该路线，必须替换上游
producer 并让新状态同时删除其他已付节点，不能把 `E6` 当成免费命名。

对三份人工样本的早到节点执行相同检查，也没有出现可直接迁移的 baseline `nC4@3`
或 `E6@3` 单元桥。

## 可迁移的确定原则

### 1. 共享 reason，而不是恢复完整 carry

```text
nC = reason0 OR reason1
```

如果多个输出都需要 `nC`，应优先让它们分别消费 reason0/reason1；只有在这能删除至少
两个后续 owner 时，额外 Switch 成本才可能回本。

### 2. 同 data owner 优先合并 enable

多个 Switch 共用 data 时，enable 可以重叠且不产生异值冲突。若 arrival 允许：

```text
BUS(SW(e0,d),SW(e1,d))
```

可以考虑：

```text
SW(e0 OR e1,d)
```

它从 4 门降到 3 门，但增加一级。三份人工样本说明该交换通常用于换深度，不能脱离
arrival 账本计算收益。

### 3. care-domain 等价必须同时检查 driven/Z

A/B 的 C6 enable 在共同 data 为 1 的关心域内等价，却不是全域同函数。这种放宽有效，
但必须同时验证：

```text
目标 one-mask
driver active-zero 域
driver active-one 域
Z 域
所有 driver overlap conflict
```

### 4. 终端 one-cover 可以免费归零

最终输出的目标零行可以是 active-0 或 Z；Maker/Splitter 可免费归一化。内部网络仍不能
把 Z 当作透明的第三逻辑值，也不能容忍 0/1 短路。

## 当前状态与下一入口

本轮明确关闭了四个看似只差一门的伪拼接：

```text
154/4 low41 + one nC4 gate
103/5 B C6 -1 without paying early C4
103/5 A helper -1 + B completion -1
conditional nC6 tail without a physical E6 producer
```

对 `83/6` 仍有意义的入口是跨 producer/consumer 的重新编码：

1. 在产生 `B23/C4/U45/C6` 的同一结构中公开可复用的 negative reason。
2. 让一个新 reason 同时删除 S5 与高尾中的至少两个旧节点。
3. 对 S7/C8 继续采用联合 cofactor，不先恢复标量 C7。
4. 只对完整固定候选做真值验证，不把这些样本扩展成大规模门序列搜索。
