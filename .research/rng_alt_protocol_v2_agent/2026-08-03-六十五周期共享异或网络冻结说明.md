# 六十五周期共享异或网络冻结说明

## 2026-08-03：65-cycle 稀疏 C 搜索

### 结论

本轮建立了一个可独立复核的 65 周期持续种子协议搜索器，但尚未找到可构造的榜单候选。

当前三个互不等价的前沿是：

| 目标 | over | excess | max | quadratic | 含义 |
| --- | ---: | ---: | ---: | ---: | --- |
| 违规行数优先 | 11 | 125 | 42 | 2021 | 反馈半部仍有 11 行不满足必要到达时间 |
| 总超额优先 | 17 | 70 | 28 | 390 | 当前最小 `excess` |
| 平方超额优先 | 21 | 79 | 24 | 359 | 当前最小平方 hinge 与最小最坏行 |

`over` 尚未达到 0，因此这些记录都不是完整 XOR DAG，更没有写入存档或声称取得游戏成绩。

### 协议

设 `A` 是游戏 RNG 所用的 `xorshift32(13, 17, 5)` 线性变换，`C` 是待搜索的可逆矩阵：

```text
P = C^-1
T = P*A
B = T*C
D = T*(A+I)

q' = B*q XOR D*seed
y  = C*q XOR A*seed
```

零初态下，tick `0..64` 的输出依次为：

```text
A(seed), A^2(seed), ..., A^65(seed)
```

`audit_sparse_c65.py` 会从每条记录的 `C` 独立重建 `P/T/B/D`，并完整重放 65 拍；它不信任搜索器写入的 `protocol_verified` 字段。

### 到达时间必要条件

本路线假定：

```text
state leaf arrival = 4
seed leaf arrival  = 0
普通 XOR            = 3 gate / 2 delay
目标 delay          = 8
```

每个输出或反馈行必须满足：

```text
4 * state_support + seed_support <= 16
```

输出半部 `[C|A]` 在搜索期间被严格限制。每行容量为：

```text
cap[row] = floor((16 - wt(A[row])) / 4)
```

32 行中有 17 行允许 `wt(C[row]) <= 3`，15 行只允许 `wt(C[row]) <= 2`。反馈半部 `[B|D]` 的 `over` 是仍违反同一必要条件的行数。

### 能耗预算

32 位状态固定按 `160 gate` 计。为了改进已验收成绩，研究目标为：

```text
delay 8, cycles 65: total <= 466, logic <= 306, 普通 XOR <= 102
delay 9, cycles 65: total <= 414, logic <= 254, 普通 XOR <= 84
```

即使未来得到 `over=0`，仍须做 arrival-aware 共享 DAG 综合并验证 XOR 数量；必要时序可行不等于满足门预算。
