# 字节加法器合法冲榜第二检查点

## 2026-08-03 / 提交：冻结公开拓扑、区间下界与旧版考古

### 规则边界

- 当前版本 `byte_adder` 关卡禁止使用原生 `com_add`；所有部署候选必须保证
  `kind 30` 数量为零。
- 完整测试域为 `A:U8 × B:U8 × Carry in:U1`，共 `131072` 组输入；服务端会收到
  实际电路并重算，不能依赖文件头或样本特化。
- 当前合法基线仍是 Hub 79 转换版 `154 gate / 4 delay / 616 energy`。

### 本阶段确定结果

1. A/V 联合相位区间族在六延迟下得到严格边界：`<=108/6 UNSAT`，`109/6 SAT`。
   该结论只封闭指定区间族，不能外推为所有门/开关结构的全局下界。
2. 公开来源共扫描 390 个 Hub 电路及 8 个 GitHub 存档仓库的相关历史；完整可重放
   原件只有 Hub 79 `154/4` 和 Hub 88 `56/18`，没有恢复排行榜中间点的网表。
3. 旧 v6 存档中的低延迟方案按当前成本重算为 `144/18` 和 `209/10`，不能直接迁移为
   当前榜单候选；旧 Switch、NOT 和关卡端口针脚也与 v15 不同。

### Byte MUX 成本纠错

曾提出“合法 `33/2` Byte MUX 可把窄位宽 `com_mux` 导入为 `U1/U2/U3 =
1/2、2/2、3/2`”的假设。当前 `2.1.281` 可执行文件的精确成本分支与既有运行时审计
表明该假设错误：导入门数先按八位基准拆成商和余数，再使用目标位宽，`33/2` 对应的
窄位宽结果是 `5/2、9/2、13/2`。此外主线图显示 `byte_mux` 位于 `byte_adder` 之后，
不能把后解锁的原生 MUX 作为本关安全综合基础。

所有基于廉价 MUX 的临时搜索均已撤销或明确标记无效。后续只采用当前关卡可用的普通门、
`3/2` XOR、`2/1` Bit Switch、高阻总线以及由这些元件组成的合法自定义结构。

### 下一步

- 将已验证的二位、三位和四位联合 `Sum + transfer` 宏接入完整八位共享节点搜索；
- 同时攻击 `<=128/4`、`<=102/5`、`<=85/6` 和 `<=73/7`；
- 只有完整候选通过全真值、Z 冲突、物理网分区、全局时序、v15 往返和几何审计后，
  才能覆盖正式存档交给用户实机验收。
