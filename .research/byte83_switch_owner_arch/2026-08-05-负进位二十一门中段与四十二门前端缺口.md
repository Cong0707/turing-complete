# 负进位二十一门中段与四十二门前端缺口

日期：2026-08-05

## 结论

用户新取得的帕秋莉截图与仓库权威原图逐字节相同：

```text
SHA-256  B9090FB9D253DED8DB241590387457F401F8E50F17958F88D986A5FA6B6ECCCD
score    84 gate / 6 delay / 504 energy
```

因此图中不存在此前裁图漏掉的 `E6@3`、`nC6@3` 或其他隐藏 rail。公开图的低四位仍为
`42` 门正相结构，帕秋莉从 `85 -> 84` 的一门节省位于五门 `S5`。

本轮只使用固定公式和三态 Switch 语义，得到一个严格的 `21` 门负进位中段。若低四位能
在不超过 `42` 门内输出：

```text
S0,S1,S2,S3
nC4 @3
```

则完整账本成为：

```text
negative low front                 42
negative bits4:5 + nC6             21
phase-flipped bits6:7 + C8         20
-------------------------------------
complete target                    83 / 6 / 498
```

当前仍未闭合的是第一行，故本文不宣称已经得到 `83/6` 候选，也不物化或覆盖存档。

## 一、二十一门中段

每位使用 one-hot 状态：

```text
Qi = NOR(Ai,Bi)
Gi = AND(Ai,Bi)
Pi = NOR(Qi,Gi)
```

负 group carry 定义为：

```text
R45 = NOR(Q5,Q4)                                  @2
K45 = NOR(G5,R45)                                 @3
    = Q5 OR P5*Q4

P45 = AND(P4,P5)                                  @3

nC6 = BUS(
  SW(enable=K45,data=ON),
  SW(enable=P45,data=nC4)
)                                                  @4
```

`K45` 与 `P45` 严格互斥：

```text
K45=1 -> Q5=1，或 P5*Q4=1
P45=1 -> P5*P4=1
Q5*P5=0
Q4*P4=0
```

所以 owner 没有 active-zero/active-one 冲突。`P45=1,nC4=0/Z` 时第二路可主动驱动
零，但第一路严格关闭；最终 Maker 可把 Z 数据面免费归一化为零。

bit4 Sum 使用 `nC4` 的补相：

```text
L4 = NOR(P4,nC4)                                  @4
H4 = AND(P4,nC4)                                  @4
S4 = OR(L4,H4)                                    @5
```

即：

```text
S4 = XNOR(P4,nC4) = XOR(P4,C4)
```

bit5 不恢复标量 `C5`，而在消费者关心域内使用：

```text
U45n = NAND(nC4,P4)                               @4
H5   = NOR(Q4,P5)                                 @3
T5   = AND(U45n,H5)                               @5
J5   = AND(P5,nC6)                                @5
S5   = OR(T5,J5)                                  @6
```

当 `H5=1` 时必有 `Q4=0`：

```text
bit4=P: U45n = NOT nC4 = C4
bit4=G: P4=0, U45n=1
```

所以在 `H5` 的完整观察域：

```text
U45n = C4 OR G4
T5   = NOT P5 * C5
J5   = P5 * NOT C5
S5   = P5 XOR C5
```

精确门账为：

```text
bit4/5 Q/G/P leaves                              6
R45/K45/P45                                      3
nC6 two-Switch owner                             4
S4                                               3
U45n/H5/T5/J5/S5                                 5
--------------------------------------------------
middle                                          21
```

## 二、低位合法的早到负进位核心

对 bit0 输入任取 `x,y,z`，定义三个 majority-zero implicant：

```text
qxy = NOR(x,y)
qxz = NOR(x,z)
qyz = NOR(y,z)
```

bit1 定义：

```text
Q1  = NOR(a1,b1)
nG1 = NAND(a1,b1)
```

则以下 owner 是合法的 `nC2@2`：

```text
nC2 = BUS(
  SW(qxy,nG1),
  SW(qxz,nG1),
  SW(qyz,nG1),
  SW(Q1,Q1)
)                                                  @2
```

四个 driver 的 active-one union 为：

```text
Q1 OR nG1*(qxy OR qxz OR qyz)
= Q1 OR P1*nC1
= nC2
```

`Q1` 分支与三个 low-kill 分支重叠时 data 都为一；bit1 generate 时 `nG1=0` 且
`Q1=0`。因此没有异值重叠。成本为：

```text
three bit0 NOR leaves                 3
Q1/nG1                               2
four Switches                        8
--------------------------------------
nC2 core                             13
```

## 三、低两位的门数/时序缺口

在复用 `qyz` 后，以下六门能同时生成 `S0` 与 `nC1`：

```text
D   = AND(y,z)                                     @1
E   = OR(qyz,D)                                    @2
R   = NOR(x,E)                                     @3
T   = AND(x,E)                                     @3
S0  = OR(R,T)                                      @4
nC1 = OR(qyz,R)                                    @4
```

严格恒等：

```text
E   = XNOR(y,z)
S0  = XNOR(x,E) = x XOR y XOR z
nC1 = majority_zero(x,y,z)
```

门数恰好满足低两位 `23` 门的局部目标，但 `nC1@4` 太晚。当前四门负相 `S1` 尾为：

```text
Z1 = NOR(nC1,nG1)
N1 = NAND(nC1,Q1)
E1 = AND(nC2,N1)
S1 = OR(Z1,E1)
```

它在布尔上正确，却得到 `S1@7`。若另付两门先把三个 `q` 合成 `nC1@3`，并使用五门
`S0`，时序恢复，但低两位从目标 `23` 变为 `24` 门：

```text
bits0:1                              24
```

必须明确：这只是**低两位**账本，不是一个已经闭合的 `43` 门快速负前端。合法的
`nC4@3` ordered-cofactor 边界还需要：

```text
Q2/nG2/Q3/nG3 leaves                  4
V23 two-Switch owner                  4
U23 enable OR                         1
nC4 two-Switch owner                  4
---------------------------------------
carry boundary                       13
```

其中：

```text
V23 = BUS(SW(Q3,nG3),SW(nG2,nG3))              @2
U23 = OR(Q2,Q3)                                 @2
nC4 = BUS(SW(U23,V23),SW(nC2,V23))              @3
```

这个 `13` 门只交付 carry，尚未包含 `S2/S3` 的完整相位。现有资料没有一份已经闭合的
`19` 门 `bits2:3 + nC4@3`，因此当前没有完整 `43`、`42` 或更低的快速负前端，不能把
低两位的一门缺口误报为整个前端只差一门。

真正的 `83/6` 前端合同包含两个同时成立的子目标：

```text
bits0:1 -> S0,S1,nC2@2                        <=23 gate
bits2:3 -> S2,S3,nC4@3                        <=19 gate
-------------------------------------------------------
complete negative low front                   <=42 gate
```

低两位当前最窄的局部收口仍是二选一：

```text
1. 同样六门同时产生 S0 与 nC1，并令 nC1 最迟 @3；
2. 保留上述 nC1@4，但用不超过四门、且 nC1 路径最多两级的 S1 闭合。
```

bits2:3 则必须让 `V23/U23` 成为 `S2/S3` 的已付相位，不能把 `13` 门 carry 边界与
独立 parity 尾简单相加。第二项也不能简单复用现有四门 `S1` 尾：其
`nC1 -> N1 -> E1 -> S1` 是三级路径。任何普通门的主动零输出都不能直接接入另一个
active-one driver；那会把布尔 OR 误当成合法 BUS。

## 四、`103/5` 同-data enable 合并技巧的严格投影

新取得的 `103/5` 样本反复使用：

```text
BUS(SW(e0,D),SW(e1,D))                 4 gate / 1 owner layer
```

如果 `e0/e1` 有一级时序余量，可以改为：

```text
u = OR(e0,e1)                          1 gate
SW(u,D)                                2 gate
----------------------------------------------
                                       3 gate
```

这是真实的一门节省，但不是零延迟合并。负前端有三处表面命中，全部位于关键路径：

### 4.1 `nC2` 的 low-kill drivers

把 Q1 driver 的 data 也写成 `nG1` 后，四个 driver 可以统一为：

```text
SW(qxy,nG1)
SW(qxz,nG1)
SW(qyz,nG1)
SW(Q1, nG1)
```

其中 `Q1 -> nG1=1`，所以该改写布尔与三态均正确。但所有 enable/data 都是 `@1`：

```text
未合并：Switch                           -> nC2@2
合并两 enable：OR@2 -> Switch            -> nC2@3
```

bits2:3 全传播时，每一种 `nC2` cause 都会改变 `nC4`，没有可以走慢支路的非观察 cause。
所以该一门节省会直接把 `nC4` 推到至少 `@4`。

### 4.2 `V23` 的 common-data owner

```text
V23 = BUS(SW(Q3,nG3),SW(nG2,nG3))       @2
```

改成：

```text
ve = OR(Q3,nG2)                          @2
V23 = SW(ve,nG3)                         @3
```

虽然 `4 -> 3 gate`，但末层 `nC4` 还必须再消费 `V23`，故 `nC4@3 -> @4`。

### 4.3 `nC4` 的 FAST_APPLY owner

```text
nC4 = BUS(SW(U23,V23),SW(nC2,V23))       @3
```

两 enable 都在 `@2`。合并后：

```text
ue = OR(U23,nC2)                          @3
nC4 = SW(ue,V23)                          @4
```

同样省一门、增加一级。`nC4@4` 会令 `nC6@5`，随后 `S5` 或高尾进入 `@7`。

因此，`103/5` 的技巧本身有效，但当前三个 obvious hit 都没有 arrival slack。要把它变成
`83/6` 的真实收益，必须先改变 producer ABI，使某一对 enable 在 `@1` 以前等价公开，
或让合并后的 Switch 本身直接成为最终 Sum 输出；不能只在现有 owner 上机械替换。
