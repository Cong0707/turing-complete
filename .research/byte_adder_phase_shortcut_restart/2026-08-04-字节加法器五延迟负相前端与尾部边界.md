# 字节加法器五延迟负相前端与尾部边界

## 2026-08-04 / 提交：固化七门 `S1/S2` 并关闭两条尾部主线

### 结论

本检查点没有产生可部署的新完整电路，正式存档和仓库候选继续保持用户已经实机验收的：

```text
80 gate / 7 delay / 560 energy
```

本轮形成了三个可复现的严格结果：

1. 快速负相前缀中的 `S1/S2` 可以用 **7 个普通门**在最大延迟 5 内完成；
2. 在固定 fast-negative paid-source 接口下，`S5/S6` 总成本 `<=7`、延迟 `<=6`
   的全部 30 种 ordinary/Switch/XOR 成本分解均为严格 `UNSAT`；
3. `S7/C8` 直接尾部 11 门路线中最有希望的两种无 XOR 分解
   `n8/s3/x0` 与 `n9/s2/x0` 均已在 Ubuntu 工作站严格 `UNSAT`。

后两项都是**接口限定或分解族限定**的局部下界，不能外推成整个 Byte Adder 的全局下界。

### 七门 `S1/S2` 结构

付费源及到达时间为：

```text
nC1 @2
Q1  @1
P1  @2
P2  @2
nC3 @3
```

精确 SAT 见证解码为：

```text
v  = NOR(Q1, P2)
a  = AND(P2, nC3)
w  = NAND(nC1, P1)
x  = AND(v, w)
u  = OR(nC1, P1)
S1 = NAND(w, u)
S2 = OR(a, x)
```

成本与时序：

```text
ordinary gates = 7
Switch          = 0
XOR             = 0
S1 arrival      = 4
S2 arrival      = 5
```

它不是把 XOR 错算成一门；七个节点全部是游戏中真实的普通一门、一延迟原语。

完整负相低位重放从真实 bit0 Switch 证书开始，构造 `nC1`、A/V12、`nC3`，再接入上述
七门网络。全 `U8 × U8 × U1` 输入域结果为：

### `S4@D5` 的局部成本提示

在完整 paid leaf/A/V/nC7 相关域、真实高阻态、冲突和 physical-net partition 约束下，
单独 `S4@5` 的所有总成本 `<=8` 分解均为 `UNSAT`；首次 SAT 为：

```text
9 gate / 7 components / 2 Switch / 0 XOR
```

该结果说明高位 29 门预算不能按六个输出分别切开；`S4` 单独综合已经需要 9 门，必须依靠
跨输出中间相位共享。规范正例：

```text
.research/byte_adder_phase_shortcut_restart/probe_s4_g9_n7_s2_x0_d5.json
```

### 固定 `S5/S6` 七门窗口

脚本穷尽成本 `1..7` 的全部合法分解：

```text
gate = ordinary + 2*Switch + 3*XOR
```

总计 30 项，全部在真实三态和物理网络模型中严格 `UNSAT`，没有 timeout/unknown：

```text
records       = 30
summary SHA-256 = d45985fd5b24107fcd47f0506e34e4d3e8e17f069f03bdac7aab8f596499a619
```

这只证明以下限定结论：

```text
固定 fast-negative paid sources + 隔离 S5/S6 residual <=7/D6 不可行
```

它不排除把 `S3..S6`、C5/C7 或 bit6 leaves 一起重写后的 `<=93/6`。


它包含：

```text

```

但该切片不是 Byte Adder 的可直接提交解。它从外围 32 位 ALU 免费接收已经预计算的
`AND/NOR/XOR/XNOR/A/B` 总线；若把这些输入的生成成本隐去，就会形成错误账本。当前只把
它作为公开、真实的 Switch 多输出共享拓扑来源，正在展开其控制函数并投影到
`fixed 73 + high residual 29` 接口。
