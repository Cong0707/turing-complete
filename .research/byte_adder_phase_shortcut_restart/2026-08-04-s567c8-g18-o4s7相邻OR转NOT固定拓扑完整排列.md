# `S5/S6/S7/C8 g18/o4/s7` 相邻 `OR -> NOT` fixed-kind 完整排列

## 结论

以前一轮已封闭的尾部 ordinary multiset `{NOT,NOR,OR,OR}` 为中心，本轮只改变
一个 kind，把其中一个 `OR` 替换为 `NOT`：

```text
{NOT, NOT, NOR, OR}
```

两个 `NOT` 对称等价，因此穷尽全部 `4!/2! = 12` 个唯一槽位排列；每个排列后面
固定七个 `SWITCH`：

## 内存保护与恢复

初始 spec 使用三个 worker、每片 `800 s` 外层硬超时和
`stop_on_first_sat=true`。启动后 Free RAM 一度降至约 `2584 MiB`，贴近本任务
`2.5 GiB` 下限，因此立即：

1. 停止 runner supervisor；
2. 保留优先级最高的两个在途 solver；
3. 干净终止第三片 `NOR/NOT/NOT/OR`；
4. 两个保留片自然写出 UNSAT 后，以完全相同的 12 个约束和结果目录生成
   2-worker resume manifest；
5. resume 自动复用 2 个已完成结果并求解其余 10 片。

原始与恢复 manifest 的 `name/proof_scope/values/arguments/working_directory/script`
逐项相等；只把 workers 从 3 降为 2。最终 summary：

```text
finished            = true
workers             = 2
results             = 12
reused              = 2
completed           = 10
UNSAT               = 12
SAT                 = 0
timeout/error/null  = 0
remaining processes = 0
```

所有 12 个正式结果均在硬超时前自然结束：

```text
minimum solve time = 87.782 s
maximum solve time = 220.110 s
sum solve time     = 1453.766 s
```

独立交叉检查确认 summary 中 12 个 value 与原始 manifest 逐项相等，12 个
`output_sha256` 与磁盘文件逐项相等，结果目录恰好是 manifest 指定的 12 个 JSON；
交叉检查 `errors=[]`。被主动终止的第三片没有进入终态集合，恢复后由新进程重新
求解；没有把中断、timeout、无 JSON 或 runner 状态误记为 UNSAT。

## 限定范围

本结论只封闭：

```text
[perm(NOT,NOT,NOR,OR), SWITCH, SWITCH, SWITCH, SWITCH, SWITCH, SWITCH, SWITCH]
```

它不能外推到其它 ordinary multiset、ordinary/Switch 交错拓扑、完整
`g18/o4/s7`、`g18/o6/s6`、含 XOR 的分解或 residual 接口重写后的完整 Byte
Adder。因此正确表述是“单步 `OR -> NOT` 邻域 terminal-Switch 拓扑类 UNSAT”，
不是“四输出 `g18/o4/s7` 全局 UNSAT”。
