## 已实现的统一语义模型

`interval_dp.py` 已实现：

- 规范化布尔/三态 DAG 与公共子表达式复用；
- 普通门 `1 gate / 1 delay`、XOR/XNOR `3/2`、Bit Switch driver `2/1`；
- 完整 `2^17 = 131072` 输入的 packed truth；
- BUS 的 `value / driven / conflict` 三态重放；
- 九个输出的 mismatch、Z 与冲突计数；
- 从输出 backward slice 精确计门；
- 每个输出的全局最长到达路径；
- 共享七门 ripple、动态 Cin 前缀、GP 区间树、递归 carry-skip 与命名共享区间 DAG。

固定六门 Sum 壳为每位三门 `G/K/P` 叶和三门 Sum 相位：

```text
G = AND(A,B)
K = NOR(A,B)
P = NOR(K,G)
T = AND(P,C)
N = NOR(P,C)
S = NOR(N,T)
```

八位固定壳共 `48 gate`。若使用本地普通 carry，`T` 与 Sum 共享，只需再加最终 OR 一门。

## 递归 carry-skip 证书

`interval_dp_carry_skip.json` 冻结了允许 `C_i` 从任意更早 `C_l` 经连续 GP 区间跳转的
加权节点并集选择。实际点为：

```text
116/7, 105/8, 102/9, 74/10, 67/12, 63/14, 60/16, 56/18
```

其中 `116/7` 的布尔值虽然没有 mismatch，但共有 `57344` 个最终输出 Z 赋值，故它是
**非法结构**，不得当作正向候选。`105/8` 及更慢点的 mismatch、冲突和九输出 Z 均为零。

这个结果也说明只按单个 carry 的局部 gate/arrival Pareto 裁剪，会删除“局部较差、全局
共享后更好”的区间计划；因此不能用该递归 DP 声称公开前沿不可达。

## 离散命名区间精确模型

`discrete_named_interval_dp.py` 修复了旧 `Optimize` 模型的性能问题：

1. Python 先穷举每个连续区间实际可达的 `(G arrival, P arrival)`；
2. Z3 只选择有限个布尔 recipe，不再求解无界整数到达时间；
3. 每个非叶区间至多选择一种状态和 recipe；
4. 多个 carry 可以共享同一命名区间；
5. 求解后用真实 `Factory` DAG 重建，并交叉检查 PB 账本、真实 backward-slice、到达路径和
   全 `131072` 三态语义。

D8 模型规模：

```text
interval states    230
interval recipes  1546
carry edges        253
```

三个可复现边界：

| 证书 | 结论 | 求解时间 |
|---|---|---:|
| `discrete_d8_g74.json` | `gate <= 74` UNSAT | 0.11 s |
| `discrete_d8_g81.json` | `gate <= 81` UNSAT | 0.32 s |
| `discrete_d8_g82.json` | `82/8` SAT | 0.08 s |

因此，在“固定 48 门 Sum 壳 + 普通/Switch GP black/gray + 单一命名连续区间”的精确定义
内，D8 最优门数严格为 **82**。正向见证：

```text
gate/delay/energy = 82/8/656
output arrivals   = 4,5,7,6,8,7,8,8,8
structural sha256 = 42b937a3263f3d2a8b8ae9d5c95a0a15df7a3e73ef7e45da29b2c6af28b518dc
mismatch           0
BUS conflict       0
九输出 Z           0
```

所选 carry 边：

```text
C1 <- C0 switch   [0,0]
C2 <- C1 ordinary [1,1]
C3 <- C1 switch   [1,2]
C4 <- C3 ordinary [3,3]
C5 <- C3 switch   [3,4]
C6 <- C5 switch   [5,5]
C7 <- C5 switch   [5,6]
C8 <- C7 ordinary [7,7]
```

公开 `74/8` 比该严格族下界少八门，所以它必然联合重写 Sum/carry 相位，或使用本模型没有
包含的双轨/多驱动状态；继续只扩展 GP 区间树不会命中公开点。

## 有界一位 SAT 审计

复用了相邻研究线的独立 CNF 编码器，并把结果写入本目录：

- 原始三输入、八槽位、`<=8 gate / <=3 delay`：UNSAT；
- `Cin arrival=16`、Sum/Cout deadline=17：
  - 八槽位 `<=8 gate` UNSAT；
  - 十槽位、gate bound `9..14` 均 UNSAT。

这些 UNSAT 只对各 JSON 中写明的槽位数、门上限和原语库成立。它们排除了“把末位直接换成
一个很小的一层 late-Cin 全加器”的简单解释，但不能外推为任意多槽位全局下界。

二位 `15 gate` late-Cin 搜索在停止通知前没有返回，已主动终止且没有结果文件；其状态严格为
`UNKNOWN`，不得写成 SAT 或 UNSAT。

## 公开 `103/5` 文件的边界

公开 Hub 33 包含一张序列化为 `103/5` 的依赖电路：

```text
.research/byte_adder_public/hub-33/dependencies/04/
  alu/32balu/extraction/2th add/circuit.data
```

只读解码确认它是 32 位加法器的八位提取段，输入包括外部预计算的 `NOR/AND/XOR/XNOR`
U32 总线、一个 carry 和额外控制；它不是 `A[7:0], B[7:0], Cin` 的独立 Byte Adder。
因此该文件可用于研究联合相位拓扑，但不能直接当作排行榜 `103/5` 完整原件，也不能把外部
预处理成本漏算。

## 冻结结论与继续方向

- 已得到可复现、完全驱动的 `82/8` 完整 DAG，以及该命名区间族 `<=81/8` 的严格 UNSAT。
- 尚未得到 `<=102/5`、`<=85/6` 或公开 `74/8` 的完整结构。
- 公开链从 `56/18` 到 `57/17` 已经超出固定 Sum 壳族，下一步必须把两位或多位
  **Sum + carry** 当成一个联合状态，而不是先物化每个 `C_i` 再做三门 XOR 相位。
- 值得继续的状态是 `(G,K)`、`(U=f(0),V=f(1))`、carry 双轨和同 data Switch cover；
  每个状态必须同时保留 value/driven/conflict 和逐轨到达时间。
- 任何新的结构都必须生成真实 Factory DAG并通过完整 `131072`、BUS 冲突、最终非 Z 和
  全局时序证书后，才能交给 builder；当前没有可写入存档的候选。
