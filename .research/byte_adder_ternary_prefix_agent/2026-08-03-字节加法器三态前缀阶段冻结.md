# 字节加法器三态前缀阶段冻结

## 2026-08-03 / 研究边界

本线独立研究 `byte_adder` 的合法无 `com_add` 构型，只使用当前已确认成本：

```text
NOT / AND / OR / NAND / NOR = 1 gate / 1 delay
XOR / XNOR                  = 3 gate / 2 delay
Bit Switch                  = 2 gate / 1 delay
```

没有启动游戏，没有修改正式存档、`examples/byte_adder/candidate` 或 Git 索引，也没有
创建子代理。收到冻结通知时，7 延迟枚举已经写完完整 JSON、尚未刷新标准输出；随后
进程被立即终止。`joint_d7.json` 已通过 JSON 解析且记录了全部 262,144 个 mask，不是
中途检查点。本目录及命令行中没有残留的 Python 求解进程。

## 物理三态约束

所有推导继续采用严格物理规则：

```text
一个 Switch 输出针脚只能属于一条 resolved wire net；
若两个抽象 BUS 共享任一 driver，则其完整 driver 集必须相同；
否则游戏中物化时两条 BUS 会直接短接。
```

因此旧证书中的 `6/1 shared combine`、`10/2 transfer` 与 `18/3 transfer` 不能作为
合法宏。本线没有复用这些已否决结构。

## `(G,L)` 三态区间代数复核

对任意 carry 转移函数 `f` 定义：

```text
G = f(0)
L = f(1)
G <= L
```

高区间 `H` 与低区间 `L0` 合成时，正确关系是：

```text
Gnew = LH & (GH | GL)
Lnew = LH & (GH | LL)
```

每一轨可由两只 data 均为 `LH` 的 Switch 在一层实现；两轨完整合成是合法的
`8 gate / 1 delay`。重叠 enable 只会驱动同一个数据值，不产生 0/1 冲突。

同时纠正一个容易误用的简式：

```text
Lblock = AND(逐位 Li)
CarryOut = Lblock & (CarryIn | OR(逐位 Gi))
```

这个等式对一般区间是错误的。高位 generate 可以覆盖低位 kill；此时逐位 `L` 的 AND
为 0，但区间输出 carry 仍为 1。合法的 `Lblock` 必须是完整区间的 `f(1)`，而不是逐位
`A|B` 的简单合取。后续搜索不得再用这个错误简化来声称省门。

## 固定 48 门 Sum 外壳的边界

排行榜的 `56/18 ... 88/6 ... 154/4` 可以在数值上减去 48，但这不等于已证明这些实物
共享同一个固定 Sum 外壳。使用每位：

```text
G = AND(A,B)
K = NOR(A,B)
P = NOR(K,G)
T = AND(P,C)
N = NOR(P,C)
S = NOR(N,T)
```

时，`P` 在第 2 层到达，Sum 还需要两层。为了总延迟 6，`C0..C7` 必须在第 4 层前
到达。直接枚举普通/快速 `(G,P)` 连续区间后，第 4 位 carry 的最快构造已经需要第 5
层；所以该固定外壳不能解释公开 `88/6`。`88/6 = 48 + 40` 只能视为算术账本，不能
作为拓扑证据。六延迟突破必须联合重写 carry 与 Sum 相位。

## Hub79 联合替换完整枚举

为避免冻结输入到达时间造成假前沿，本线调用现有 Hub79 全局 backward-slice 计分器，
枚举 18 条 Switch BUS 的“保留原 BUS / 使用已综合布尔表达式”组合，并在每个组合中：

1. 从 9 个输出重新追踪全部活节点；
2. 去除替换后失活的普通门与 Switch；
3. 递归重算替换表达式输入的真实到达时间；
4. 按实际仍存活的元件计门。

结果：

```text
延迟上限 5：检查 16,384 个 mask，104 个可行
Pareto：154/4、142/5

延迟上限 6：检查 262,144 个 mask，6,976 个可行
Pareto：154/4、142/5、126/6

延迟上限 7：检查 262,144 个 mask，50,304 个可行
Pareto：154/4、142/5、126/6、117/7
```

关键选择：

```text
142/5 Boolean BUS = [120,122,231,238,284,308]
126/6 Boolean BUS = [22,24,33,43,70,120,231,238,284,308]
117/7 Boolean BUS = [22,24,33,43,48,70,91,120,122,231,238,246,284,308]
```

这与此前报告的真实替换前沿一致，也严格否定了把独立 BUS 表中 `120/5` 或 `112/6`
直接当成完整网表的做法。该结构族离 `<=102/5`、`<=85/6` 仍很远，不应物化或覆盖
当前候选。

## ABC 校准旁证

用当前 `tc.genlib` 对通用 ripple AIG 执行 `map -D 6` 时，ABC 明确报告初始网络最佳
延迟仍为 14，并打印：

```text
Cannot meet the target required times (6.00). Continue anyway.
```

因此 `-D 6` 只是约束请求，不能作为六延迟证书。任何 ABC 输出仍须独立拓扑计时与完整
真值重放；本线没有把 ABC 的目标参数误报为候选。

## 冻结结论与继续入口

- 本线没有得到可物化的 `<515 energy` 完整 DAG，未修改存档。
- Hub79 的逐 BUS 布尔替换族已在 D5、D6 完整封闭，最佳仅 `142/5`、`126/6`。
- 固定 48 门 Sum 外壳不能产生公开 `88/6`；下一阶段必须联合综合 Sum/carry 相位。
- 有效方向是把区间状态扩展为 `(G,L,P/NP)` 或 carry 双轨，并让最终 Sum 直接消费该
  相位；不能把晚到单轨 carry 再接固定两层 XOR 外壳。
- 任何新 SAT 宏都必须包含物理 BUS 分区，并在组成 8 位 DAG 后执行 `131072` 全真值、
  冲突 0、最终输出非 Z、真实到达时间与 backward-slice 门数复算。
