# RNG U32 Switch 双标签模型

日期：2026-08-02

## 目标

本轮研究无 RAM、服务端可重算的 65-cycle 与 66-cycle 候选。异或成本严格按
游戏实测的逐位线性计费，不存在低价的 U1 Word XOR：

| 元件 | gate | delay |
| --- | ---: | ---: |
| 普通 XOR / U1 Word XOR | 3 | 2 |
| U2 Word XOR | 6 | 2 |
| U3 Word XOR | 9 | 2 |
| U4 Word XOR | 12 | 2 |
| U8 Word XOR | 24 | 2 |

因此下文所有 `x` 都是逐位二输入 XOR 的数量，成本一律为 `3*x gate`；把它们
打包成 Word 元件不会降低门数。65-cycle 模型的固定成本为：

```text
32 Delay Bit               160 gate
ready Delay Bit + NOT        6 gate
U32 Word Switch             64 gate
x 个逐位 XOR              3*x gate
k 个 Bit Switch            2*k gate

gate = 230 + 3*x + 2*k
delay = 9
cycles = 65
```

相对 `431/9/66 = 256014`，整数门数上限为 437。因此：

| XOR | Bit Switch 上限 | 最大 gate | energy |
| ---: | ---: | ---: | ---: |
| 61 | 12 | 437 | 255645 |
| 60 | 13 | 436 | 255060 |
| 59 | 15 | 437 | 255645 |

首拍必须同时满足：

```text
output   = A * seed
feedback = T * A * seed
```

之后同一物理 DAG 保持 `output=C*q`、`feedback=B*q`。

## 求解器

`solve_fixed_cover.py` 将 `search_word_bus_phase.py` 推广为共享 B/C DAG：

- U32 Word Switch 的每个 lane 在首拍携带一个固定 seed bit，稳态携带一个 q bit；
- 每个 raw q 出现位置可以选择一个与其稳态 q bit 匹配的 word lane；
- Bit Switch 按 `(seed, steady_node)` 去重并允许扇出；
- 与原模型一致，Bit Switch 只能用于首拍标签为零的 base；
- 同时约束 32 个 B 输出为 `T*A`、32 个 C 输出为 `A`；
- SAT 后独立检查矩阵恒等式、双标签、Switch 计数和 65 拍序列。

回归正例：把契约切回旧的“只要求 `B-load=T`”后，fixed two-shear x61
在 `k=15` 得到 SAT，证明求解器的 word lane、DAG 和 Bit Switch 连接没有被新约束
意外破坏。证据为 `positive-old-x61-k15.json`。

新契约下，基线在 `k=12` 为 UNSAT；把预算临时放宽到 256 仍为 UNSAT。

## 全局支持集阻塞

新契约存在一个与状态基无关的直接矛盾。

按照 `search_word_bus_phase.py` 的物理语义：

1. 一个 raw q 出现位置的首拍标签只能是 0 或一个 seed 单位向量；
2. Bit Switch 只能把零标签子树替换为一个 seed 单位向量；
3. 第一层二输入 XOR 的首拍支持集大小最多为 2；
4. 第二层二输入 XOR 的首拍支持集大小最多为 4；
5. 最终 Bit Switch 不会提高这个上限。

所以任意 C 输出的首拍标签权重最多为 4。但是 xorshift32 的 `A` 行权重分布为：

```text
weight 3:  5 rows
weight 4: 12 rows
weight 5:  3 rows
weight 6: 10 rows
weight 7:  2 rows
```

共有 15 个必须输出的 `A` 行权重大于 4，因此 `C-load=A` 不可能成立。

这个矛盾不依赖 `T/B/C`、pair cover、XOR 数量或 Bit Switch 预算。也就是说，在
当前深度二、相同 Switch 语义下，继续搜索 x61、x60 或 x59 状态基不会产生 SAT。

## 全量审计

`prove_support_bound.py` 同时扫描了 radius-7 的全部相关记录：

```text
x61: 19604
x60:  4329
x59:   842
合计: 24775
矩阵恒等式失败: 0
```

完整证据为 `support-bound-radius7.json`，状态为
`unsat-by-support-bound`。这不是抽样或求解超时。

## 结论与边界

当前精确定义的 65-cycle U32 Switch 双标签路线已被支持集上界整体排除，没有
合法候选可写入存档。

结论只覆盖 `search_word_bus_phase.py` 的 Switch 组合语义和深度二 XOR DAG。
若继续研究 65-cycle，必须至少改变一项：

- 提供能在首拍携带多 bit 线性形式的 load source；
- 使用更深的首拍 XOR 网络，并重新承担延迟；
- 证明游戏内存在不同于当前模型的合法 Switch 合并语义。

不能通过继续更换状态基绕过 `A` 的 15 个重行。

## 66-cycle 旧反馈契约的完整 x61 cover 审计

66-cycle 路线允许首拍沿用旧契约 `B-load=T`，因而不受上面 65-cycle
`C-load=A` 的支持集矛盾直接排除。其同一外壳仍按正确的 XOR 成本计费：

```text
gate = 230 + 3*x + 2*k
delay = 9
cycles = 66
```

相对 `431/9/66`，整数 `k` 的门数关系为：

| XOR 数 x | 严格超榜所需 k | 追平所需 k |
| ---: | ---: | ---: |
| 61 | <= 8 | 9 |
| 60 | <= 10 | 无整数 k（k=10 为 430，k=11 为 432） |
| 59 | <= 11 | 12 |

对 radius-7 的 145 个 direct/pair-clean x61 状态基，已无截断地枚举全部
`427` 个 pair cover；cover 搜索共访问 `8,050,797` 个状态。随后在允许 Word lane
任意扇出的宽松模型中，对每个 cover 精确求解 `k<=9`：

```text
processed = 427 / 427
SAT       = 0
UNSAT     = 427
UNKNOWN   = 0
```

因此该范围内既没有严格超榜的 `x61,k<=8` 解，也没有追平的 `x61,k=9` 解。
严格双射 lane 映射是此宽松模型的子集，也同步被排除。

radius-7 的全部 x60、x59 状态基另有更直接的物理剪枝：x60 每个基至少存在
1 个、x59 每个基至少存在 2 个 `direct_target_not_unit`。直通 B 输出只能从 Word
lane 或 final Bit Switch 得到零/单位标签，不能生成这些非单位 T 行。因此该范围内
全部 `4329` 个 x60 基与 `842` 个 x59 基对任意 cover、任意 k 都不可实现。

证据文件：

- `frontier-x61-all-covers-summary.json`：全 cover 枚举规模与无截断证明；
- `x61-all-covers-fanout-k9.jsonl`：427 个逐 cover 求解结果；
- `x61-all-covers-fanout-summary.json`：最终计数与模型参数；
- `../rng_weighted_basis_global/radius7-early-conflicts.json`：x59/x60 全范围 direct 冲突计数；
- `x60-d1p0-fanout-summary.json`、`x59-d2p0-fanout-summary.json`：最低冲突子集的精确回归；
- `solve_fixed_cover.py`、`enumerate_cover_variants.py`、`batch_minimize_k.py`：可复现脚本。
