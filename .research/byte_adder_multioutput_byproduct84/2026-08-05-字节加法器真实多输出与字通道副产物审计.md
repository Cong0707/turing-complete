# 字节加法器真实多输出与字通道副产物审计

日期：2026-08-05

## 结论

本轮只读检查当前安装的 Turing Complete 2.1.292 元件 ABI、已经实机通过的
`85 gate / 6 delay / 510 energy` Factory DAG，以及已经提取的真实原语关系。
没有启动游戏，没有修改正式存档，没有运行 SAT、BDD、随机电路或大规模枚举。

结论是：当前 ABI 中没有一项尚未消费的公开多输出、word-lane 或免费
Maker/Splitter 副产物，能够在保持 D6、完整 BUS owner、Z 与 fanout 合同的同时把
`85/6` 降到 `84/6`。因此本轮没有物化候选，也没有创建伪 `84/6` 目录。

最接近减门的结构是把唯一的 opaque `S0 XOR` 拆成三只普通门，免费暴露
`Cin AND P0`。它在布尔层面可以取代四门的低位 raw owner，并使账本暂时成为
`81 gate`；但该相位从当前 owner 的 `@1` 变成 `@3`，使 `S1` 到达 `@7`，同时把
`C2/B23/C6` 链整体推迟，严格违反 D6。这是一个真实多输出副产物，却不是可落实候选。

## 当前 ABI 的真实多输出边界

当前 Byte Adder 之前允许的 23 种 kind 中，只有以下元件与本轮问题有关。

| 元件 | 当前成本 | 公开输出 | Z/owner 行为 | 能否提供门数折扣 |
|---|---:|---|---|---|
| Full Adder | `16/8` | `Result, Carry out` | 两个 active 普通输出；同一付费实例 | 否；当前时序也直接失败 |
| Maker2/4/8 | `0/0` | 一个 U2/U4/U8 word | 逐 lane 读 data plane，Z 读成 0，产生新 active owner | 只做归一化，不产生逻辑 |
| Splitter2/4/8 | `0/0` | 2/4/8 个 scalar lane | 每个输出 active；不保留输入 Z owner | 只做拆线，不产生逻辑 |
| word NOT | `w/1` | 一个 word | lane 独立、active 输出 | 否，恰好 `1 gate/lane` |
| word NAND | `w/1` | 一个 word | lane 独立、active 输出 | 否，恰好 `1 gate/lane` |
| word Switch | `2w/1` | 一个 tristate word | 一个 scalar enable 控制整字 driven/Z | 否，恰好 `2 gate/lane` |

其余普通 `NOT/AND/NAND/OR/NOR/XOR/XNOR` 和 bit Switch 均只有一个公开输出。
当前 EXE 的静态 pin 表没有发现隐藏可接线输出。opaque 元件内部的中间变量不是 pin；
只有把它显式拆成多个合法原生门后，中间相位才成为真实可扇出的输出，同时必须支付全部门。

### Maker/Splitter 的精确能力

对 scalar raw BUS `R=(value, driven, conflict)`：

```text
R -> Maker -> Splitter -> Ractive

value(Ractive)    = value(R) 的 data plane
driven(Ractive)   = all rows
Z(Ractive)        = 0 rows
conflict          = conflict(R)，冲突不会被合法化
gate / delay      = 0 / 0
```

原 raw owner 仍可从原导线 fanout；适配器输出是另一个 active owner。这个机制不能：

```text
提取 driven mask
提取 Z predicate
复制某一只 Switch 的 partial-driver pin
把一个完整 BUS 的 driver proper subset 变成第二个 BUS
让两个不同 lane 发生逻辑混合
```

Maker 的公开 word 到达时间取所有 lane 最大值；再经过 Splitter 后，各输出共享该 word
到达时间。因此把快慢不同的 raw BUS 一次打包，可能免费归一化却破坏关键路径。

### word 元件没有隐藏共享成本

当前成本公式是：

```text
word NOT(w)       = w gate / 1 delay
word NAND(w)      = w gate / 1 delay
word Switch(w)    = 2w gate / 1 delay
```

所以 U2/U4/U8 只提供并行时序和版图聚合，不提供 gate 折扣。word Switch 还有更强的
物理限制：全部 lane 共用一个 scalar enable 和一个 whole-word driven state，不存在逐 lane
Z mask。把 word Switch 输出经过 Splitter 会立刻变成 active lanes，不能再把这些 lane 当作
不同 resolved BUS 的 partial driver。

当前 85 门不是“只取每个门最终输出”的朴素网络，它已经使用了真实可接线中间相位：

```text

           同时服务 S4 与 S5 owner

node 75  = C6 OR (NOT P6)
```

这些是显式普通门输出，可合法 fanout；它们已经按一次成本计入，不能作为未付费副产物
再次删除一门。

## 候选逐项审计

## 候选 A：六个 raw BUS 的免费 active clone

动作：分别用 Maker/Splitter 为 node 18、26、31、68、74、80 产生 active clone。

```text
新增 gate                         0
新增 delay                        0（逐个适配时）
删除付费 gate                     0
净 gate                         85
```

Z 审计：clone 把 Z 变 active 0，数据面保持；raw owner 仍存在且不可拆分。fanout 审计：
node 18/26/31/68 的消费者已经由普通门或 Switch 输入按 data plane 读取，active clone 不会
取代任何逻辑门；74/80 已在最终 Maker8 做同一件事。

若把多个 BUS 合并到一个 word 后再拆分，word 到达取最大值。例如把 arrival
`1,2,3,4` 的 node 18/26/31/68 一次打包，会把所有拆出 lane 推迟到 `@4`；node 18 当前
必须在 `@1` 进入 C2/C1 边界，因而这种共享还会破坏 D6。

结论：真实、合法，但已消费或无减门作用。

## 候选 B：Maker/Splitter 复制 raw value 给两个消费者

动作：把同一个 raw BUS 放入 Maker2 的两个 lane，再经 Splitter2 得到两个 active copies，
同时保留原 raw 输出。

```text
新增 gate                         0
可见输出                         raw + active0 + active1
可见 Boolean function            仍只有同一个 data plane
```

这看似是“免费三输出”，但三个输出不包含 driven 或 `NOT value`。普通线本来就允许无限
fanout；额外 active owner 只有在消费者要求 fully-driven 时有意义。当前没有一只付费门
只执行 raw-to-active buffer。active 输出若与另一 driver 直接短接，会在异值行冲突，不能
充当新 partial owner。

结论：不能同时替代两条付费相位，也不能替代两个 owner。

## 候选 C：word NOT/NAND 批处理多条相位

动作：把 2/4/8 个 scalar 任务打包，经过一个 word NOT 或 word NAND 后拆出。

```text
k 个 scalar NOT/NAND             k gate
一个 Uk word NOT/NAND             k gate
Maker + Splitter                  0 gate
净节省                            0 gate
```

当前 DAG 共有 6 个 NAND 节点。即使把六只全部送入 U8 NAND，仍需 `8 gate`，相对现有
`6 gate` 为 `+2`；只有再找到两个真正需要的 NAND lane 才能打平，仍不能得到 84。
word 输出的到达时间还会按最慢 lane 传播到所有 Splitter 输出，可能污染早期 phase。

Z 审计：word ordinary gate 与 scalar ordinary gate 一样读取 Z=0 并主动驱动，不能保留
partial owner。fanout 审计：拆出的 active lane 可自由 fanout，但不比原 scalar 输出多出
新逻辑函数。

结论：可用于布局和同步，不提供排行榜 gate 优势。

## 候选 D：word Switch 合并多个 scalar BUS driver

当前 13 只 U1 Switch 的 enable 分组为：

```text
bus18   {9, 1}
bus26   {18, 19, 21}
bus31   {26, 25}
bus68   {31, 65}
bus74   {73, 69}
bus80   {57, 78}
```

没有一个相同的公开 enable 节点跨两个 owner 重复。word Switch 只能用同一个 scalar
enable 控制全部 lane，所以不存在可直接合并的两条 driver。

即使存在共享 enable，成本也只是打平：

```text
k 只 U1 Switch                 2k gate
一只 Uk word Switch            2k gate
```

并且多个 scalar BUS 只有在完整 driver partition 也能统一时才能保持 raw Z；将 word
输出先 Splitter 再接回各 BUS 会把 Z 归零为 active，造成短路或改变 owner。

结论：当前 owner 集既无共同 enable，也无宽度折扣。

## 候选 E：把 S5 与 S7 合成 U2 owner

当前两个终端 owner 各有两只 Switch：

```text
S5 enables = {73,69}
S7 enables = {57,78}
```

四个 enable 全不同。若用四只 U2 Switch 覆盖两个 lane：

```text
当前 4 只 U1 Switch              8 gate
四只 U2 Switch                  16 gate
Maker2/Splitter2                 0 gate
净变化                          +8 gate
```

若缺少某 lane 的有效 driver，只能在该 lane 放 0/1 data；word Switch 开启时它仍是 active，
可能改变本来需要的 Z。S5/S7 的 false 行最终可被 Maker8 归零，但这不改变每个 Sum=1 行
必须有 active 1 且 owner 无冲突的要求。

结论：功能可按具体 data 重画，物理成本先验已经失败。

## 候选 F：把 S7 与 C8 合成双输出 owner

当前尾部为：

```text
S7 owner       2 * U1 Switch = 4 gate
Z7 node 78                     1 gate，S7/C8 共享
C8 node 79                     1 gate，C8 私有
```

向任何现有 S7 driver 增加一个 C8 lane，会把 U1 Switch 升为 U2 Switch，单个 driver
至少增加 `2 gate`。即使一条现有 enable/data 恰好足以覆盖所有 C8=1 行，最多只删除
C8 私有的 node 79 一门：

```text
最乐观净变化                  +2 - 1 = +1 gate
```

若 C8 需要两条 driver，则至少 `+4-1=+3`。node 78 不能顺便删除，因为它仍是 S7 第二
driver 的 enable。Cout 的 false-Z 宽松合同只允许 C8=0 行不驱动，不能免除 C8=1 行的
active-one coverage，也不能把 S7 owner 的 partial pin复用到第二个 BUS。

结论：线性 lane 成本已经排除直接 `S7/C8` owner 合并。

## 候选 G：当前 opaque Full Adder 双输出

当前有效 ABI 成本为：

```text
com_full_adder                 16 gate / 8 delay
public outputs                 Result, Carry out
```

从 arrival 0 的原始输入开始，输出也最早为 `@8`，已经超过整关 D6；接入任何内部 carry
只会更晚。两个输出都是 active ordinary owner，没有 Z/BUS 副作用可补偿时序。

结论：当前 imported frontier 下完全不可用。

## 候选 H：显式七门 Full Adder 多输出宏

把 Full Adder 拆平为七只合法普通门，可得到：

```text
G    = A AND B
K    = NOR(A,B)
P    = NOR(G,K)
PC   = P AND Cin
NPC  = NOR(P,Cin)
Sum  = NOR(PC,NPC)
Cout = OR(G,PC)

cost                           7 gate
A/B -> outputs                 4 delay
Cin -> outputs                 2 delay（G/K/P 已提前时）
```

`G/K/P/PC/NPC` 只有在七只门显式放置时才是公开输出；opaque Full Adder 不允许从内部
取线。逐位置换结果如下。

| 位置 | 当前边界 | 七门宏结果 | 审计结论 |
|---|---|---|---|
| bit0 | S0@4，早期 cause@1，C1/C2@2 | S0/C1@4，PC0@3 | 门数可降，早期链晚两层，D6 失败 |
| bit1 | C2 由三驱动 raw owner@2 直接编码 | Cout 最早@4 | B23/C6 链整体变晚，失败 |
| bit2/3 | B23@3 绕过完整 C3 | 完整 carry 最早@4 后再传播 | 失去 group bypass，失败 |
| bit4 | G/Q/P 已支付，当前 S4 tail 3 门 | PC/NPC/Sum/Cout tail 4 门 | C5 无外部消费者，净 `+1` |
| bit6 | C6@4，当前 S6 tail 3 门 | 还需 P6，tail 共至少 5 门 | 净至少 `+2`，C7@6 无法再驱动 bit7 |
| bit7 | 当前没有完整 C7 rail | 必须先新增 C7 | 新增 carry 的 gate/arrival 抵消双输出 |

其中 bit0 候选最值得明确记录。拆平当前 `S0 XOR(Cin,P0)` 会免费产生：

```text
PC0 = Cin AND P0                    @3
```

当前 node 18 的 data plane 是：

```text
T0 = Cin AND (A0 OR B0)             @1，4 gate raw owner
```

两者只在 `G0=1` 的行不同，而 node 26 的 C2 owner 已有独立 `G0` driver，node 36 也
显式 OR 了 G0。因此：

```text
G0 OR T0  = G0 OR PC0
V1*(T0 OR G1 OR G0) = V1*(PC0 OR G1 OR G0)
```

布尔和 owner coverage 均允许删除 node 18 的四门成本，得到纸面 `81 gate`。但 arrival：

```text
PC0                         3
node26 C2 owner             4   （当前 2）
node36 C1                   4   （当前 2）
node37/38/39/46 S1          5/6/5/7
```

`S1@7` 已直接失败；node31/C4/C6 与高位输出也继续后移。保留 node 18 给关键消费者时，
它仍有 fanout，四门不能删除，PC0 便不产生净收益。

结论：这是本轮唯一出现 `gate<85` 账本的真实多输出方案，但严格因时序不成立。

## 后续研究边界

本轮排除的是“依靠当前 ABI 免费或线性 word 机制，直接拿两个输出省一门”，不是
`84/6` 的全局不可达证明。下一步应保留以下边界：

1. 新架构必须产生一个 arrival `<=4` 的共享 rail，同时替代两个现有付费 phase/owner；
   `@5` 后再 NOT、AND 或 Switch 均会越过 D6。
2. Maker/Splitter 只应作为 raw-to-active owner barrier 使用，不应进入 Boolean gate
   计数优化器充当 driven/Z extractor。
3. word 结构只有在同时改变完整 owner partition 或版图时有价值；仅把 scalar 门装入
   lane 不可能减少 gate。
4. 若 Full Adder 关卡以后得到真实、服务端可导入的新 Pareto 点，必须按实际 opaque
   统一 input-output delay 重新审计；不能拿显式七门宏的短 Cin arc 冒充 opaque 元件 arc。
5. 真正可能到 `84/6` 的方向仍是跨 `C2/B23` 或 `C6/S6/S7/C8` 的早期状态重编码，
   不是再包装当前输出。

本轮没有完整 `<=84/6`，所以没有物化、没有覆盖候选或正式存档。
