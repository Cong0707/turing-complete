## 2026-07-31 / 提交：修复：校正字宽关卡端口并重构研究记录

### 子代理核验：字宽关卡输入端口

`com_level_input_word`（61）的引脚偏移与 `word_size` 无关，旋转 0 时固定为 `(3, 0)`。
证据包括：

- byte_not 的 8 位输入原点 `(-17, 0)`，导线端点为 `(-14, 0)`。
- byte_lsr 的 3 位 Shift 输入原点 `(-9, -18)`、旋转 1，导线端点为 `(-9, -15)`。
- 当前样本中 20 个 rot0/word8、1 个 rot1/word8 和 1 个 rot1/word3 的已连接实例全部
  符合三格偏移，没有发现反例。

rot2/rot3 由统一旋转函数推导为 `(-3, 0)`、`(0, -3)`，当前没有真实连接样本，因此仍需
以后使用隔离 fixture 验证，不能把推导冒充运行证据。

### 字宽关卡输出端口

`com_level_output_word`（69）旋转 0 时固定为 `(-3, 0)`。byte_not 的 8 位输出和
bit_adder 中 `word_size=1` 的 Sum/Carry 输出都证明距离为三格。

### 修改与边界

- 61/69 使用固定三格偏移，旋转继续复用统一坐标变换。
- `com_constant`（46）仍按常量显示宽度分档，它不是关卡 I/O 外壳。
- 增加多个现有 v15 基线的固定端口连通回归测试。
- 架构切换端口、程序端口、RAM 和显示元件仍需各自证据，不在本节推断。

## 2026-07-31 / 提交：功能：扩展多输入验证并生成第二批候选

### 八路关卡输出端口

`com_level_output_8`（40）在旋转 0 时有八个单比特输入，引脚位于本体左侧一格，纵向偏移
依次为 `-4..3`。当前 `decoder_3` 存档在八个坐标上均有独立导线端点，支持这一映射。

结构深度分析把该元件视为关卡观察端口，不额外增加逻辑深度。三位解码器候选因此只有
一个实际逻辑元件层级。

## 2026-08-01 / 提交：修复：校正字元件几何并重新生成候选

### 当前字元件宽体形状

对当前 v15 的 foundry/RISCV 电路、主线基线和官方提示端点交叉核验后，修正以下映射：

- 字 NOT/AND/OR/NAND/NOR/XOR/XNOR 与比较、取负：输出在右侧两格；双输入脚纵向为
  `-1/+1`。
- LSL/LSR/ROL/ROR/ASR：数据和位移输入为 `(-1,-1)`、`(-1,1)`，输出为 `(2,0)`。
- 字 MUX：三个输入保持 `x=-1`，输出为 `(2,0)`。
- 当前已观察的字常量宽度 2、8、16、64 均从右侧三格输出。

旧迁移电路中仍能看到落在右侧一格的导线端点，这些与当前引擎形状冲突，不能用于推翻
正在工作的 v15 foundry 电路和官方提示证据。相关候选已按新坐标重新生成。

## 2026-08-01 / 提交：功能：生成第三批候选并校正一位非门

官方 `always_on/hint_solution.data` 与当前 `xnor`、`second_tick`、`saving_gracefully` v15
电路共同证明：一位 NOT（3）的输入为 `(-1,0)`，输出为 `(2,0)`。同形状的一位 Switch
和字 Switch 输出也位于右侧两格。`decoder_1` 候选已按该坐标重建。

## 2026-08-01 / 提交：修复：自动识别旧版与新版 Foundry 端口跨度

同一个 `kind=79/81` 在当前现代 Foundry 中通常使用三格端口，但迁移保留的
`OVERTRUE`、`LEG/SWT` 等电路仍可能使用一格端口。`positioned_pins()` 默认继续返回现代
三格位置；`analyze_connectivity()` 则同时计算一格和三格候选，并以真实导线端点唯一命中的
跨度为准。

这项修改只影响离线分析，不改写元件或存档。若两个跨度都没有命中或同时命中，分析器保持
现代三格默认值，避免在证据不足时擅自降级。新增测试分别覆盖一格旧端口和三格现代端口。
