# 候选电路生成器

## 2026-07-31 / 提交：功能：生成首批排行榜候选电路

## 提交目的

验证项目已经能够从“解析和分析”进入“可重复生成新电路”，同时坚持不启动游戏、
不写正式存档和不复制游戏提示方案。

## 生成框架

- 稳定永久 ID 由 `SHA-256(project namespace + level + logical name)` 派生。
- 布线路径由顶点序列生成，只接受水平、垂直和 45 度线段，相邻同方向自动合并。
- 候选继承该关 baseline 的容器头、custom ID 和 design，但元件及导线完全由配方重建。
- 固定端口从 `scaffold/immutable.json` 加载，保持游戏永久 ID。
- 写入 `candidate/circuit.data` 前必须满足：受支持元件、所有引脚连接、无组合环、
  v15 编码后反解析完全一致。

## 第一批关卡

- `or_gate_3`：两个 OR，声明 `2/2/4`。
- `and_gate_3`：两个 AND，声明 `2/2/4`。
- `xnor`：AND 与 NOR 并行后 OR，声明 `3/2/6`。

三项均达到总榜前 12 名公开 profile 联合样本中的最低能耗代表。每关的具体灵感、
布局和验证结果记录在自己的 `history/` 目录。

## 限制

容器内的 gate/delay 是声明值，不能替代游戏运行测试。候选只进入项目目录；正式存档
写回必须等用户明确验收阶段，并继续经过游戏未运行检查和原子替换。

## 2026-07-31 / 提交：功能：扩展多输入验证并生成第二批候选

## 第二批关卡

- `byte_mux`：单个 8 位 MUX，声明 `33/2/66`。
- `byte_xor`：单个 8 位 XOR，声明 `24/2/48`。
- `decoder_2`：单个二位解码器，声明 `4/2/8`。
- `decoder_3`：单个带 Disable 的三位解码器，声明 `14/3/42`。
- `signed_negator`：单个 8 位取负器，声明 `24/5/120`。

生成器的配方现已改用标签化多输入定义，输出标签也不再固定为 `Output`。这使 `Result`
命名和 A/B/Select 等多端口关卡可以使用同一验证流程。

## 2026-08-01 / 提交：功能：生成第三批候选并校正一位非门

## 第三批关卡

- `byte_less_s`：双 XOR 翻转符号位后无符号比较，声明 `90/4/360`。
- `byte_lsr`：单个 8 位 LSR，声明 `70/3/210`。
- `full_adder`：单个全加器，同时验证两路输出，声明 `14/3/42`。
- `one_hot_encoding`：常量 1、LSL、Splitter，声明 `70/3/210`。

没有当前存档 baseline 的关卡使用干净的 v15 默认容器，再注入官方不可变脚手架；不会为了
继承头字段而读取或改写正式存档。
