# 排行榜公开榜页采集器

## 2026-08-01 / 提交：功能：建立单关公开榜页采集器

早期目标文件只联合总榜前 12 名玩家的公开 profile，因此只能证明“顶尖样本中的最好成绩”，
不能证明单关榜当前前沿。官网同时公开每个关卡的榜单页面：

```text
https://turingcomplete.game/leaderboard/{level_id}
```

`tc-save scrape-leaderboards` 直接解析这些公开页面，保留当前公开最低能耗、榜页可见最低门数、
可见最低延迟和可见非支配点。组件关使用 `gate/delay` 两个维度；程序关额外加入 `cycle`。

2026-08-01 实测单关页面最多返回 1000 行，并按能耗排序。工具记录 `row_count` 与
`page_cap_suspected`，不会把页面外没有返回的玩家或方案冒充为已经遍历。

单关榜的每位玩家只显示其用于能耗排名的一条记录；同一玩家的低延迟或低门数替代解只出现在
profile 的 Pareto 前沿。因此：

- `global_energy_rank1` 可用于核对当前公开能耗冠军。
- `visible_best_gate`、`visible_best_delay` 和 `visible_pareto` 只描述榜页返回的能耗代表解。
- 现有 profile 采样中的其他 Pareto 点不能被榜页结果覆盖。
- 要证明全体玩家所有方案中的绝对最少门数或最低延迟，仍需抓取对应 profile 前沿。

定点刷新重点关卡：

```powershell
.\.venv\Scripts\tc-save.exe scrape-leaderboards byte_adder signed_negator byte_less_u
```

刷新 `examples/leaderboard-targets.json` 中列出的全部可计分关卡：

```powershell
.\.venv\Scripts\tc-save.exe scrape-leaderboards --all
```

默认结果写入 `examples/leaderboard-live.json`。请求之间默认等待 1.2 秒，并发送
`Connection: close` 以规避站点长连接偶发不结束的问题。工具同时校验
`energy = gate * delay * cycle`（组件关省略 cycle）；网络或数据错误会记录在输出的
`errors` 字段，不会用旧样本静默冒充新结果。
