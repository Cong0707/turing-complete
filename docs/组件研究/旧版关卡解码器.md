# 旧版关卡解码器

## 2026-07-31 / 提交：功能：解析旧版主线关卡电路

## 提交目的

让项目能独立读取最新版游戏目录中仍以旧格式保存的关卡脚手架与提示方案，为后续
提取 immutable 输入输出、建立连通网络和自动生成候选电路提供统一模型。

## 格式证据

本次以游戏生产环境实际使用的
[`Stuffe/save_monger`](https://github.com/Stuffe/save_monger) 为主证据。该仓库 README
明确说明它是 Turing Complete 用来加载和保存游戏状态的生产代码，并以 CC0 发布；
其中 `versions/v7.nim`、`versions/v13.nim`、`versions/v14.nim`、`versions/v15.nim`
给出了逐字段读取顺序。研究副本仅位于被 Git 忽略的 `.research/`，没有复制第三方
实现代码进入项目。

当前安装目录的主线静态资源同时存在 v7、v13、v14、v15。主要差异为：

- v7 头部仍有 camera position，导线使用 3 位方向 + 5 位长度的单字节段，并支持
  一个特殊的断开导线表示。
- v13 元件只保存一个 label 字符串，没有独立成本变体字段。
- v14 增加 `cost_gate`、`cost_delay`，但仍只有一个 label 字符串。
- v15 才同时保存 `user_label` 与 `custom_string`，也是本项目唯一允许写出的版本。

## 修改点

- 新增 v7、v13、v14 严格只读解码器和 `decode_circuit` 统一分发。
- 旧版字段映射到现有无损模型；v7 的断开导线单独保留 `teleport_end`，禁止被 v15
  写出器静默降级。
- `validate` 与 JSON 导出可以读取支持的旧版本；构建和正式存档写回仍严格限定 v15。
- 增加全量安装资源测试，逐个解析所有受支持的 `circuit.data` 和
  `hint_solution.data`，并要求解析结束时不存在尾随字节。
