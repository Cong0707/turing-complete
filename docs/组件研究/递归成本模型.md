# 递归成本模型

## 2026-07-31 / 提交：功能：建立自定义元件递归成本报告

## 目标

Custom 元件的 `kind=78` 只保存 `custom_id`，单看实例无法知道真实门数。该工具只读扫描
`schematics/foundry`，建立 `custom_id -> circuit.data` 索引，然后按实例数量递归展开门数。

## 算法

- 每个自定义电路的 `gate`/`delay` 头部值视为游戏写入的实测结果。
- 直接子元件由 `kind=78` 和 `custom_id` 统计；`dependencies` 必须与直接 ID 集合一致。
- `local_gate_excluding_children = header_gate - sum(child_header_gate * count)`。
- 递归门数为本地门数加所有子元件的递归门数；缺失依赖、重复 ID 和依赖环都使报告不健康。
- 延迟不被伪造为简单相加；报告保留头部实测值，并明确递归关键路径尚未重建。

## 当前存档只读扫描

执行：

```powershell
.\.venv\Scripts\tc-save.exe analyze-costs `
  --root "$env:APPDATA\Turing Complete\schematics\foundry" `
  --output .research\foundry-costs.json
```

结果扫描 45 个自定义电路：重复 ID、缺失依赖、依赖环和 v15 解码错误均为 0，所有递归门数
与头部门数一致。代表性证据包括 `REGUNIT=1496/11`、`RegisterPlus64=1088/6`、
`REGFILE=47872/11`（32 个 REGUNIT）以及 `architecture/RV64=235437/2773`。

## 边界

报告不会修改正式存档，也不会把估算的延迟写回候选。只有游戏自身重新计分后，排行榜成绩才
具有最终效力。
