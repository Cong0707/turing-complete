# 2026-07-31 / 0004 / 主线固定脚手架提取

## 提交目的

为每个主线关卡建立可复现的固定接口描述，使候选生成器不必复制游戏资源，也不会
因为 baseline 是否已经保存输入输出元件而产生重复永久 ID。

## 修改点

- 新增 `tc-save extract-scaffolds`，从 92 个主线 `campaign/<level>/circuit.data`
  读取 immutable 元件，并写入对应的 `examples/<level>/scaffold/immutable.json`。
- 每条记录保留元件 kind、位置、旋转、永久 ID、位宽、链接和成本等生成候选必需
  字段，同时记录源版本、大小和 SHA-256。
- 不复制 `circuit.data`、`meta.txt`、`test.si` 或提示方案。campaign 中的非固定
  教学种子元件和导线只记录数量，不作为脚手架发布。
- 读取现有 baseline 后仅记录与脚手架相交的永久 ID。后续规范化候选时可以删除
  这些重复元件，而不依赖某个游戏版本恰好如何保存固定接口。
- 固定元件永久 ID 必须非零且关卡内唯一；违反该条件时提取立即失败。

## 当前数据

- 主线关卡：92。
- 静态格式：v7 15 关、v13 18 关、v14 57 关、v15 2 关。
- immutable 元件：406 个。
- 静态脚手架为空：15 关，均为架构或编程类关卡，接口由所选架构和测试运行时提供。

## 安全边界

提取命令只读取游戏安装目录和项目中的 baseline，仅写入项目 `examples/`。本次没有
启动游戏，没有读取或修改正式存档，也没有创建备份。
