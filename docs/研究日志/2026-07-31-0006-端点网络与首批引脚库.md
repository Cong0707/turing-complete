# 2026-07-31 / 0006 / 端点网络与首批引脚库

## 提交目的

把几何指标提升为可审计的逻辑连接图，同时明确区分导线交叉和实际接点，为后续关键
路径、逻辑等价检查和自动布线提供基础。

## 关键修正

研究现有转换工具和实际方案后确认：网络按导线端点合并。两条导线的内部路径在同一
格交叉，只是几何交叉；若没有公共端点，不能直接视为同一逻辑网。上一阶段的网络数
采用任意路径点相交，现改为：

- `endpoint_junction_count`：真正参与网络合并的公共端点。
- `path_intersection_point_count`：用于整线审查的几何交叉/重叠点。
- `network_count`：只按公共端点计算。

## 首批引脚库

- 覆盖基本 bit 门、word 逻辑、加减比较、乘除、移位、Mux、Decoder、Full Adder、
  常见主线输入输出。
- 坐标旋转规则按当前 circuit 的 0/1/2/3 四向变换实现，并用现有方案端点验证。
- word 引脚宽度来自元件 `word_size`，多位输入输出的外形距离按 1/8/16/32/64 位
  分档。
- 未覆盖的 RAM、Custom、复杂时序和显示元件只进入
  `unsupported_component_kind_counts`，绝不猜测引脚。

## 新指标

- 已连接/未连接引脚及具体位置。
- 无驱动、无接收、多驱动、位宽冲突网络。
- 元件逻辑边数、单位门深度、环路涉及的元件数。
- 分析普通方案时会从 `scaffold/immutable.json` 补入缺失的固定端口，并按永久 ID
  去重；不会把固定元件写回候选。

单位门深度目前把每个受支持的组合元件视为 1，不冒充游戏的真实 delay。真实成本
和关键路径权重需要下一阶段从解锁元件成绩及 Custom 依赖中递归构建。
