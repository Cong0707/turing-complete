# 随机数生成器研究资料索引

本目录保存从 `396 / 10 / 66` 到实机榜一 `245 / 7 / 66` 的可复核材料。
最终事实以游戏通过全部测试后保存的
`../candidate/circuit.data` 为准；生成器声明、静态成本表和求解器输出均不能覆盖实机结果。

## 最终成果

- 实机与排行榜：`245 gate / 7 delay / 66 cycle = 113190 energy`。
- 正式电路 SHA-256：
  `15E1BAA8D2AC7599592417534CED3E4583B87D9823D80AB6B509DEE47AE8F069`。
- 电路规模：122 个元件、278 条导线。
- 拓扑：自然状态 xorshift32、32 个种子装载 OR、61 个 U1 Word XOR、一个
  `kind 118 + kind 54 + kind 56` 原生 RAM 组。
- `archive/rng_natural_ram_u1/` 是最终生成路线的原始脚本、候选和审计结果。
- `src/tc_save_lab/rng_natural_ram_asic.py` 是整理后的可复现生成器，已把实机门数修正为 245。

## 目录说明

`archive/` 按原 `.research/rng_*` 相对路径保存研究现场，主要包括：

- GF(2) 状态重编码、特征多项式、联合 B/C 网络和 XOR 深度搜索；
- SAT、MaxSAT、Z3 与启发式搜索脚本及紧凑证书；
- Switch 高阻语义、单输入/单输出协议和 42 状态路线；
- 原生组件成本、RAM 模式、RAM 端口、同拍读写顺序和精灵几何的静态审计；
- 各阶段候选 `circuit.data`、结果 JSON 和失败报告；
- 最终自然状态 RAM8 生成器、拓扑转储和原生计分审计。

`archive-manifest.json` 记录每个纳入文件的大小和 SHA-256。`prepare_archive.py`
可以从原研究目录重新生成同样的筛选归档。

## 未纳入 Git 的内容

以下内容体积大、可再生成或不属于有效游戏解，因此只在清单中按类别统计：

- IDA `.i64` 数据库、Python 缓存、对象文件、可执行文件和 vendored 第三方包；
- 数百 MB 的 `.jsonl` 求解轨迹与 PLA 中间网络；
- 需要重新运行求解器才能使用的大型日志；
- 修改计分字段、认证状态或请求数据的无效实验。

服务端会重新执行并计分，本地伪造不是可提交方案。归档中来自
`rng_score_bypass` 的文件仅保留 RAM 和成本函数的只读静态反编译证据，不保留认证、提交或
伪计分工具。

## 复验

在项目虚拟环境中运行：

```powershell
& '.\.venv\Scripts\python.exe' -m unittest `
  tests.test_rng_natural_ram_asic `
  tests.test_rng_ram_asic `
  tests.test_architecture_candidates
```

生成一份规范编码候选：

```powershell
& '.\.venv\Scripts\python.exe' -m tc_save_lab.cli `
  build-architecture-candidates rng
```

规范编码候选与游戏紧凑重写后的文件可以有不同字节哈希。复验时应分别检查：

1. `components` 与 `wires` 结构完全相同；
2. 游戏重新计算为 `245 / 7 / 66`；
3. 256/256 测例通过；
4. 排行榜接受服务端重算结果。

## 历史脚本警告

`archive/` 是研究现场，不是稳定 API。部分脚本包含机器绝对路径，部分候选已被证明错误，
部分 `install_candidate.ps1` 会直接覆盖存档。运行前必须先阅读同目录的 `RESULT.md` 或
结果 JSON。当前可维护入口只有项目 `src/tc_save_lab/` 下的模块。
