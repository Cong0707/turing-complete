# 随机数生成器：单输出协议与零初态初始化

## 2026-08-02 / 研究：排除双输出并校正首拍控制

### 运行时事实

- 当前关卡只允许一个 Architecture Output，因此每个仿真周期最多调用一次
  `arch_check_output`；双输出降周期路线不成立。
- `campaign/rng/test.si` 的 `arch_get_input()` 每次都返回同一个
  `initial_seed`。输入不是一次性队列，只要 Architecture Input 的 U1 control
  精确为 `1`，本周期就能再次取得相同 seed。
- Architecture Output 的 U1 control 精确为 `1` 时，本周期调用一次
  `arch_check_output(value)`；control 为 `0` 时不调用。
- `count` 从 0 开始，检查正确结果后在 `count == 64` 时返回 `win`，所以必须依次提交
  `F(seed)` 到 `F^65(seed)`，总计 65 次回调。单输出方案的周期下界因此是 65。
- 最新版实机已经证明：Delay Bit 保存数据中的 `init_data=1` 不能作为首周期高电平保证。
  当前失败电路在首周期观察到 phase 为 0，因而没有读取 seed，却开启输出并提交 0。

### 保持 396 门编码数据通路时的正确首拍

不得使用非零寄存器初态。使用一个从零开始的 phase Delay Bit：

```text
Constant 1 -> phase Delay Bit(init_data=0)
phase       -> Architecture Output.control
phase -> NOT -> Architecture Input.control
```

精确拍序：

| 仿真周期 | phase | Input control | Output control | 数据动作 |
| ---: | ---: | ---: | ---: | --- |
| 0 | 0 | 1 | 0 | 读取 seed，状态 Delay 捕获 `T(seed)`，不检查输出 |
| 1 | 1 | 0 | 1 | 输入关闭，提交 `F(seed)` |
| 2..65 | 1 | 0 | 1 | 依次提交 `F^2(seed)..F^65(seed)` |

这正是提交 `f78b926` 中原有的控制连接。生成器应恢复：

```python
one = component("initialize-one", 2, ..., init_data=0)
phase = component("ready-delay", 13, ..., init_data=0)
not_phase = component("not-ready", 3, ...)

one.out       -> phase.in
phase.out     -> not_phase.in
not_phase.out -> level_input.control
phase.out     -> level_output.control
```

全部 32 个状态 Delay Bit 也保持 `init_data=0`。这一路径用 1 个装载周期加 65 个输出周期，
总计 66 周期。它不依赖 seed 的具体值，也不依赖任何非零寄存器初态。

当前失败连接恰好相反：`phase.out -> input.control`、`NOT phase -> output.control`，而 phase
首周期实际为 0，并且其输入是 Constant 0，因此 phase 永远保持 0。结果就是输入永远不调用、
输出从首周期起一直调用并提交零。

### 重新综合时的 65 周期零相位方案

RNG 输入可每拍重复读取同一个 seed，所以理论上的最短初始化根本不需要 phase 寄存器：

```text
Architecture Input.control  = Constant 1
Architecture Output.control = Constant 1
全部状态寄存器初态          = 0
```

令 `s` 为持续可用的 seed、`A` 为 xorshift32 线性变换、`T` 为任意可逆状态编码，并定义：

```text
q_t = T * (x_t xor s), q_0 = 0
B   = T * A * T^-1
D   = T * (A + I)
C   = A * T^-1

output_t = C*q_t xor A*s
q_(t+1)  = B*q_t xor D*s
```

周期 0 时 `q_0=0`，所以直接提交 `A*s = F(seed)`；周期 1..64 提交后续 64 项，
第 65 次回调在周期 64 获胜，总周期严格为 65。该协议完全依赖零初态，不依赖
`init_data=1`，也不需要初始化相位元件。它是后续联合状态重编码/联合 XOR 综合应使用的
测试模型；现有 396 门双模网络不能只改控制线就实现它，必须重新综合 `B*q xor D*s` 与
`C*q xor A*s` 的共享网络。

### 生成器与离线测试必须加入的断言

1. 部署候选中 Architecture Output 恰好一个。
2. 任何 Delay Bit 的 `init_data` 都必须为 0；测试不得用 `initial_clocked_memory()` 注入 1。
3. 66 周期兼容方案首周期必须出现一次输入回调、零次输出回调，随后每周期零次输入、
   一次输出。
4. 65 周期持续 seed 方案每周期必须出现一次输入回调和一次输出回调，共 65 周期。
5. 输出序列必须严格为 `F(seed)..F^65(seed)`；首周期提交 0 必须立即判错。
6. control 按 U1 的精确值 `== 1` 建模，不把非零宽值、Z 或未驱动网络当作 enable。
