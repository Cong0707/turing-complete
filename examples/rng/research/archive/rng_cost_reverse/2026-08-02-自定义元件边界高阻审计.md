# RNG 自定义元件边界高阻审计

## 结论

最新版 `2.1.281` 中，Foundry 自定义元件的输入边界不能把调用者网络的高阻态 `Z`
复制到元件内部。编译预处理生成的 `com_cc_input_buffer`（kind 80）把输入数据面写成一个
始终主动驱动的普通输出。因此不能利用“一个自定义输入、多个自定义输出”零成本复制
Architecture Input 的 `Z`，现有放宽模型中的 `427 / 9 / 66` 仍然不可物理实现。

## 决定性证据

只读分析对象：

```text
D:\Game\Steam\steamapps\common\Turing Complete\Turing Complete.exe.i64
add_circuit_code: 0x140441388
store_output:     0x140437079
```

组件调度中：

```text
kind 79 com_cc_input       -> 默认空分支，由编译预处理消费
kind 80 com_cc_input_buffer-> 0x140479513
kind 81 com_cc_output      -> 默认空分支，由编译预处理消费
```

kind 80 在 `0x140479591` 构造 `input(...)` 数据表达式，随后在 `0x1404796b0` 至
`0x1404796c2` 为 `store_output` 构造 drive-enable 字符串。对应静态对象为：

```text
TM__THWBxVSaWN2Zh7OMooFH0w_1961 @ 0x140a2a540 = 0
off_140A2A548                    @ 0x140a2a548
```

即 drive-enable 字符串长度为零。`store_output` 的反编译结果在 `code_gen.nim:272-273`
明确执行：

```c
if (!drive_enable.length) {
    drive_enable = "1";
}
```

普通 Bit Splitter 的输出使用相同空字符串约定；Bit Switch 则传入真实 enable 表达式。
所以 kind 80 与 Splitter 一样无条件主动驱动，而不是高阻感知缓冲器。

## 对 RNG 的影响

以下设想被排除：

```text
U32 三态 seed -> 零成本自定义扇出 -> 多个相互隔离的 EARLY seed 网络
```

进入自定义元件时，seed 的 `Z` 只剩数据面零；kind 80 随即把零重新主动驱动。稳态再与
不同状态 Switch 输出并网仍会短路。若要隔离每个副本，仍必须支付独立三态驱动成本。

可继续保留的 Switch 方向只有：

1. 在 U32 层、任何 Splitter 或自定义边界之前完成唯一一次三态合流；
2. 重新综合满足物理一一匹配的 seed/state 网络；
3. 直接综合共享 enable 的多驱动共识网络，而不是假定免费传播 `Z`。

遗留 `idat64` 进程。
