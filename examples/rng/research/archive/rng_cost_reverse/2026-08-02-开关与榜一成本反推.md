# RNG 开关与榜一成本反推

## 2026-08-02：结论

最值得优先验证的 `431 gate / 9 delay / 66 cycles` 结构不是 42 位冗余状态，
而是下面这条 **32 位三态共用总线**：

```text
Level Input --Z--+                         +--> U32 Delay --> q
                 +--> r --> A(r), delay 4 -+
q --> U32 Switch-+                         
                 +----------------------------> Level Output
```

控制时序：

```text
tick 0: input enable=1, feedback switch=0(Z), r=seed
        U32 Delay 捕获 A(seed)，Level Output 关闭

tick 1: input enable=0(Z), feedback switch=1, r=q=A(seed)
        Level Output 输出 A(seed)，U32 Delay 捕获 A^2(seed)

...

tick 65: Level Output 输出 A^65(seed)
```

这里 `A` 是关卡要求的原始 `xorshift32`：

```text
x ^= x >> 13
x ^= x << 17
x ^= x >> 5
```

这是一条真实游戏电路路线：只使用原生元件语义，不修改文件头成本、不改关卡、
不绕过验证，也不依赖服务端协议。

## 精确成本与延迟

固定部分：

| 部分 | gate | delay |
|---|---:|---:|
| U32 状态 Delay | `32*5 = 160` | 4 |
| U32 feedback Switch | `32*2 = 64` | 1 |
| phase Delay + NOT | `5+1 = 6` | 控制路径 5 |
| **固定小计** | **230** | |

榜一余下的组合逻辑预算恰为：

```text
431 - 230 = 201 gate
9 - 4 - 1 = 4 delay
```

因此只要找到一张真实的：

```text
A(x): 32 bit -> 32 bit
gate <= 201
delay <= 4
```

组合网，就能完整解释 `431/9/66`。

若组合网只用 `XOR2=3/2` 和公开 `XOR3=12/2`，则：

```text
3*xor2 + 12*xor3 = 201
xor2 + 4*xor3 = 67
```

其中最醒目的指纹是：

```text
47 XOR2 + 5 XOR3 = 47*3 + 5*12 = 201
160 + 64 + 6 + 201 = 431
```

反馈关键路径和控制关键路径都正好为 9：

```text
q path:     Delay 4 + Switch 1 + A network 4 = 9
ready path: Delay 4 + NOT 1    + A network 4 = 9
```

## 为什么 Switch 线索高度吻合

### 1. U32 Switch 完成装载/反馈合流

关闭的 Switch 输出 Z，因此 Level Input 与反馈能直接驱动同一条 U32 网络；
两个驱动永远互斥，不需要 32 个 OR。普通 Splitter 不传播 Z，所以必须先在 U32
总线上合流，再拆位进入 `A` 网络。

仓库已有的 `src/tc_save_lab/rng_asic.py` 候选已使用同一种 U32 三态合流，只是它先把
seed 存入 Delay，再以三层 canonical XOR 计算输出，离线计分为 `413/11/66`。
本反推把 `A` 放到 Delay 前、把共用总线直接送到输出；协议仍是 1 拍装载、65 拍输出。

### 2. FermiEnergy 的 XOR3 本身依靠 Switch

并列榜一 FermiEnergy 公开的 XOR3 是精确的 `12 gate / 2 delay`：

```text
4 Bit Switch + 3 NOR + 1 AND
= 4*2 + 3*1 + 1*1
= 12 gate
```

其四个互斥驱动为：

```text
c  when NOR(a,b)   # 001
b  when NOR(a,c)   # 010
a  when NOR(b,c)   # 100
a  when AND(b,c)   # 111
```

奇校验时恰有一个 Switch 驱动 `1`；偶校验时所有 Switch 都关闭，公共输出网由
无驱动态解析成 `0`。它不是普通 OR 拼接，而是直接利用 Z 构造互斥多驱动网络。

证据文件：

```text
.research/hub-entry-53/dependencies/00/XOR7/XOR3/circuit.data
SHA-256 2A82925A48CBF20AEB4CB9D9BCA83FEB51F56FFB0537EBFCF56FE00677164D69
```

同一作者还公开了 7 输入 XOR；而自然态 `A` 的最大输出支持度正好为 7。
这只是相关性证据，不是榜一原图泄露或结构证明。

## 两层 XOR 检查

新增低内存模型：

```text
.research/rng_cost_reverse/search_partition_mixed.py
```

模型允许：

- 第一层任意无抵消的 XOR2/XOR3 形式；
- 第二层 XOR2/XOR3；
- 第一层形式跨 32 个输出任意共享；
- 末级直接复用第一层输出；
- 精确统计 XOR2/XOR3 数量。

规模：

```text
463 个可共享第一层形式
1486 个输出实现选项
```

结果：全部 17 组满足 `3*xor2+12*xor3=201` 的计数组合均为 `UNSAT`，包括：

```text
47 XOR2 + 5 XOR3: UNSAT
```

这严格排除的是 **无抵消的集合分割模型**。它不能排除：

- 首层形式含目标支持集外的位，再在末级抵消；
- XOR3 内部的 NOR/AND/Switch 控制被多个输出交叉共享；
- 不封装成 XOR2/XOR3 的一般三态布尔网络；
- 改变 32 位内部状态编码或增加隐藏状态。

原有完整抵消模型位于：

```text
.research/rng_xor3_retime/depth2_mixed/search_depth2_mixed.py
```

它在更宽松的 `233 gate`、30 秒条件下仍是 `unknown(timeout)`，不是 UNSAT。
本轮尝试过更直接的完整抵消枚举，但建模进程增长到约 1.57 GB，已立即终止并删除
该实现；没有继续消耗内存，也没有把结果写成证明。

复现低内存精确项：

```powershell
.\.venv\Scripts\python.exe `
  .research\rng_cost_reverse\search_partition_mixed.py `
  --exact-xor2 47 --exact-xor3 5 --max-cost 201 `
  --output .research\rng_cost_reverse\exact-47-5.json
```

## 其它恰好命中 431 的指纹

### 47 个双模选择点

当前 `396/10/66` 的固定部分为：

```text
32 Delay + 61 XOR2 + phase Delay + NOT = 349 gate
```

若仍保留 47 个选择点，且每点只能是 OR 或 Switch：

```text
or + switch = 47
or + 2*switch = 431 - 349 = 82
```

唯一解：

```text
12 OR + 35 Switch
```

数字很漂亮，但不能把现有 35 个 OR 机械替换成 Switch。拆位后的 seed 和 q 都是
主动驱动；只隔离其中一边会在 seed=1 或 q=1 时与另一边的 0 驱动冲突。合法实现必须
在字级三态合流、使用成对互斥驱动，或完全重做双模 DAG。

### 42 个数据状态位

另一条纯成本恒等式是：

```text
42 state Delay + 61 XOR2 + 32 OR + phase Delay/NOT
= 42*5 + 61*3 + 32 + 6
= 431
```

但它不使用 Switch，与榜一提示不符。现有 42 状态搜索的严格见证仍需 74/75 XOR，
非强模型前沿还有 3 个 weight-5 行，未达到 61 XOR；该方向没有全局 UNSAT，
但优先级应低于共用三态字总线。

### 从 381 基线做局部替换

若假定一只 XOR3 恰好替换两只 XOR2，且增加 Delay/Switch，则成本方程为：

```text
5*extra_delay + 6*xor3_collapse + 2*extra_switch = 50
```

`4 extra Delay + 5 XOR3` 是其中一个精确解。但已有严格 retiming 证书证明：
对 canonical 61-XOR DAG，仅做局部 XOR3 折叠和同步 retiming 时，组合周期 5 至少需要
17 个 XOR3；所以该漂亮指纹不能直接套在标准 DAG 上。
