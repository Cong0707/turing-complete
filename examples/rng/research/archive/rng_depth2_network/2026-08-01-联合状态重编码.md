# 随机数生成器：联合状态重编码

## 2026-08-01：二层异或网络边界

### 结论

本轮没有找到 `67 XOR` 的完整联合编码，因此没有生成或写入游戏存档。

得到了一份可逐门验证的严格上界：

| 部分 | XOR 数 | 最大 XOR 深度 |
|---|---:|---:|
| 种子编码 `T` | 34 | 2 |
| 反馈 `B=TAT^-1` 与输出 `C=AT^-1`，完全共享 | 61 | 2 |
| 把 `T/B/C` 的相同线性形式作理想化全局共享 | 95 | 2 |

这里的“理想化全局共享”已经比真实电路更宽松：它假定初始化阶段和运行阶段只要线性形式相同，就能复用同一个 XOR 节点，而且没有计入为此需要的额外选择器。即便如此仍需 `95 XOR`，比目标多 `28 XOR`。

按当前已确认成本模型估算：

```text
32 Delay Bit = 160 gate
32 Switch Bit = 64 gate
95 XOR = 285 gate
初始化控制 = 6 gate
总计 = 515 gate
```

因此该构型可以解释 `delay=9` 的实现方式，但不能解释榜首的 `431/9/66`。

### 自然状态的严格障碍

令自然状态变换为：

```text
A(x) = S3(S2(S1(x)))
S1 = I + R13
S2 = I + L17
S3 = I + R5
```

直接把 32 个自然状态位作为组合网输入时，`A` 的 32 个输出行支持度分布为：

```text
weight 3: 5 rows
weight 4: 12 rows
weight 5: 3 rows
weight 6: 10 rows
weight 7: 2 rows
```

二输入 XOR 的两层网络中，每个输出最多依赖四个原始输入：第一层节点最多含两个输入，第二层最多合并两个第一层节点。因此 15 个支持度大于 4 的输出给出严格反证：

```text
32 个自然状态位 -> A -> 32 个下一状态位
```

不存在任何纯二输入 XOR、深度不超过 2 的实现，门数再多也不能改变该结论。必须改变跨拍状态编码、引入已寄存的线性形式，或使用 XOR 之外的游戏语义。

### 可行编码

取：

```text
T = (I + R17)(I + R13)
q = T x
C = A T^-1
B = T A T^-1 = T C
```

此时：

```text
T 行支持度：1x13, 2x4, 3x13, 4x2
C 行支持度：1x5, 2x12, 3x5, 4x10
B 行支持度：1x5, 2x8, 3x5, 4x14
```

所以三张矩阵都能独立映射为二层 XOR 网络。脚本会验证：

```text
C*T == A
T*C == B
T*T^-1 == I
```

还会逐门检查每个门的两个输入都已存在、输出向量确实等于两输入异或，并检查所有目标行均被覆盖。

### 固定编码的门数证明

对支持度不超过 4 的目标行，二层网络可规范化为：

1. 第一层生成若干输入位对的 XOR。
2. 第二层把两个原始输入或第一层节点合并为目标行。

每个非直通且互不相同的目标行至少需要一个门。额外成本只来自不是目标输出、但必须在第一层生成的输入位对。

本目录脚本内置三组具体的第一层配对证书：

```text
T:   19 个非直通目标 + 15 个额外配对 = 34 XOR
B/C: 46 个非直通目标 + 15 个额外配对 = 61 XOR
T/B/C 联合：65 个非直通目标 + 30 个额外配对 = 95 XOR
```

安装可选的 `z3-solver` 后，脚本能重新建立“每个目标从三个二分方案中至少选一个”的集合优化问题，并证明上述额外配对数量是该固定编码的最小值。Z3 只用于证明最小值，普通证书验证仅使用 Python 标准库。

### 受限族穷举

脚本穷举下列 `63 x 63 = 3969` 个有序编码：

```text
T = Q P
P,Q in {I, I+Rk, I+Lk | 1 <= k < 32}
```

同时要求 `B` 与 `C` 的每一行支持度不超过 4。唯一通过的有序写法是：

```text
R13 -> R17
R17 -> R13
```

右移算子可交换，所以两种写法实际上是同一个 `T`。这严格排除了“换成另外两个全宽移位剪切就能降到 67”的方向，但不是对任意可逆 32x32 编码的全局排除证明。

### 后续方向

- 榜首 `431/9/66` 若确实等价于 `67 XOR`，很可能没有为任意种子单独实现静态 `T`，而是利用初始化拍的三态、开关或状态时序复用。
- 下一轮应把“初始化拍允许不同连接关系”直接纳入综合模型，不再把它抽象成一张必须常驻的 `T` 网络。
- 也应核实 `431` 的元件分解；仅凭总分反推 `67 XOR` 并不是唯一分解。
- 任意新候选仍必须把种子装载、65 次输出和游戏静态延迟一起验证，不能只证明稳态矩阵关系。
