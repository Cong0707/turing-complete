# 随机数生成器：九延迟相位注入

## 2026-08-01：固定 61-XOR DAG 的严格控制路径

### 最终结论

本轮的 `78` 成本结果只在“Splitter 能零成本复制并隔离高阻 seed”这一放宽模型中成立，
**不能实装为当前游戏可用的 `427/9/66` 电路**。

对最新版可执行文件的 code generation 路径做只读核验后确认：

- kind17 / kind99 Splitter 的输出模板不调用 `get_output_z_value`；
- `store_output` 的高阻控制参数为空，Splitter 输出属于无条件驱动；
- kind12 Bit Switch 才会把 `enable` 作为高阻控制，disable 时输出 Z；
- 多驱动网络本身允许编译，但两个启用驱动值不同时会被运行时判为短路。

决定性二进制证据（Turing Complete 2.1.281）：

```text
EXE SHA-256: C93F5E8E826050C3F92E2B3891D26FCDFC933658614185CB9B2EB6A34C5B8D1C
store_output: 0x140437079
空第 5 参数在 0x1404377D2..0x1404377FB 被替换为字面量 1

kind17 Splitter Bit 8 的第 5 参数为空：
0x140A294B0, 0x140A294E0, 0x140A29510, 0x140A29540,
0x140A29590, 0x140A295E0, 0x140A29630, 0x140A29680

kind99 Splitter Word4 的第 5 参数为空：
0x140A297B0, 0x140A29800, 0x140A29850, 0x140A298A0

kind12 Bit Switch 对照：input0 作为第 5 参数（drive-enable），input1 作为值
```

生成逻辑等价于 `if enable != 0`，即 `_is_z = !enable`。Splitter 的空参数被固定成 1，
所以其输出 `_is_z=false`；Bit Switch 才会随 enable 进入 Z。Verilog 导出路径可能自然传播
Z，但排行榜使用的内部模拟器不是该路径，不能以 Verilog 行为替代游戏实测语义。

所以 Architecture Level Input 关闭产生的 Z 不会穿过普通 Splitter。若把一个 seed 位经多组
Splitter 接到多个 EARLY 网，稳态时这些输出仍会主动驱动，和已启用的 q Bit Switch 冲突。
这正是用户要求禁止的短路，不应生成候选或写入存档。

物理生成已在候选落盘前终止；没有启动游戏，没有写入正式存档，也没有留下可误装的
`circuit.data`。

### 放宽模型结果

当前游戏实测把原 `396` 方案计为 `delay=10` 是合理的。其最长控制路径为：

```text
ready Delay 4 + NOT 1 + OR 1 + XOR 2 + XOR 2 = 10
```

因此，原先只统计稳态 `q Delay + OR + 2 XOR = 9` 会漏掉 Architecture Level Input 的
控制到数据路径。

在不改变 `src/tc_save_lab/rng_encoded_asic.py` 中 `B/C/GATES/T` 的前提下，本轮曾建立
下列放宽的九延迟相位模型：

```text
EARLY(seed_i, q_j): seed 直入第一层 XOR；q 经 Bit Switch 后与 seed 三态汇合
LATE(seed_i, node): 仅当 node 在装载拍恒为 0 时，使用 seed OR node
```

Z3 找到的放宽模型证书为：

```text
31 EARLY * Bit Switch gate cost 2 = 62
16 LATE  * OR gate cost 1         = 16
相位总成本                         = 78

32 Delay Bit = 160
61 XOR        = 183
相位网络      =  78
ready + NOT   =   6
总门数        = 427
预测成绩      = 427 / 9 / 66
预测能量      = 253638
```

它只能给出代数层面的结论：

1. 若额外假定存在零门、零延迟且传播 Z 的隔离复制元件，gate cost `82` 和 `78` 都可满足。
2. 当前游戏的普通 Maker/Splitter 不具备该语义，所以这不能解释榜首 `431/9/66`，也不能
   宣称存在 `427/9/66` 候选。
3. 对 `phase cost <= 77` 的一次 180 秒检查为 `unknown(timeout)`；即使放宽模型中也没有
   最优性证明。

### 为什么路径不再是 10

早期配对的两条控制路径为：

```text
seed:   ready Delay 4 + NOT 1 + XOR 2 + XOR 2       = 9
steady: ready Delay 4 + Switch 1 + XOR 2 + XOR 2    = 9
```

后期 OR 只能放在第一层输出、第二层的直通输入或最终输出，并且其装载拍输入必须恒为零：

```text
seed control: ready Delay 4 + NOT 1 + OR 1 + <=1 XOR 2 <= 8
feedback:     q Delay 4 + XOR 2 + OR 1 + XOR 2          <= 9
```

因此没有任何 `OR + 两层 XOR` 路径。

### 已被推翻的零成本隔离前提

早期配对使用互斥三态驱动：tick 0 由 Architecture Level Input 驱动，之后由受 `ready`
控制的 Bit Switch 驱动。一个 seed 位或 q 位若参与多个不同配对，不能把这些网直接相连，
否则会把不同状态短接。

证书原先假定使用游戏中的 Maker/Splitter 进行电气隔离复制：

```text
U32 source -> 多组 Splitter32/Splitter8 -> 相互隔离的逐位输出
32 q bits  -> Maker8/Maker32 -> 多组 Splitter32/Splitter8 -> 隔离副本
```

虽然这些宽度适配元件计为零 gate、零逻辑 delay，但它们不会传播 Z，因而不能隔离三态
相位网。若禁止这一无效手段并要求所有早期配对形成 seed/q 二分图匹配，本模型在
`phase cost <= 150` 为 UNSAT。因此当前固定 DAG 的 EARLY 方案不是 `431` 的合理解释。

### 逻辑证书

求解器逐位建立以下约束：

- 第一层每个 XOR 输入可选零或一个 EARLY seed 位；
- EARLY 物理配对按 `(seed_i, q_j)` 去重，一个 Bit Switch 可扇出到相同配对的多个输入；
- LATE OR 仅能选择装载拍标签严格为零的 steady node；
- LATE OR 之后最多经过一个第二层 XOR；
- 32 个反馈节点的装载拍标签逐位等于 `T(seed)`；
- 稳态不改变原 61-XOR DAG，所以反馈/输出仍严格为 `B(q)` 与 `C(q)`。

JSON 中列出所有物理配对和逐消费端选择。纯 Python 核验会重建第一层标签、第二层反馈
标签、相位成本和四条最长路径，不依赖 Z3 模型对象。

### 后续方向

- 不再实现或部署该 `78` 成本拓扑。
- 若继续寻找 `delay=9`，必须使用真实传播 Z 的元件、避免 seed 复制，或完全改变
  `B/C/T` DAG 与相位编码。
- 任何新模型都应把每个元件的 `store_output` 高阻控制参数直接纳入约束，不能仅按
  gate/delay 成本推断三态语义。
