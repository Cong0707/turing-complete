# 汉诺塔

## 2026-08-01 / 拟定提交：研究：确定汉诺塔专用状态机下界

### 范围与证据

本关只研究面向 `2.1.281/v15` 的专用 ASIC/FSM。`examples/tower/level.json`
中的 `LEG` 只是损坏前存档留下的选中架构，不是功能基线、性能基线或可复用
依赖。本方案不使用 `LEG`、`OVERTURE`、`RV64` 或任何通用处理器。

决定性证据来自当前游戏文件：

- `campaign/tower/meta.txt`：测例盘数为 3、4、5；输入依次为 `N-1`、`source`、
  `destination`、`spare`；合法输出为 `0`、`1`、`2`、`5`。
- `campaign/tower/test.si:2-31`：`source` 和不同的 `destination` 在三根柱之间取值，
  `height = 3 + random(3)`。
- `campaign/tower/test.si:108-169`：`0/1/2` 只改变磁铁位置，`5` 只切换
  吸起/放下；放到小盘上立即失败。
- `campaign/tower/test.si:206-256`：输入读取顺序是固定的；所有存在的盘片
  进入 `destination` 后立即胜利，因此电路不需要在最后一步后自行停机。
- `examples/leaderboard-current.json`：当前公开能耗榜首为
  `125 gate / 7 delay / 125 cycles = 109375 energy`。单关页按能耗排名，
  这个点不能证明全球完整 Pareto 前沿。

### 周期下界

5 个盘片的最少合法搬运数是：

```text
2^5 - 1 = 31
```

每次搬运必须依次完成：

```text
移到源柱 -> 5 吸起 -> 移到目标柱 -> 5 放下
```

四个命令不能合并：移动命令不会切换磁铁，`5` 也不会移动磁铁。在最短
汉诺塔序列中，前一次的目标柱不会是后一次的源柱，所以相邻搬运之间
也无法省掉“移到源柱”。因此 5 盘语义下界是：

```text
31 moves * 4 output events = 124 useful output events
```

当只使用一路顺序 Level Input 时，第一个输入是 `N-1`，第二个输入才是
`source`。为覆盖随机的三种源柱，第一个有效移动命令最早只能与第二个输入
同周期产生。目标时序是：

```text
cycle 0: 读 N-1
cycle 1: 读 source      + 输出首次 FROM
cycle 2: 读 destination + 输出首次 LIFT (5)
cycle 3: 读 spare       + 输出首次 TO
cycle 4:                    输出首次 DROP (5)
...
cycle 124:                  输出第 31 次 DROP (5)
```

这正好对应公开榜首的 `125 cycles`，说明输入采集和首次搬运可以重叠，
而不应先用 4 个纯初始化周期再开始工作。

`124` 是已证明的有效输出事件下界；`125` 是当前单路顺序输入方案的周期
目标且已被榜首实现。在没有实测“多个 Level Input 是否能在同一模拟周期可靠地
消耗多个输入”之前，不把 `125` 声称为无条件的全局周期下界。

### 非递归搬运核

令 `N` 为盘数，`m` 为从 1 开始的搬运编号，令：

```text
q = ctz(m) & 1
virtual_from = (m + 2 - q) mod 3
virtual_to   = (m + 1 + q) mod 3
```

虚拟柱到实际柱的映射为：

```text
N 为奇数: [source, spare, destination]
N 为偶数: [source, destination, spare]
```

这一恒等式直接生成唯一的最短搬运序列，不需要栈、RAM、指令译码、
通用 ALU 或程序 ROM。对本关的 `m <= 31` 也不需要完整 CTZ，只需要其奇偶性。
如果 5 位计数状态保存 `k = m - 1`，则在 `0 <= k <= 30` 上：

```text
q = k0 & (~k1 | (k2 & ~k3))
```

该式只是一个小布尔网络，不应实例化通用前导零计数器。

### 现代 v15 拓扑

优先实现两个 Pareto 方向，两者都应展平到现代 `foundry/codex` 元件且不引用
任何旧架构元件。

#### 低门数：7 位动作计数器

使用单个 7 位动作计数器 `c`：

```text
phase = c[1:0]
k     = c[6:2]
m     = k + 1

phase 0: FROM
phase 1: 5
phase 2: TO
phase 3: 5
```

这个编码自然把 31 次搬运和每次 4 个动作合成一个状态。对 3/4 盘无需
终止比较器：测试器在第 7/15 次放下后已经返回 `win`。

`m mod 3` 可以从 `k+1` 组合计算，但延迟可能较高。低门数版应将
`q`、`mod 3` 和三路柱选择交给真值表精确综合，而不拼接完整算术元件。

#### 低延迟：冗余一热状态

在 5 位搬运计数状态之外，保存一个随每次 `DROP` 旋转的三状态一热
`m mod 3` 环。它用 3 个状态位换取零深度的模 3 解码。阶段也可使用 4 状态
一热环，或直接使用动作计数器的低两位。两种必须用 v15 实际计分比较，
不预设一热必然更好。

延迟优化要点：

- 采集输入时就按 `N` 奇偶性将 `destination/spare` 存成虚拟柱 1/2，
  不在每个输出周期重复做奇偶置换。
- 柱号只需低 2 位；存储 `source`、归一化柱 1、归一化柱 2 共 6 位。
- `phase 1/3` 的常数 `5` 应绕过搬运核，不经过柱选择网络。
- 三路柱选择适合用一热使能和共享总线，避免串联两层通用 MUX。
- 可在前一次 `DROP` 前将下一次 `FROM/TO` 锁存，但实际延迟计分也会
  看锁存输入路径；该重定时必须实测，不能只看输出端口。
- 首次 `FROM/LIFT/TO` 必须与第 2/3/4 个输入采集重叠，否则周期会退化到
  128 或更高。

#### ROM 只作对照组

31 项 `FROM/TO` 表或 124 项动作表能够实现本关，但它丢失了序列的
`ctz parity + mod 3` 极小结构。除非 v15 实测证明小 ROM 的计分成本异常低，
否则 ROM 只用于功能对照，不作榜单主候选。

### 榜首成本边界

当前榜首：

```text
125 * 7 * 125 = 109375
```

保持 `125 cycles` 时，严格打破榜首的整数边界是：

| delay | 最大 gate |
| ---: | ---: |
| 5 | 174 |
| 6 | 145 |
| 7 | 124 |
| 8 | 109 |

因此将延迟从 7 降到 6 可允许最多增加 20 个门，是值得单独搜索的方向。
反之，把周期从 125 降到未证实的 124，在 `delay = 7` 时只容许
`gate <= 126`；较多的并行输入元件很可能抵消这不到 1% 的周期收益。

### 离线验证规范

本关的随机输入实际只有 18 种语义组合：

```text
N in {3, 4, 5}
(source, destination) in 3 * 2 ordered distinct peg pairs
spare = 3 - source - destination
```

候选不应只重放 64 个随机测例，而应在 Python 中穷举全部 18 种组合，
逐命令复制 `test.si` 的磁铁和盘片状态转移。每个组合必须断言：

- 所有输出均在 `{0, 1, 2, 5}` 中；
- 吸起的永远是当前柱上最小的盘片；
- 从不将大盘放到小盘上；
- 第 7/15/31 次放下后所有存在的盘片均在 `destination`；
- 有效输出数分别为 `28/60/124`；
- 搬运序列与独立的递归参考实现完全一致，而不是只验证最终柱状态。

状态电路还需要额外跟踪逐周期信号：输入索引、动作计数器、模 3 状态、
`q`、归一化柱、输出值和输出使能。组合真值表模拟器不足以验证这个关卡，
需要按时钟沿执行的轨迹模拟。

最后的 v15 候选还必须通过：格式解码、唯一 `permanent_id`、无旧架构依赖、
`foundry/codex` 递归成本统计和人工游戏验收。本次未启动游戏，未写入正式存档，
也未把研究数值声称为已验证成绩。

## 2026-08-01 / 拟定提交：实现：加入汉诺塔单 I/O 协议穷举验证

### 本次实现

新增 `src/tc_save_lab/tower_asic.py` 与 `tests/test_tower_asic.py`。它们不是
“看最终柱位置”的简化脚本，而是按当前 `campaign/tower/test.si` 的真实状态机
重放：磁铁位置、吸起盘片、空吸、放置到小盘上的失败条件，以及每一个输出后的
胜利检查。

验证器穷举以下全部 18 个语义组合：

```text
highest_disk in {2, 3, 4}
source, destination in {0, 1, 2}, source != destination
spare = 3 - source - destination
```

每组都把无递归公式生成的动作与独立递归参考逐项比较，并断言：

- 3/4/5 盘分别得到 7/15/31 次搬运；
- 输出事件数分别为 28/60/124；
- 周期数分别为 29/61/125；
- 所有命令严格属于 `0/1/2/5`；
- 每次吸起的都是当前柱顶，永不空吸，永不大盘压小盘；
- 胜利只在最后一次 `DROP` 回调后发生，所有实际盘片都在目标柱。

125 周期轨迹固定使用一个输入流和一个输出流：第 0 周期读取 `N-1`，第 1
周期读取 `source` 并输出第一次 `FROM`，第 2 周期读取 `destination` 并输出
`LIFT`，第 3 周期读取 `spare` 并输出第一次 `TO`，随后连续输出直到第 124
周期的最后一次 `DROP`。没有假定多个 I/O 元件的执行顺序。

### 真实精灵几何审计

为避免再次产生“导线穿过元件或元件引脚”的存档，模块包含不依赖第三方包的
PNG RGBA 解码器。它读取当前游戏安装目录的
`asset/component_sprites/*.png`，校验 PNG CRC、解压和反滤波后按 20 像素网格
提取真实 alpha 占位。

审计规则是：导线可以彼此交叉；但是只要导线经过任一元件的非透明 alpha 单元，
就失败。当前 I/O 圆形精灵把逻辑端口绘制在不透明图形内部，因此已知端点引脚
可以沿“从元件中心向外、直到 live alpha 结束”的唯一逃逸通道离开精灵；这条
通道按真实 alpha 网格计算，不能被中途穿过的导线或非端点引脚借用。元件 alpha
重叠和未映射元件类型同样失败。测试还故意构造一条穿过 `AND` 元件体的导线，
确保审计器不会退化为普通矩形或只检查端点。

### v15 范围与阻塞条件

新增的 `build_tower_io_protocol_probe()` 是一个明确标记为**不可部署**的四元件
v15 连通性/编码/精灵审计探针。它有且只有一个 `kind=62` 和一个 `kind=70`，但
不会写入 `examples/tower/candidate/circuit.data`，也不会进入正式存档。

尚未生成完整电路的原因是刻意保守，而非把未证实的元件当作事实：当前项目没有
经实测固定的 `Counter`、`CTZ`、`Inc` 引脚和时钟语义。下一步必须用已审核的
位门、Delay、Byte splitter/maker、Word adder 展开状态网络，并同时通过本事件
模型、v15 round-trip、连通性和上述 alpha 审计，才允许产生可安装候选。期间不
启动游戏、不写存档、不宣称排行榜成绩。
