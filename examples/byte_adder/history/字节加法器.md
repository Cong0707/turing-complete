# 字节加法器

## 2026-08-01 / 候选构建

### 思路

当前版本的原生 U8 加法器同时提供 `carry_in`、8 位和输出与 `carry_out`，可以直接
覆盖旧的八级全加器链。候选保留关卡的三个输入和两个输出，只替换可编辑区域。

### 修改点

- 在 `(0, 0)` 放置一个 `com_add`（kind `30`，U8）。
- 分别接入 Carry in、A、B，并从原生元件输出接到 Output、Carry out。
- 所有线路只在端点触及元件引脚；导线之间的交叉不作为连接点。

### 离线验证

- 穷举 `A(256) * B(256) * Carry in(2) = 131072` 组输入。
- 每组均比较低 8 位和与第 9 位进位。
- v15 编解码往返、引脚连通性、组件实体碰撞和引脚穿越审计均通过。

候选成绩头为 `103 gate / 5 delay / 515 energy`，仍待游戏内实际验收。

## 2026-08-04 / 提交：五延迟负相低位与尾部严格边界

### 七门 `S1/S2` 前端

快速负相前缀现在有一份真实普通门结构：

```text
v  = NOR(Q1, P2)
a  = AND(P2, nC3)
w  = NAND(nC1, P1)
x  = AND(v, w)
u  = OR(nC1, P1)
S1 = NAND(w, u)
S2 = OR(a, x)
```

七个节点全部按 `1 gate / 1 delay` 计费；没有把 XOR 当成一门，也没有使用 RAM 或原生
`com_add`。完整 bit0→A/V12→`nC3`→`S1/S2` 重放通过全部 `131072` 行：

```text
S0/S1/S2 arrival = [4,4,5]
mismatch          = 0
BUS conflict      = 0
final Z           = 0
```

由此得到严格的完整 D5 账本：

```text
fixed low outputs and paid high state = 73
S3..S7/C8 joint residual target       = 29
complete target                       = 102/5/510
```

### 新的限定下界

- 固定 fast-negative paid-source 接口下，`S5/S6<=7/D6` 的 30 种 ordinary/Switch/XOR
  成本分解全部严格 `UNSAT`；这不排除跨 `S3..S6/C5/C7` 的联合重写。
- 慢 C7 paid-source `S7/C8` 联合尾部的 exact-cost-11 方程恰有 16 种合法 kind 分解；
  13 种由完整 CNF、余下 3 种由互斥完备的 `slot0-kind` 分片全部严格 `UNSAT`。因此，
  在当前真实三态、BUS conflict、physical-net partition、deadline=6、dead-component
  精确模型内，tail11 已全局封闭；这不是全局字节加法器下界，也不自动推出所有
  `cost <= 11` 均 `UNSAT`。
- 单独 `S4@D5` 的总成本 `<=8` 全部 `UNSAT`，首次 SAT 是 `9 gate` 且使用两只 Switch，
  证明高位 29 门必须跨输出共享，不能逐位独立拼装。
