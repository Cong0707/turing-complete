# 除法器

## 2026-08-01 / 提交：实现原生字节除法候选

### 运行时证据

- 当前安装版 `Turing Complete.exe` 的序列化枚举确认 `com_div` 为 `kind=32`；`kind=107` 是已删除的占位元件，不能用于候选。
- 可执行文件内嵌的 Verilog 是 `TC_Div (in0, in1, out)`，核心语句为 `assign out = in0 / in1;`。它只有商输出，不是旧引脚库曾假设的商、余数双输出块。
- 当前 RV64 v15 存档中的一个 U64 `kind=32` 实例提供了独立端点证据：旋转为零时 `in0=(-1,-1)`、`in1=(-1,+1)`、`out=(+2,0)`。
- `campaign/byte_divide/meta.txt` 明确规定除数为零时结果应为零；`test.si` 使用与字节取模相同的 65536 tick 仿射发生器，实际覆盖 32768 个不同输入对。

### 候选结构

使用原关卡的两个 U8 输入、一个 U8 输出和一个当前原生 `com_div`。三条线分别连接 A、B、Result；版图将除法器放在 `(0,-8)`，线路在其左右留出开放通道。

### 指标

- 门数：`370`
- 延迟：`32`
- 能耗：`11840`
- 元件：`4`
- 导线：`3`

这一点与 2026-08-01 采集的公开榜单前沿 `370 / 32 / 11840` 对齐。它是原生元件基线，不宣称超过榜首。

### 离线验证

- 对全部 `65536` 个 U8 `(A, B)` 组合验证无符号整除，含 256 个除零输入。
- 逐 tick 重放关卡脚本的 `65536` 次输入。
- v15 编码往返无损，候选生成确定性稳定。
- 端点网络无未连接引脚、多驱动、无驱动、位宽不匹配或组合环。
- 读取当前 `com_div.png` 和关卡 I/O 精灵的 alpha 网格；无元件重叠、导线穿元件、导线穿非端点引脚。

### 部署边界

候选只写入 `examples/byte_divide/candidate`，未加入自动直写名单，也未修改正式存档。游戏仍需人工加载、跑完关卡测试并提交榜单后，才能将它从“研究候选”提升为“游戏内确认”。
