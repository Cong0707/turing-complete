# 代码破解器

## 2026-08-01 / 提交：修复反馈顺序并落成专用 ASIC

### 方向

本关虽然位于顶层 `architecture` 区域，但关卡契约只要求根据一位“上次输出过高”
反馈继续输出一个字节。最短路线是专用状态机，不是修复或优化通用处理器。

`OVERTURE`、`LEG`、`RV64`、ISA、RAM 和程序 ROM 均不参与本候选。旧架构只作为
历史存档保留，不能作为当前版本的功能或性能基线。

### 旧实现为何失败

最初尝试使用下面的移位寄存器：

```text
state_next = (state >> 1) | ((not over) << 7)
```

它会反转反馈出现的先后顺序。第一层看似正确，但进入右侧子树后立即偏离区间中点：

```text
当前区间：[64, 126]
当前输出：63
反馈 over=0
正确下一输出：95
旧实现输出：159
```

更深处会复现原始失败：当区间即将收敛到 `[252, 252]` 时，旧状态会错误变成
`126`。测试保留 `63 + over=0 -> 95` 和 `253 + over=1 -> 252` 两个回归断言，并
穷举完整反馈树，避免再次出现“前几层正确”的假阳性。

### 正确状态编码

每个可达的非终止状态都是：

```text
已经选择的决策前缀 + 一个 0 分隔位 + 低位连续的 1
```

令 `delimiter` 为最低零位，则正确递推为：

```text
delimiter      = (state + 1) AND (NOT state)
clear_previous = delimiter >> 1
next           = (state XOR clear_previous) OR (delimiter AND (NOT over))
```

初值仍为 `0b01111111 = 127`。该编码直接产生当前闭区间的向下取整中点：

```text
127
63 / 191
31 / 95 / 159 / 223
...
```

### 现代 v15 候选

`.research/binary-search-next.v` 保存可读逻辑，
`.research/binary-search-next-area.v` 保存 Yosys/ABC 的面积映射结果。生成器将后者的
37 门网络逐门写成当前基础元件：

- 12 个 AND；
- 10 个 NAND；
- 14 个 OR；
- 1 个 NOT；
- 8 个单比特 Delay Line 保存状态；
- 1 个 Maker8 汇总输出；
- 当前版 architecture 输入、输出及使能常量。

8 个 Delay Line 的初值从低位到高位是 `1,1,1,1,1,1,1,0`。候选不含自定义元件，
依赖列表为空。

### 离线验证与指标边界

测试逐分支复制当前 `test.si` 的闭区间更新。运行时脚本不是预先固定一个秘密值，
而是每轮从 `[min, max - 1]` 采样，再按当前输出选择左右子区间；当前输出本身会被
排除。因此 256 次测试是随机重复次数，可达终点实际为 128 个（`0..252` 的偶数
加 `255`），而不是 256 个固定密码。离线验证确认：

- 128 个可达终值各出现一次，所有随机分支都能收敛；
- 每个非终止状态都等于当前区间中点；
- 每个终止状态都等于唯一剩余值；
- 周期只可能为 8 或 9，最坏为 9；
- 37 门综合网络既匹配每个可达状态转移，也通过全部 512 个 `(state, over)` 向量；
- v15 编解码往返完全一致；
- 所有引脚均连接，无多驱动、位宽冲突、组合环或未知元件；
- 完全独立于旧架构和通用处理器。

当前候选的离线成本声明为：

```text
77 gate / 8 delay / 9 cycles / 5544 energy
```

其中 77 门由 37 个组合门加 8 个、每个成本为 5 的 Delay Line 得到；8 delay 是
映射网络最长输出路径。公开榜首 `92 / 6 / 9 / 4968` 仅作为下一轮优化目标，不能
写成当前候选的实测成绩。本次没有启动游戏，也没有写入正式存档，运行时计分仍待
后续人工验收。
