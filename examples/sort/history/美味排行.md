# 美味排行

## 2026-08-01 / 提交：研究：确定三十二周期流式排序ASIC

### 关卡实证

最新版 `campaign/sort/test.si` 明确规定：每次测试生成 16 个 `0..255` 的随机整数，电路先
调用输入端 16 次，再将结果从小到大提交到输出端。测试总数为 64。

当前公开榜首为 `1654/11/32/582208`。其中 32 个周期正好等于 16 次读取加 16 次输出，已经
达到串行接口的周期下界。因此本关不应继续优化通用处理器，目标应是固定功能的流式排序
ASIC，并首先保持 32 周期。

### 电路结构

使用 16 个字节寄存器组成降序链。初始值全部为 `0`。每个装载周期把输入值作为 `carry`，
从第 0 级向第 15 级传播：

```text
if register[i] < carry:
    register[i], carry = carry, register[i]
```

一级硬件只需要一个无符号比较器、一个选择器和一个带条件写入的字节寄存器。比较成立时，
较大值写入本级，较小值继续向右传播；比较不成立时，本级保持，输入值继续传播。16 个输入
结束后，寄存器从左到右保持降序，链尾是当前最小值。

输出阶段连续注入哨兵 `255`。每个周期都会把当前最小值从链尾挤出，同时用 `255` 填补左侧
空位，因此连续 16 个链尾值正好是升序结果。严格小于比较可以正确保留重复值；输入中的
`0` 由初始零槽位表示，输入中的 `255` 也不会与冲刷哨兵发生计数丢失。

### 形式化不变量

- 每个周期结束后，寄存器链始终单调不增。
- 寄存器链与链尾输出的多重集，等于周期前寄存器与 `carry` 的多重集。
- 装载 16 次后，寄存器多重集等于 16 个输入的多重集。
- 第 `k` 次冲刷输出原输入中的第 `k` 小元素。
- 固定执行 16 次装载和 16 次冲刷，总周期数为 32。

### 公开旧电路证据

CC0 仓库 `zoickx/turing-complete` 的旧 v6 `ASIC/SORT` 不能直接复用到当前 v15，但其结构可作
交叉验证：顶层包含 16 个寄存器自定义元件、15 个无符号字节比较器、16 个字节选择器和一个
计数器，正是上述流式插入链。旧文件声明 `1460/394`，不能当作当前版本成绩或成本基线。

### 本次产物

`examples/sort/asic_model.py` 实现了与电路逐周期一致的行为模型。测试覆盖随机排列、重复值、
全零、全 `255`、完整字节边界以及输入范围校验。下一步是在现代 v15 布局器具备时，将一级
比较交换单元和 16 级寄存器链降低为 `foundry/codex` 元件，并以榜首 `1654/11/32` 为首个
实测上界。
